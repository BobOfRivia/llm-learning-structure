# 9.1 MoE 基础与路由（Top-K / Expert Choice / Hash / Sinkhorn）

[← 返回框架](../../README.md) · [📎 materials.md → §9.1](../../materials.md)

---

## 〇、本节回答什么

> **MoE（Mixture of Experts）**：FFN 这一侧的稀疏化。每个 token 只**激活一小部分**专家网络，但总参数量可以扩到 trillion 级。
>
> 核心问题 = "**谁去激活谁？**" → **路由（router / gating）** 是 MoE 的灵魂。

本节先建立 MoE 的基本图景，再展开主流路由策略：Top-K（GShard/Switch/Mixtral/DeepSeek）vs Expert Choice（Google）vs Hash / Sinkhorn。

---

## 一、MoE 是什么、为什么

### 1.1 直觉

dense FFN：每个 token 都过同一个大 FFN（每层 ~8×d² 参数）。
MoE FFN：每个 token 只过 **K 个**（如 2 个）小 FFN，但**池子里有 N 个**（如 64、256 个）。

```
dense:        token → [一个 big FFN] → out
MoE (top-2):  token → router → 选 2/N 个 expert FFN → 加权和 → out
                       (每 token 只算 K/N 的 FFN 计算量)
```

→ **参数量** = N × FFN（巨大）
→ **每 token 算量** ≈ K × FFN（远小于 dense）

效果：**用 N 倍参数容量 + K 倍算量** 换取质量。

### 1.2 经验放大率

经验法则（Switch Transformer 论文）：

> 同 FLOPs 的 MoE 模型，质量 ≈ **3-7×** 参数量的 dense 模型。

→ 一个 671B 总参 / 37B 激活的 DeepSeek-V3 ≈ ~120-250B dense 模型的质量。

### 1.3 关键发展史

| 年份 | 工作 | 核心贡献 |
|------|------|---------|
| 1991 | Jacobs et al. | "Adaptive Mixture of Local Experts"（原始 MoE 概念） |
| 2017 | Shazeer et al. — Outrageously Large NN | top-K gating + noise，第一次在 LSTM 上做大规模 MoE |
| 2020 | GShard (Google) | sharding + top-2 + aux loss 标准化 |
| 2021 | Switch Transformer | top-1 极简路由，scale 到 1.6T |
| 2022 | GLaM, ST-MoE | top-2 + z-loss，质量逼近 dense |
| 2022 | Expert Choice (Zhou et al.) | 翻转路由：expert 选 token |
| 2023 | Mixtral 8x7B | 第一个高质量开源 MoE |
| 2024 | DeepSeek-MoE / V2 / V3 | 细粒度 + 共享专家 + **aux-loss-free** |
| 2024-25 | Llama-4, Qwen3-MoE, Kimi K2 | MoE 成大模型默认 |

→ MoE 从"边缘实验" 变成 **2024 之后大模型的事实标配**。

## 二、路由的两大流派

```
┌────────────────────────────────────────────────────────┐
│                                                        │
│   Token-Choice：每个 token 选 K 个 expert              │
│       └─ Top-K（最主流） / Hash / Sinkhorn              │
│                                                        │
│   Expert-Choice：每个 expert 选 K 个 token             │
│       └─ 天然负载均衡，但 streaming 推理难落地         │
│                                                        │
└────────────────────────────────────────────────────────┘
```

两者的根本差异：**主动权在 token 还是在 expert**。

## 三、Top-K Routing（绝对主流）

### 3.1 数学

输入 token 表示 $x \in \mathbb{R}^d$，N 个 expert，门控权重 $W_g \in \mathbb{R}^{d \times N}$：

$$g = \text{softmax}(W_g \cdot x) \in \mathbb{R}^N$$
$$\text{indices} = \text{TopK}(g, K)$$
$$y = \sum_{i \in \text{TopK}} \frac{g_i}{\sum_{j \in \text{TopK}} g_j} \cdot E_i(x)$$

其中 $E_i$ 是第 $i$ 个 expert（一个独立 FFN）。

```
                     ┌─→ Expert 1 ─┐
token x ─→ Router ───┼─→ Expert 2 ─┼─→ weighted sum ─→ y
                     │   Expert 3   │
                     │     ...      │
                     └─→ Expert N ─┘
              (只激活 top-K，其他 expert 不算)
```

### 3.2 K 怎么选

| K | 代表模型 | 备注 |
|---|---------|------|
| 1 (top-1) | Switch Transformer | 极简 + 极便宜，但质量略弱 |
| 2 (top-2) | GShard, Mixtral, GLaM | 经典 trade-off |
| 6-8 | DeepSeek-MoE (256 专家选 8) | 细粒度，见 §9.3 |
| 8+ | Llama-4 (128 选 8) | 高路由分辨率 |

**为什么 top-2 > top-1**：
- top-1 时一个 expert 决定一切 → router 噪声直接放大
- top-2 给了 "main + backup" → 训练更稳

**为什么不用 top-N（dense）**：
- top-N = dense MoE，失去稀疏性
- 算力增长 ∝ K，浪费

### 3.3 Switch Transformer：top-1 + 极简

[Fedus et al. 2021 — Switch Transformer](https://arxiv.org/abs/2101.03961)：

```python
gates = softmax(router(x))      # [B, T, N]
idx = argmax(gates, dim=-1)     # [B, T]  ← 选一个 expert
y = E[idx](x) * gates[idx]
```

收益：
- 通信开销最低（only 1 expert per token）
- 实现简单
- 在同算力下 scale 7× 参数

代价：
- 路由错就完全错（无 backup）
- 需要更强的 aux loss / capacity buffer

### 3.4 Top-2 + Noise（GShard 风格）

[Lepikhin et al. 2020 — GShard](https://arxiv.org/abs/2006.16668)：

加 Gaussian noise 到 logits，作训练时的 exploration：

$$\text{logits} = W_g x + \epsilon, \quad \epsilon \sim \mathcal{N}(0, 1/N^2)$$

→ 防止 router 早期 collapse 到少数 expert。

### 3.5 Top-K 的痛点：**负载不均**

routing 是离散决策 → 训练早期 router 倾向"投到几个特定 expert"，出现：

```
Expert 1: 80% token   ← 训练充分，但单卡爆显存
Expert 2: 15% token
...
Expert N: 0.1% token  ← 几乎不更新（dead expert）
```

→ 必须加 **load balance** 机制（见 §9.2）。

## 四、Expert Choice — 翻转视角

[Zhou et al. 2022 — Expert Choice Routing](https://arxiv.org/abs/2202.09368)（Google）。

### 4.1 思路

不让 token 选 expert，反过来让 **expert 选 token**：

```
传统 Token-Choice:
  for each token:
     pick top-K experts                    ← token 主动

Expert-Choice:
  for each expert:
     pick top-C tokens (按 affinity score) ← expert 主动
     (C = capacity = T·K/N)
```

### 4.2 优点

- **天然负载均衡**：每个 expert 强制处理固定数量 C 个 token，永远不 starve
- **不需要 aux loss**（容量是硬约束）
- token 可被 0 个、1 个、或多个 expert 选中 → 学到的 routing 更灵活

### 4.3 缺点（为什么没成为主流）

- **推理时 streaming 很难**：expert-choice 需要看到一个 batch 内所有 token 才能选 top-C；而 LLM 推理 decode 阶段一次只来一个 token
- **causal masking 复杂**：训练时未来 token 不能影响过去（autoregressive 约束）
- → 适合 **encoder / vision / batch inference**，不适合 **decoder LM**

### 4.4 工业现状

- Google 早期 PaLM 系列实验过
- 当前 decoder-only LLM 几乎都用 Token-Choice
- Expert Choice 在 ViT-MoE、encoder retrieval 中仍活跃

## 五、其他路由变体（不深入）

### 5.1 Hash Routing

[Roller et al. 2021 — Hash Layers](https://arxiv.org/abs/2106.04426)：

直接用 token id / hash 函数决定 expert，**不学 router**。

- 优点：零参数路由、负载完全均衡
- 缺点：失去"内容相关 routing"，质量低于学习 router
- 用作 baseline，不上 production

### 5.2 Sinkhorn / Balanced OT Routing

[Clark et al. 2022 — Sinkhorn routing](https://arxiv.org/abs/2202.01169)：

把 token-expert 分配看作 **最优传输** 问题，用 Sinkhorn 迭代解出均衡分配。

- 优点：训练时严格均衡
- 缺点：每 forward 都做几轮迭代，开销大
- 现实使用少

### 5.3 Soft MoE / Soft Routing

[Puigcerver et al. 2023 — Soft MoE](https://arxiv.org/abs/2308.00951)：

不做 top-K 硬选择，每个 expert 输入是所有 token 的**加权和**：

```
slot_i = Σ_t w_{t,i} · x_t        ← expert i 的输入是全 batch 加权
output_i = E_i(slot_i)
```

- 优点：可微、训练稳
- 缺点：每 expert 都要算（不再是稀疏） → 计算 ≈ dense
- 在 ViT 上有效，LLM 上没普及

### 5.4 BASE Layer

[Lewis et al. 2021 — BASE Layers](https://arxiv.org/abs/2103.16716)：

每个 token 强制只去 1 个 expert，用 linear assignment（匈牙利算法）求最优匹配。

- 思想接近 Expert Choice 的离线版
- 训练 + 推理对齐难

## 六、Router 本身的设计细节

### 6.1 Router 是个独立小网络

通常就是一个 **线性层 + softmax**：

```python
class Router(nn.Module):
    def __init__(self, d_model, n_experts):
        self.w = nn.Linear(d_model, n_experts, bias=False)

    def forward(self, x):              # x: [B, T, d]
        logits = self.w(x)             # [B, T, N]
        # 加 noise / aux loss / z-loss …
        gates = topk_softmax(logits, K)
        return gates
```

参数量：$d \times N$ — 相比 expert 几乎可忽略。

### 6.2 Router 初始化

[ST-MoE](https://arxiv.org/abs/2202.08906) 推荐 truncated normal $\sigma = 0.01$ —— 让初始 logits 接近均匀（避免训练初期某 expert 暴涨）。

### 6.3 Router 精度

router 数值敏感：很多 paper 报告**用 FP32 算 router**（其他用 BF16）。
- DeepSeek-V3 / Mixtral 都明确 router 用 FP32

### 6.4 Router z-loss

[ST-MoE](https://arxiv.org/abs/2202.08906) 引入：

$$L_z = \frac{1}{B} \sum_i \left( \log \sum_j e^{x_{ij}} \right)^2$$

→ 防止 router logits 数值爆炸（softmax 进入饱和区）。
→ 现在是 MoE 训练**标配**之一（见 §9.2）。

## 七、关键问答

**Q1**：为什么不直接用 dense FFN 加大参数？
- dense：参数 ↑ K 倍 → 计算 ↑ K 倍
- MoE：参数 ↑ K 倍 → 计算 ↑ ~1 倍
- 在 inference cost 是瓶颈的场景（大部分 LLM 部署），MoE 是"参数白嫖"

**Q2**：Top-1 和 Top-2 怎么选？
- 同算力下 Top-2 质量略优（多一个 backup expert）
- Top-1 通信成本最低（仅一次 send）
- Switch 路线（top-1）：极致 scale
- GShard/Mixtral/DeepSeek（top-2 或 top-K）：质量优先
- 大多数 production 用 top-2 起步

**Q3**：Expert Choice 既然好，为啥不用？
- Decoder LM 在 decode 阶段一次只来一个 token，"expert 选 top-C token" 没法 streaming 运行
- Token-Choice 天然 autoregressive 友好
- Encoder / Vision / 批量场景仍是 Expert Choice 的舞台

**Q4**：DeepSeek-V3 256 专家选 8 比 Mixtral 8 选 2 强在哪？
- 细粒度专家（小 + 多）→ 路由分辨率高 → 单 token 能选到更精确的专家组合
- 详见 §9.3

**Q5**：MoE 一定比 dense 强吗？
- 同**激活参数**下：MoE > dense（容量大）
- 同**总参数**下：dense > MoE（每 token 用到全部）
- 同**算力**下：要看任务，retrieval / 知识密集型 MoE 占优；reasoning 上略复杂
- 详见 §9.5

**Q6**：MoE 必须做负载均衡吗？
- 必须。否则 dead expert + capacity 爆显存
- 详见 §9.2

**Q7**：每一层都做 MoE 吗？
- 通常只在 FFN 层做 MoE，attention 仍 dense
- 部分 layer 做 MoE，部分做 dense（"MoE 间隔"）— Mixtral 是每层都 MoE；某些模型隔层做
- Attention 也做 MoE 的方案有，但少（如 MoA）

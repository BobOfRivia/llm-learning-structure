# 9.1 MoE 基础与路由（Top-K / Expert Choice / Hash / Sinkhorn）

[← 返回框架](../../README.md) · [📎 materials.md → §9.1](../../materials.md)

## 〇、本节回答什么

> **MoE（Mixture of Experts）**：FFN 这一侧的稀疏化。每个 token 只**激活一小部分**专家网络，但总参数量可以扩到 trillion 级。
>
> 核心问题 = "**谁去激活谁？**" → **路由（router / gating）** 是 MoE 的灵魂。

本节自下而上建立 MoE 的完整数学图景，回答四个层层递进的问题：

1. **数学起点**：sparse MoE 是怎么从 dense FFN "推" 出来的？为什么这样改 FLOPs 而不改总参数？
2. **梯度问题**：top-K 是离散选择，按理说不可微——MoE 训练为什么能跑？反传通路长什么样？
3. **路由设计**：四个代表实现（Switch / GShard / Mixtral / DeepSeek-V3）的公式差别在哪里？sigmoid 评分 vs softmax 评分、归一化做不做、bias 加在哪里——这些"小细节"决定了能不能 scale 到 671B。
4. **其他流派**：Expert-Choice / Hash / Sinkhorn / Soft MoE 各自为什么没成主流？

---

## 一、从 dense FFN 到 sparse MoE 的数学等价

### 1.1 dense FFN 的标准形式

Transformer block 里的 FFN（也叫 MLP）：

$$\text{FFN}(x) = W_{\text{down}} \cdot \sigma(W_{\text{up}} \cdot x), \quad x \in \mathbb{R}^d$$

- $W_{\text{up}} \in \mathbb{R}^{d_{\text{ff}} \times d}$，$W_{\text{down}} \in \mathbb{R}^{d \times d_{\text{ff}}}$
- 常用 $d_{\text{ff}} = 4d$（Llama 用 $\tfrac{8}{3} d$ + SwiGLU 门控），下面用 $d_{\text{ff}} = 4d$ 算账
- 参数量：$P_{\text{FFN}} = 2 d \cdot d_{\text{ff}} = 8 d^2$
- 单 token FLOPs：$F_{\text{FFN}} \approx 2 \cdot P_{\text{FFN}} = 16 d^2$（前向；反向 ≈ 2 倍）

**关键观察**：dense FFN 里**每个 token 都用同一套权重**，但 token 的"内容"差异巨大（中文 vs 代码、问句 vs 陈述、专业术语 vs 日常）。这意味着 $W_{\text{up}}, W_{\text{down}}$ 同时在"学所有 token 的所有模式"，参数效率受限。

### 1.2 直接放大 dense 的代价

如果想提升质量，最直接的办法是把 $d_{\text{ff}}$ 放大 N 倍：

$$P_{\text{FFN}}' = 8 d \cdot (N \cdot d_{\text{ff}}) = N \cdot P_{\text{FFN}}, \quad F_{\text{FFN}}' = N \cdot F_{\text{FFN}}$$

**参数和算力同步线性涨**——这就是 dense scaling 的本质代价。Chinchilla 法则告诉我们：给定 FLOPs 预算 $C$，最优 dense 规模约为 $N_{\text{opt}} \propto C^{0.5}$。

### 1.3 MoE 的 "解耦" 思路

> **核心动机**：把"参数容量"和"单 token 计算量"解耦——让参数能涨 N 倍，但单 token 算力只涨 K 倍（$K \ll N$）。

做法：

$$\text{MoE-FFN}(x) = \sum_{i=1}^{N} g_i(x) \cdot E_i(x)$$

- $E_i$ 是第 $i$ 个 "专家"（一个独立的 FFN，结构和 dense FFN 一致）
- $g_i(x) \in \mathbb{R}$ 是 **gate value**（路由权重），由 router 算出
- 关键约束：$g_i(x)$ 在大多数 $i$ 上**等于 0**——只有少数（K 个）非零

```
对一个 token x：
  router(x) → [g_1, g_2, ..., g_N]   ← 大部分是 0
                 ↓
  output = Σ g_i · E_i(x)   ← 只算 g_i ≠ 0 的 E_i
```

**FLOPs / 参数账**：

| 量 | dense | MoE | 比例 |
|---|---|---|---|
| 总参数（FFN） | $8d^2$ | $N \cdot 8d^2$ | $\times N$ |
| 单 token FLOPs（FFN） | $16d^2$ | $K \cdot 16d^2$ | $\times K$ |
| 参数/算力 比 | 1 | $N/K$ | $\times N/K$ |

→ MoE 让 **"参数预算"** 和 **"算力预算"** 沿不同斜率增长。这就是为什么大家说 MoE 是"参数白嫖"。

### 1.4 "sparsity" 的几个等价度量

讨论 MoE 时经常出现的几个比例，要明确：

| 度量 | 公式 | DSv3 数值 | 含义 |
|---|---|---|---|
| **激活率**（Activation Ratio） | $K/N$ | 8/256 = 3.1% | 每 token 激活几分之几的 expert |
| **激活参数 / 总参数** | $P_{\text{active}}/P_{\text{total}}$ | 37B / 671B = 5.5% | 实际参与计算的参数比例 |
| **稀疏度**（Sparsity） | $1 - K/N$ | 96.9% | 多少参数对单 token 是"零计算" |
| **Granularity** $G$ | $d_{\text{ff}}^{\text{dense}} / d_{\text{ff}}^{\text{expert}}$ | ≈8-16 | 单 expert 比 dense FFN 小多少倍（§9.3） |

注意"激活率"和"激活参数比"不完全相等，因为：

- 总参数里还有 attention / embedding 等 dense 部分
- 共享专家（§9.3）每 token 都过，提升激活参数比
- DSv3 的 37B 激活参数 = 1 shared expert + 8 routed experts + MLA + embedding

### 1.5 经验放大率与 Scaling Law 起点

> **Switch Transformer 经验法则**：同 FLOPs 的 MoE 模型，质量 ≈ **3-7×** 参数量的 dense 模型。

这条只是经验，背后有更精确的 scaling law（细节在 §9.5）：

- **[Clark et al. 2022 — Unified Scaling Laws for Routed LM](https://arxiv.org/abs/2202.01169)**：MoE 的 loss 同时受总参数 $N$ 和激活参数 $N_a$ 影响，可写成 $L(N, N_a, D)$
- **[Krajewski et al. 2024 — Fine-grained MoE Scaling Laws](https://arxiv.org/abs/2402.07871)**：再加一维 granularity $G$，得到 $L(N, N_a, D, G)$，并发现 $G \to \infty$（极细粒度）时 loss 继续下降但有 collapse 风险

→ 一个 671B 总 / 37B 激活的 DeepSeek-V3 ≈ ~120-250B dense 模型的质量。这个倍率不是凭空，是 scaling law 拟合出来的。

### 1.6 关键发展史

| 年份 | 工作 | 核心贡献 |
|------|------|---------|
| 1991 | Jacobs et al. | "Adaptive Mixture of Local Experts"（原始 MoE 概念，soft mixture） |
| 2014 | Eigen et al. | 第一次提 "深度+稀疏 MoE" 思路 |
| 2017 | Shazeer et al. — Outrageously Large NN | **Top-K gating + noise**，在 LSTM 上做 100B+ 稀疏 MoE |
| 2020 | GShard (Google) | sharding + top-2 + aux loss 标准化（首个大规模 Transformer MoE） |
| 2021 | Switch Transformer | top-1 极简路由，scale 到 1.6T |
| 2022 | GLaM, ST-MoE | top-2 + z-loss，质量逼近 dense |
| 2022 | Expert Choice (Zhou et al.) | 翻转路由：expert 选 token |
| 2023 | Mixtral 8x7B | 第一个高质量开源 MoE，激活 13B |
| 2024-01 | DeepSeek-MoE | **细粒度 + 共享专家** |
| 2024-12 | DeepSeek-V3 | **Aux-loss-free + grouped TopK + node-limited routing** |
| 2024-25 | Llama-4, Qwen3-MoE, Kimi K2 | MoE 成大模型默认 |

→ MoE 从"边缘实验" 变成 **2024 之后大模型的事实标配**。重要节点：2020（GShard 工程化）、2022（ST-MoE 稳定性）、2024-01（DeepSeek-MoE 细粒度）、2024-12（DeepSeek-V3 无 aux loss）。

## 二、路由的根本难题：离散选择如何反传梯度

这是 MoE 训练里最容易被跳过、但又最容易让人困惑的一点。

### 2.1 问题陈述

Top-K 路由是这样写的：

$$\text{selected} = \text{argTopK}(s_1, s_2, \dots, s_N), \quad y = \sum_{i \in \text{selected}} w_i \cdot E_i(x)$$

**argTopK 是不可微的**——它返回的是离散下标集合，对输入的微小扰动可能让 selected 突变。如果按传统 backprop，梯度无法穿过 argTopK 流回 router。

那 MoE 怎么能训练？

### 2.2 解法：用 "weight × expert output" 让梯度走 weight 通路

主流 MoE 用的不是真正的"argTopK 反传"，而是一个**等价改写**——把前向过程拆成**两条并行通路**，在 output 处汇合：

> **图中的 $x$ 是什么？** —— 是当前 Transformer block 里**前面 attention 子层的输出**（pre-LN 结构下是 `LN(attn_out + residual)`）。MoE 替换的是原本 dense FFN 的位置，输入输出形状与 dense FFN 完全一致 —— 对外（attention、残差、下一层）来说 MoE 是"透明替换"，从外面看不出它内部是稀疏的。

```
                  ┌─→ E_1(x) = y_1 ┐
                  │                │     右通路：expert 输出
  x ──┬──────────→├─→ E_2(x) = y_2 ┤    （可微，∂y_i/∂E_i 正常反传）
      │           │     ...        │
      │           └─→ E_N(x) = y_N ┘
      │                            │
      │                            │
      └─→ router(x) = [s_1,..,s_N] │     左通路：gate 分数
                  │                │    （可微）
                  ▼                │
            TopK → mask ∈ {0,1}^N  │     ← stop-gradient（离散，不反传）
                  │                │
                  ▼                │
            w_i = normalize(       │     左通路最终输出：weight
                    s_i · mask_i)  │
                  │                │
                  └───────┬────────┘
                          ▼
              output = Σ_i mask_i · w_i · y_i
                            ↑          ↑
                            │          └─ y_i 是 expert 输出
                            └─ w_i 是 router 给的权重（梯度沿此回流到 W_g）
```

**逐步解读这张图：**

| 步骤 | 公式 | 是否可微 | 说明 |
|---|---|---|---|
| ① expert 输出 | $y_i = E_i(x)$ | ✅ | 每个 expert 是普通 FFN，对 x 算输出 |
| ② router 打分 | $s_i = \text{score}(W_g x)$ | ✅ | softmax 或 sigmoid，连续 |
| ③ TopK 造 mask | $\text{mask}_i = \mathbb{1}[i \in \text{TopK}(s)]$ | ❌ | 离散 0/1，**反传时当常数** |
| ④ 算权重 | $w_i = \dfrac{s_i \cdot \text{mask}_i}{\sum_j s_j \cdot \text{mask}_j}$ | ✅ | 注意 $w_i$ 含 $s_i$（连续），mask 只是"清零" |
| ⑤ 汇合 | $\text{output} = \sum_i \text{mask}_i \cdot w_i \cdot y_i$ | ✅ | 加权和 |

合在一起的最终公式：

$$y = \sum_{i=1}^{N} \text{mask}_i \cdot w_i \cdot E_i(x)$$

> **⚠️ "图上画了 N 条线，实际只算 K 条"**
>
> 上图为了说明梯度通路，把 N 个 expert 都画了出来。但工程实现里 **mask_i = 0 的 expert 根本不会被调用** —— $E_i(x)$ 不算、$y_i$ 不存在。否则 MoE 就没有省 FLOPs 的意义了。
>
> 等价的"稀疏前向"伪代码：
> ```python
> idx, w = router(x)              # idx: [K], w: [K]
> y = sum(w[k] * experts[idx[k]](x) for k in range(K))
> ```

**关键洞察 —— 梯度为什么能流回 router**：mask 本身离散不可微，但它被**乘到** $w_i$ 上，而 $w_i$ 含有连续的 $s_i$。所以梯度可以**绕开 mask、沿着 $w_i \to s_i \to W_g$ 这条连续通路**回到 router。mask 的"不可微性"被隐藏在 stop-gradient 里——它只在前向决定"哪些 expert 算"，反向上当常数处理。

换句话说：**离散的是"选谁"，连续的是"以多大权重选"。MoE 训练靠后者把梯度送回 router**。

#### 2.2.1 澄清：只有"一个 router、一个 mask"，但用在两处

容易误读的点：公式里 $\text{mask}$ 同时出现在 $w_i$ 和 output 中，看起来像是"两个 mask 分别选 router 和 expert"。实际上：

> **router 是一个线性层 $W_g \in \mathbb{R}^{d \times N}$，一次性输出 N 个分数 $[s_1, \dots, s_N]$。** 不是"N 个 router 各打一分"，而是"一个 router 打 N 个分"。在这 N 个分数上做一次 TopK，得到一个 mask，这个 mask 在两个地方被复用：

```
router(x) → [s_1, s_2, ..., s_N]
                    │
                    ▼
            TopK → mask ∈ {0,1}^N   ← 同一个 mask
                    │
            ┌───────┴────────┐
            ▼                ▼
     用在 w_i 里        用在 output 里
   （挑哪些 s_i      （挑哪些 E_i(x)
    进归一化分母）      真的被计算）
```

| mask 出现位置 | 数学作用 | 工程作用 |
|---|---|---|
| $w_i = \dfrac{s_i \cdot \text{mask}_i}{\sum_j s_j \cdot \text{mask}_j}$ | 把未选中的 $s_i$ 清零，让归一化只在 K 个上分蛋糕 | — |
| $\text{output} = \sum_i \text{mask}_i \cdot w_i \cdot y_i$ | **数学上冗余**（因为 $w_i$ 已含 mask，未选中已是 0） | **跳过未选中的 $E_i(x)$ 计算**，省 N-K 个 expert 的 FLOPs |

注意 output 里那个 mask 在严格数学上是冗余的：

$$\text{mask}_i \cdot w_i = \text{mask}_i \cdot \frac{s_i \cdot \text{mask}_i}{\sum_j \cdots} = \frac{s_i \cdot \text{mask}_i^2}{\sum_j \cdots} = w_i \quad (\text{因为 } \text{mask}_i^2 = \text{mask}_i)$$

写出来主要是**表达稀疏激活语义**：告诉读者/编译器"未选中的 expert 不要算"。如果把它去掉、写成 $\sum_i w_i \cdot E_i(x)$，公式从数学上一样对，但读起来像"N 个 expert 全算了一遍再乘 0"——丢失了 MoE 的核心信息。

**一句话总结**：一个 router 出 N 个分 → 一次 TopK 出一个 mask → 这个 mask 在 $w_i$ 里管"归一化分母只算 K 项"，在 output 里管"只调用 K 个 expert"。两处用的是**同一个 mask、指向同一组 K 个 expert**。

### 2.3 反传通路图解

```
Loss
 │
 ├──→ ∂L/∂y                            (来自下游)
 │
 ├──→ ∂L/∂E_i(x) = mask_i · w_i · ∂L/∂y       (反传到被选中的 expert)
 │     │
 │     └─→ 只有 mask_i = 1 的 expert 收到梯度 ✅
 │
 ├──→ ∂L/∂w_i = mask_i · E_i(x) · ∂L/∂y        (反传到 gate weight)
 │     │
 │     └─→ 同样只有被选中的 expert 的权重收到梯度
 │
 └──→ ∂L/∂W_g (router 参数)
       通过 w_i = softmax_or_sigmoid(s_i) → s_i = W_g · x → W_g
       但只有 mask_i = 1 的 s_i 项有非零梯度（其他 w_i 是 0）
```

**这导致两个隐患**：

1. **未被选中的 expert 永远不更新**：如果某 expert 在前几千 step 一直没被选中，它的参数永远是初始化值——"**dead expert**"（§9.2 要解决的核心问题）。
2. **router 只学被选中 expert 的方向**：router 收到的梯度信号是"被选中的 expert 输出有多匹配 loss"，但**没收到"未被选中的 expert 会更好吗？"的反馈**。这是路由的探索-利用困境。

### 2.4 早期的辅助手段：noise / Gumbel

为缓解探索不足，[Shazeer 2017](https://arxiv.org/abs/1701.06538) 加 Gaussian noise：

$$s_i' = s_i + \mathcal{N}(0, \sigma^2), \quad \text{TopK on } s_i'$$

噪声让 router 有概率"试一下"不熟悉的 expert，给它一次更新机会。GShard 用 $\sigma = 1/N^2$，**这个具体值**的来历：

- $s_i$ 的典型尺度 ≈ $O(1)$（softmax 前 logits）
- 想让"翻转 top-K 排名"的概率 ≈ $1/N$（每 N 次 forward 翻一次）
- 在 $N$ 个 logits 里翻转排名需要噪声差异 ≈ 第二名和第 K 名的间距 ≈ $O(1/N)$
- → 噪声方差 ≈ $(1/N)^2$，即 $\sigma \approx 1/N^2$

也有用 Gumbel-Softmax / Straight-Through Estimator 的，但工业 MoE 几乎都用 weight 通路 + noise（或更现代的 aux-loss-free bias，§9.2）。

## 三、路由的两大流派：Token-Choice vs Expert-Choice

```
┌────────────────────────────────────────────────────────┐
│                                                        │
│   Token-Choice：每个 token 选 K 个 expert              │
│       └─ Top-K（最主流） / Hash / Sinkhorn              │
│                                                        │
│   Expert-Choice：每个 expert 选 C 个 token             │
│       └─ 天然负载均衡，但 streaming 推理难落地         │
│                                                        │
└────────────────────────────────────────────────────────┘
```

| 维度 | Token-Choice | Expert-Choice |
|---|---|---|
| 决策权 | token 主动 | expert 主动 |
| 输入约束 | 看单 token | 看整 batch |
| 负载均衡 | 软约束（需 aux loss） | 硬约束（容量 = 固定值） |
| 推理 streaming | ✅ 友好（单 token 可立即路由） | ❌ 不友好（需要看到 batch 才选） |
| autoregressive 兼容 | ✅ 天然 | ❌ 需特殊处理 |
| 主战场 | Decoder LLM | Vision / Encoder / 批量推理 |

→ 现代 decoder-only LLM 几乎都用 Token-Choice，原因在第六节细讲。

## 四、Top-K Routing 的设计空间

Top-K 是 token-choice 的具体实现，但"top-K"三个字下面藏着**至少 4 个相互正交的设计选项**：

```
Top-K 设计空间：
  ┌─ score 函数：softmax 还是 sigmoid？        (§4.1)
  ├─ weight 归一化：top-K 后再归一化吗？        (§4.2)
  ├─ K 怎么选：1 / 2 / 多？                    (§4.3)
  └─ bias / noise：怎么影响 TopK 选择？        (§4.4)
```

不同模型在这 4 个选项上做了不同组合——这才是 Switch / GShard / Mixtral / DSv3 真正的差异。

### 4.1 Score 函数：Softmax vs Sigmoid

> **⚠️ 先澄清："score 函数" 不等于 "激活函数"**
>
> 公式 $s_i = \text{score}(W_g x)$ 里的 score 看起来像 FFN 里的 SwiGLU/GELU，但**角色完全不同**：
>
> | 维度 | FFN 里的激活函数（ReLU/GELU/SwiGLU） | Router 里的 score 函数（softmax/sigmoid） |
> |---|---|---|
> | 目的 | **加非线性**，提升表达力 | **给每个 expert 打可比较的分数**（用于排序 + 加权） |
> | 形状 | 逐元素（pointwise） | 整向量耦合（softmax）或逐元素（sigmoid） |
> | 候选集 | 几乎所有非线性都行 | **只能是 softmax 或 sigmoid**（要有可解释的强度 + 可归一化） |
> | 换一个的代价 | 性能微调 | **改变 routing 语义** —— 决定 expert 之间是"竞争"还是"独立" |
>
> 比如把 router 后面换成 ReLU 技术上能跑，但 ReLU 输出 $[0, \infty)$ 没有概率含义、没有边界——TopK 后归一化的尺度会乱、bias 调整失效。所以 router 的"score 函数"必须满足"**输出有可解释的强度 + 可归一化**"，这是比"加非线性"更严的要求。
>
> → 文档里用 `score(·)` 而不是 `activation(·)`，正是为了**强调它的角色是"打分"**，不是"加非线性"。下面比较的就是这两种打分语义。

**经典做法（Switch / GShard / Mixtral）**：softmax

$$s_i = \frac{\exp(W_g^{(i)} \cdot x)}{\sum_{j=1}^{N} \exp(W_g^{(j)} \cdot x)}, \quad \sum_i s_i = 1$$

含义：把 N 个 expert 当作**互斥分类**——所有 expert 在竞争同一个 "1.0" 的概率质量。

**DeepSeek-V3 做法**：sigmoid

$$s_i = \sigma(W_g^{(i)} \cdot x) = \frac{1}{1 + \exp(-W_g^{(i)} \cdot x)}, \quad s_i \in [0, 1] \text{ 独立}$$

含义：每个 expert 独立给出 "这个 token 适合我吗" 的概率，**不竞争**。

**为什么 DSv3 改 sigmoid？两个原因**：

1. **避免 softmax 的"零和博弈"问题**：
   - softmax 下，当 N=256 时，单个 expert 的 score 平均只有 $1/256 \approx 0.004$
   - top-8 后归一化 → weight 之和强制等于 1，但每个 weight 仍然是 8 个之间"分蛋糕"
   - 当 N 大时，单 expert score 的"绝对值"变得没意义，只剩排名信息
   - sigmoid 让每个 expert 的 score **保留绝对意义**（0.7 vs 0.3 反映强度差异，不是分蛋糕）

2. **配合 aux-loss-free 的 bias 调整**：
   - aux-loss-free（§9.2）通过给 score 加 bias $b_i$ 来调整选择
   - softmax 下加 bias 会扰乱归一化（指数函数对 bias 敏感）
   - sigmoid 下 bias 直接加到 logit 上，**只影响排名，不扰乱权重幅度**——更适合做硬调整

**实测**：DSv3 论文 ablation 显示，固定其他条件，sigmoid 路由比 softmax 在 256 expert 下 PPL 降 ~1-2%。

### 4.2 Weight 归一化：归不归一？

选完 top-K expert 后，怎么把它们的 score 转成 weight？两类做法：

**A. 归一化**（Mixtral / DSv3）：

$$w_i = \frac{s_i \cdot \text{mask}_i}{\sum_{j \in \text{TopK}} s_j}, \quad \sum_i w_i = 1$$

意义：top-K 输出是一个**凸组合**——是 K 个 expert 输出的加权平均。

**B. 不归一化**（部分早期 MoE / GShard 风格）：

$$w_i = s_i \cdot \text{mask}_i$$

意义：top-K 输出可以放大或缩小，是 "K 个加权和"，不约束 = 1。

**为什么归一化是主流**：

- 不归一化时，路由权重之和会随 token 变化（有些 token 加起来 0.9，有些 0.3）→ 进入下游的 activation 尺度不稳定 → 训练时容易跑飞
- 归一化让 MoE 层的输出方差与 dense FFN 一致 → 与 LayerNorm / 残差连接的尺度匹配更好

**反例**：sigmoid 路由下，是否归一化要看是当**专家加和**还是**概率混合**：

- DSv3：sigmoid score → top-K mask → 归一化（仍然是凸组合）
- 一些 multi-head MoE 变体：sigmoid + 不归一化（直接加和），但需要特殊的输出缩放

### 4.3 K 怎么选

| K | 代表 | 单 token FLOPs | 质量 | 通信开销 |
|---|---|---|---|---|
| 1 | Switch / Llama-4 | 最低 | 弱（无 backup） | 最低 |
| 2 | GShard / Mixtral / DBRX | 1.5× | 经典平衡点 | 中 |
| 6-8 | DeepSeek-MoE 系列 / Qwen3-MoE | 4-8× | 高（细粒度） | 高 |

**为什么 top-2 > top-1**（数学直觉）：

- top-1 时，router 一旦选错，token 完全靠错误的 expert 处理，error 全额传到下游
- top-2 时，主 expert + backup expert 加权——即使 router 略有偏，第二个 expert 提供"残差信号"，让训练更稳
- 但 top-2 通信量 = 2× top-1，Switch 论文论证：用 top-1 + 充分的 capacity buffer 也能学好

**为什么 top-N（全选）= dense MoE**：

- 当 K = N，所有 expert 都参与，没有稀疏性 → FLOPs 退化到 dense × N
- 这种 "soft MoE" 在 ViT 上有效，但在 LLM 上完全无意义（除非每个 expert 极小）

**DeepSeek-V3 选 top-8 / 256 的逻辑**：

- 细粒度 expert（§9.3）每个只有 ~$d_{\text{ff}}/8$ 的 hidden dim
- 单 token 算力 = 8 × (单 expert FLOPs) = 8 × (dense FFN FLOPs) / 8 = 1× dense FFN
- 即"激活计算量"与 dense 相当，但**组合数** $\binom{256}{8} \approx 4 \times 10^{14}$ 给出极高的路由分辨率

### 4.4 Bias / Noise 怎么影响 TopK

| 方案 | 加在哪 | 谁来调 | 目的 |
|---|---|---|---|
| GShard noise | softmax 前 logits | 随机采样（训练） | 探索 |
| Switch jitter | softmax 前 logits | 随机扰动（训练） | 防 collapse |
| DSv3 bias $b_i$ | TopK 排名前的 logits | **规则**更新（不学） | 负载均衡 |
| 学习 bias | softmax 前 logits | 梯度更新 | 与 W_g 等价（无新意） |

**DSv3 bias 的特殊之处**：

- bias **只用于 TopK 选择**（决定哪 K 个 expert 被激活）
- 但**不用于权重计算**（weight 仍由原始 $s_i$ 归一化得出）
- 这样的设计让 bias 能"硬性调整"负载分布，但**不污染**前向 forward 输出
- 详细机制见 §9.2 第四节

## 五、四种代表实现的完整对照

下面给出 Switch / GShard / Mixtral / DSv3 的完整 router 公式，便于查阅。

### 5.1 Switch Transformer（top-1，极简）

[Fedus et al. 2021 — Switch Transformer](https://arxiv.org/abs/2101.03961)：

$$s_i = \text{softmax}(W_g x)_i$$
$$i^* = \arg\max_i s_i$$
$$y = s_{i^*} \cdot E_{i^*}(x)$$

特征：
- 单 expert，权重 = router score（**不归一化**，因为 top-1 唯一）
- 训练用 jitter noise + aux loss
- 推理用 capacity factor = 1.5 + token drop

### 5.2 GShard / GLaM（top-2，加 noise）

[Lepikhin et al. 2020 — GShard](https://arxiv.org/abs/2006.16668)：

$$s_i = \text{softmax}(W_g x + \mathcal{N}(0, 1/N^2))_i \quad \text{(训练时加 noise)}$$
$$\{i_1, i_2\} = \text{TopK}(s, K=2)$$
$$w_j = \frac{s_{i_j}}{s_{i_1} + s_{i_2}}, \quad j \in \{1, 2\}$$
$$y = w_1 \cdot E_{i_1}(x) + w_2 \cdot E_{i_2}(x)$$

特征：
- top-2 + softmax + 归一化
- 训练 noise，推理不加
- aux loss（§9.2）

### 5.3 Mixtral 8x7B（top-2，无 noise）

[Mistral AI 2024 — Mixtral](https://arxiv.org/abs/2401.04088)：

$$s_i = \text{softmax}(W_g x)_i \quad \text{(无 noise)}$$
$$\{i_1, i_2\} = \text{TopK}(s, K=2)$$
$$w_j = \text{softmax}_{\{i_1, i_2\}}(W_g x)_j \quad \text{(在选中的 2 个上重新 softmax)}$$
$$y = w_1 \cdot E_{i_1}(x) + w_2 \cdot E_{i_2}(x)$$

特征：
- 没有训练 noise（Mixtral 实测：噪声没带来收益）
- **二次 softmax**：先全 8 个 softmax 选 top-2，再在选中的 2 个上 softmax 算权重（数学上等价于 §5.2 的归一化，但实现上是 softmax）
- 用 aux loss + load balance loss

### 5.4 DeepSeek-V3（sigmoid + grouped TopK + bias）

[DeepSeek-V3 (2024-12)](https://arxiv.org/abs/2412.19437) §2.1.1：

**Step 1 — Sigmoid scoring**：

$$s_i = \sigma(W_g^{(i)} x), \quad i = 1, \dots, N_r \quad (N_r = 256 \text{ routed experts})$$

**Step 2 — 加 bias，分组 TopK**（细节关键，下一节展开）：

$$\tilde{s}_i = s_i + b_i \quad \text{(bias 只用于排名，不入权重)}$$

把 $N_r = 256$ 个 expert 分成 $g = 8$ 组，每组 32 个 expert。
- 在每组内取 top-2 $\tilde{s}$ 求和，得到该组的 "组得分"
- 选 top-4 个组（**node-limited routing**，对应 §9.4 工程意义）
- 在这 4 个被选中的组里做全局 top-K（K=8）

**Step 3 — 归一化权重**（用原始 $s_i$，不用 $\tilde{s}_i$）：

$$w_i = \frac{s_i}{\sum_{j \in \text{TopK}} s_j}, \quad i \in \text{TopK}$$

**Step 4 — 共享专家 + 加权和**：

$$y = E_{\text{shared}}(x) + \sum_{i \in \text{TopK}} w_i \cdot E_i(x)$$

特征：
- sigmoid 评分（独立而非竞争）
- bias **只影响选择**，**不进权重** ← 这是 aux-loss-free 的关键设计
- 分组 TopK 控制 All-to-All 通信扇出（详见 §9.4）
- 1 个共享专家（每 token 必过）+ top-8 routed

### 5.5 四种路由完整对照表

| 设计选项 | Switch | GShard | Mixtral | **DeepSeek-V3** |
|---|---|---|---|---|
| 总 expert 数 $N$ | 16-128 | 8-64 | 8 | **256 (+1 shared)** |
| top-K | 1 | 2 | 2 | **8** |
| score 函数 | softmax | softmax + noise | softmax | **sigmoid** |
| TopK 上的扰动 | jitter | Gaussian noise | 无 | **可调 bias $b_i$** |
| 权重归一化 | 不需要（K=1） | 归一化 | 二次 softmax | **归一化（用原 $s_i$）** |
| 负载均衡 | aux loss | aux loss | aux loss + LB loss | **aux-loss-free**（bias 自适应） |
| z-loss | 无 | 无 | 无 | ✅（数值稳定） |
| 分组 routing | 无 | 无 | 无 | ✅（**grouped TopK**） |
| shared expert | 无 | 无 | 无 | ✅（1 个） |
| capacity factor | 1.5 | 1.25 | 1.0（dropless） | 1.0（dropless） |
| router 精度 | BF16 | BF16 | BF16/FP32 | **FP32** |

→ 从 Switch 到 DSv3，路由从"3 行代码"演化到"包含 sigmoid + bias + group + shared 的复合系统"。这些 trick 不是装饰——是把 N 从 8 推到 256 的必需手段。

## 六、Expert Choice — 翻转视角

[Zhou et al. 2022 — Expert Choice Routing](https://arxiv.org/abs/2202.09368)（Google）。

### 6.1 公式

不让 token 选 expert，反过来让 **expert 选 token**：

对每个 expert $i$，定义 affinity score：

$$A_{i,t} = \text{softmax}_t(W_g^{(i)} x_t), \quad t = 1, \dots, T$$

每个 expert 选 affinity 最高的 $C$ 个 token：

$$T_i = \text{argTopC}_{t}(A_{i,t}), \quad C = \frac{T \cdot K}{N_e}$$

(其中 $K$ 是平均每 token 期望激活的 expert 数。)

每个 token 实际激活的 expert 数 = 它被多少个 expert 选中，**可能是 0、1、2、3、...** 个。

### 6.2 关键性质

- **天然负载均衡**：每个 expert 强制处理固定 $C$ 个 token，不可能 starve
- **不需要 aux loss**（容量是硬约束）
- **可能有 token 被 0 个 expert 选中**：这些 token 在该 MoE 层只走残差（信息流损失）

### 6.3 为什么没成为 Decoder LM 主流

```
训练时（teacher forcing）：所有 T 个 token 同时存在
                          → expert 可以看 batch 全貌选 top-C ✅

推理 decode 时：t 时刻只有第 t 个 token
                → expert 没法 "选 top-C"，因为只来了 1 个 token ❌
```

- Decoder 的 **自回归约束** 决定了推理时必须 "token 来一个处理一个"，不能 batch 内回头看
- Expert-choice 在 prefill 阶段（一次性处理整个 prompt）可行，但 decode 阶段失效
- → 适合 **encoder / vision / batch inference**，不适合 **decoder LM**

### 6.4 工业现状

- Google V-MoE / ViT-MoE：用 expert choice
- Decoder-only LLM（Mixtral / DSv3 / Llama-4）：全用 token-choice
- 学术上有 hybrid 方案（prefill 用 expert-choice，decode 用 token-choice），但工程复杂度大

## 七、其他路由变体（速览）

### 7.1 Hash Routing

[Roller et al. 2021 — Hash Layers](https://arxiv.org/abs/2106.04426)：

直接用 token id / hash 函数决定 expert：

$$i = \text{hash}(\text{token\_id}) \mod N$$

- 优点：零参数路由、负载完全均衡、无 router 训练问题
- 缺点：失去"内容相关 routing"——同一个 word 永远去同一个 expert，丢失上下文敏感性
- 用作 baseline，不上 production

### 7.2 Sinkhorn / 最优传输 Routing

[Clark et al. 2022 — Sinkhorn routing](https://arxiv.org/abs/2202.01169)：

把 token-expert 分配看作**最优传输**问题。给定 affinity matrix $A \in \mathbb{R}^{T \times N}$，求一个赋值矩阵 $P$ 满足：

- 行约束（每 token 总权重 = 1）：$\sum_i P_{ti} = 1$
- 列约束（每 expert 容量 = $T/N$）：$\sum_t P_{ti} = T/N$
- 最大化 $\sum_{t,i} P_{ti} \cdot A_{ti}$

用 Sinkhorn 迭代解（几轮 normalize 行和列）。

- 优点：训练时严格均衡
- 缺点：每 forward 都做几轮 Sinkhorn 迭代，开销大（~5-10× router cost）
- 现实使用少

### 7.3 Soft MoE / Soft Routing

[Puigcerver et al. 2023 — Soft MoE](https://arxiv.org/abs/2308.00951)：

不做 top-K 硬选择，每个 expert 的输入是所有 token 的**加权和**：

$$\text{slot}_i = \sum_{t=1}^{T} w_{t,i} \cdot x_t, \quad \text{output}_i = E_i(\text{slot}_i)$$

- 优点：完全可微，训练稳
- 缺点：每 expert 都要算 → 不再稀疏，计算 ≈ dense
- 在 ViT 上有效（视觉 token 数固定），LLM 上没普及（自回归）

### 7.4 BASE Layer

[Lewis et al. 2021 — BASE Layers](https://arxiv.org/abs/2103.16716)：

每 token 强制只去 1 个 expert，用 linear assignment（匈牙利算法）求最优匹配。

- 思想接近 Expert Choice 的离线版
- 训练 + 推理对齐难，工业少用

### 7.5 Multi-Head MoE（MH-MoE）

[Wu et al. 2024 — MH-MoE](https://arxiv.org/abs/2404.15045)：

把 token embedding 切成 $h$ 个 head，每个 head 独立路由到不同 expert，最后 concat。

- 优点：单 token 可激活更多"sub-expert"，分辨率高
- 缺点：实现复杂，工程未普及

## 八、Router 设计的微观细节

### 8.1 Router 是一个独立小线性层

```python
class Router(nn.Module):
    def __init__(self, d_model, n_experts, score_fn='softmax'):
        # DSv3 风格：bias=False，sigmoid 评分
        self.w = nn.Linear(d_model, n_experts, bias=False)
        self.score_fn = score_fn
        # aux-loss-free 用的 expert bias（不进梯度）
        self.register_buffer('b', torch.zeros(n_experts))

    def forward(self, x):              # x: [B, T, d]
        logits = self.w(x.to(torch.float32))   # FP32 router (DSv3)
        if self.score_fn == 'softmax':
            s = logits.softmax(-1)
        else:  # sigmoid
            s = logits.sigmoid()
        # TopK 用 s + b（DSv3）
        topk_idx = (s + self.b).topk(K, dim=-1).indices
        topk_score = s.gather(-1, topk_idx)
        weights = topk_score / topk_score.sum(-1, keepdim=True)
        return topk_idx, weights
```

参数量：$d \times N$。对 $d=7168, N=256$ 的 DSv3，router 参数 ≈ 1.8M，与 expert 参数（~1.6B per layer）相比可忽略。

### 8.2 Router 初始化

[ST-MoE](https://arxiv.org/abs/2202.08906) 推荐：truncated normal $\sigma = 0.01$。

**为什么不用 default Xavier**：

- $W_g \in \mathbb{R}^{d \times N}$，Xavier 给出 $\sigma \approx \sqrt{2/(d+N)} \approx 0.04$（对 d=4096）
- 这会让初始 logits 标准差 ≈ $\sqrt{d} \cdot 0.04 \cdot \|x\| \approx O(1)$
- → 早期 softmax 已经有明显分化，某 expert 被高频选中 → 自我强化 → collapse
- 用 $\sigma = 0.01$ 让初始 logits 接近 0，softmax 接近均匀分布，所有 expert 公平起步

### 8.3 Router 精度

router 数值敏感：很多论文报告**用 FP32 算 router**（其他用 BF16/FP8）。

- DeepSeek-V3 / Mixtral：router 明确 FP32
- 原因：softmax / sigmoid 在 BF16 下精度损失大，TopK 排名可能因数值误差翻转
- 代价小：router 计算量 = $d \times N$ 远小于 expert，FP32 不显著加成本

### 8.4 Router z-loss

[ST-MoE](https://arxiv.org/abs/2202.08906) 引入：

$$L_z = \frac{1}{B} \sum_b \left( \log \sum_j e^{x_{b,j}} \right)^2$$

防止 router logits 数值爆炸（softmax 进入饱和区，梯度消失）。

- 现在是 MoE 训练**标配**之一（DSv3 也用，即使去掉了 aux loss）
- 详见 §9.2 第三节

### 8.5 共享专家 vs Routed 专家

在 DSv3 / DeepSeek-MoE 里：

- 共享 expert：每 token **必过**，不经过 router
- Routed expert：每 token 经 router 选 K 个

数学上：

$$y = \underbrace{E_{\text{shared}}(x)}_{\text{每 token 必算}} + \underbrace{\sum_{i \in \text{TopK}} w_i \cdot E_i(x)}_{\text{稀疏激活}}$$

- 共享 expert 不需要 routing 决策 → 无负载均衡问题
- 共享 expert 承载"通用语言能力"，routed expert 专攻长尾（§9.3）

## 九、关键问答

**Q1**：为什么不直接用 dense FFN 加大参数？

- dense：参数 ↑ N 倍 → 计算 ↑ N 倍
- MoE：参数 ↑ N 倍 → 计算 ↑ ~K 倍（$K \ll N$）
- 在 inference cost 是瓶颈的场景（大部分 LLM 部署），MoE 的"参数容量"几乎是"免费的算力"
- 但显存不免费：所有 expert 都要驻留 GPU memory

**Q2**：Top-K 是离散的，MoE 为什么能训练？

- 数学上 argTopK 不可微，但 MoE 实际反传走的是 "weight × expert_output" 通路
- 梯度通过被选中 expert 的 weight 流回 router（detail 见 §2.2）
- 代价：未被选中的 expert 不更新 → dead expert 问题
- 早期靠 noise / aux loss 强行探索，DSv3 靠 bias 自适应解决

**Q3**：Top-1 和 Top-2 怎么选？

- 同算力下 Top-2 质量略优（多一个 backup expert，训练稳）
- Top-1 通信成本最低（一次 send），实现极简
- Switch 路线（top-1）：极致 scale
- GShard / Mixtral / DSv3（top-2 或更大）：质量优先
- 大多数 production 用 top-2 起步，DSv3 路线用 top-8 配合细粒度

**Q4**：DSv3 为什么用 sigmoid 不用 softmax？

- softmax 在 N=256 时单 expert 概率被压到 $1/N \approx 0.004$，只剩排名信号
- sigmoid 让每个 expert 有"独立绝对得分"——保留强度信息
- 配合 aux-loss-free 的 bias 调整，sigmoid 的 logit 加 bias 更线性

**Q5**：DSv3 的 grouped TopK 解决什么问题？

- 256 expert 分 8 组，对应 8 个 GPU 节点
- 限制 token "最多发到 4 个节点"（top-4 groups）→ All-to-All 通信扇出降一半
- 详见 §9.4 节点限制路由

**Q6**：Expert Choice 既然好，为啥不主流？

- Decoder LM decode 阶段一次只来一个 token，"expert 选 top-C token" 没法 streaming
- Token-Choice 天然 autoregressive 友好
- Encoder / Vision / 批量场景仍是 Expert Choice 的舞台

**Q7**：每一层都做 MoE 吗？

- 通常只在 FFN 层做 MoE，attention 仍 dense
- 部分模型隔层做 MoE（如 Llama-4 部分 layer dense 部分 MoE）——这样 KV cache 等仍稳定
- Attention 也做 MoE 的方案有（MoA），但很少用

**Q8**：MoE 一定比 dense 强吗？

- 同**激活参数**下：MoE > dense（总容量大）
- 同**总参数**下：dense > MoE（每 token 用到全部参数）
- 同**算力**下：要看任务，retrieval / 知识密集型 MoE 占优；reasoning 上略复杂
- 详见 §9.5

**Q9**：router 跑飞的常见现象有哪些？

- **Collapse**：1-2 个 expert 接走 50%+ 的 token，其他 dead → 监控 max/min token 比、expert 熵
- **Logits 爆炸**：router logits 标准差 > 10，softmax 进入饱和区 → 加 z-loss
- **训练后期偏移**：早期 balanced，后期某 expert 学得太"好"，router 越来越偏 → aux loss 持续生效或 bias 持续调整

**Q10**：为什么 router 用 FP32？

- TopK 排名对数值敏感，BF16/FP8 误差可能让两个相近 score 翻转
- router 计算量小，FP32 开销不显著
- DSv3 / Mixtral 都明确 FP32

   ├─→ §9.3 细粒度+共享专家 ─── 改 expert 结构提路由分辨率
   │                          ─── §5.4 的 shared expert 数学细节
   │
   ├─→ §9.4 EP / All-to-All ─── 工程：把 expert 分卡 + token 跨卡传输
   │                          ─── §5.4 的 grouped TopK 工程意义
   │
   └─→ §9.5 MoE vs Dense    ─── 整体选型 + scaling law

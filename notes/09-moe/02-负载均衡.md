# 9.2 负载均衡（Aux Loss / Router z-loss / Aux-Loss-Free）

[← 返回框架](../../README.md) · [📎 materials.md → §9.2](../../materials.md)

---

## 〇、本节回答什么

§9.1 末尾提到："Top-K 路由的天敌是 **负载不均**"。

> 训练早期 router 会偏，少数 expert 被高频选中，多数 expert "饿死" → **expert collapse**。
>
> 同时 expert 间负载不均 → 通信 / 显存 / 算力都被最热的 expert 卡住。

本节展开**三代负载均衡方法**：

```
第一代：Aux Loss（GShard 2020）         ── 加 loss 约束分布
第二代：Router z-loss（ST-MoE 2022）    ── 控制 logits 数值
第三代：Aux-Loss-Free（DeepSeek-V3 2024）── 用 bias 直接调，loss 干净
```

---

## 一、为什么会负载不均

### 1.1 自我强化循环

```
初始 router 略偏（W_g 初始化噪声）
   ↓
某些 expert 被选中略多
   ↓
被选中的 expert 学得快、表示更好
   ↓
router 看到这些 expert 输出更"有用"，更倾向选它们
   ↓
反馈循环 → 几个 expert 包揽 80% token，其他几乎不更新
```

### 1.2 工程后果

```
负载不均的工程伤害：
  ├─ Capacity overflow（热门 expert 装不下） → token 被 drop（见 §9.4）
  ├─ Dead expert（参数白存）                 → 浪费总参数预算
  ├─ All-to-All 通信不均衡                   → 单卡成瓶颈
  └─ 梯度更新不均                             → 训练越后差距越大
```

→ 必须主动干预。

## 二、第一代：Aux Loss（GShard / Switch）

[Lepikhin et al. 2020 — GShard](https://arxiv.org/abs/2006.16668)：在主 loss 上加一个 **辅助 loss** 来 penalize 不均衡。

### 2.1 公式

对一个 batch 内 $T$ 个 token、$N$ 个 expert：

- $f_i = \frac{1}{T} \sum_t \mathbb{1}[\text{token } t \text{ chose expert } i]$  ← 每 expert 处理的 token **比例**
- $P_i = \frac{1}{T} \sum_t g_i(x_t)$  ← 每 expert 的**路由概率均值**

$$L_{aux} = N \cdot \sum_{i=1}^{N} f_i \cdot P_i$$

- 当负载完全均衡时，$f_i = P_i = 1/N$，$L_{aux} = N \cdot N \cdot (1/N)^2 = 1$
- 任何偏离均衡 → $L_{aux} > 1$
- 与主 loss 相加：$L = L_{LM} + \alpha L_{aux}$，$\alpha$ 通常 $10^{-2}$

### 2.2 为什么是 $f_i \cdot P_i$ 而不是 $f_i^2$ 或 $P_i^2$

- $f_i$ 是 **离散**（top-K 决策），**不可微**
- $P_i$ 是 **连续** 路由概率（softmax 输出），可微
- 乘积形式：梯度通过 $P_i$ 流回 router；$f_i$ 起到"放大不均衡 expert 的权重"作用
- 这是 GShard 论文最 elegant 的 trick

### 2.3 实测有效但有副作用

- 能基本压住 dead expert
- **但 aux loss 本身会"扰动"主任务 loss**——尤其在收敛后期，aux loss 不再有用，反而拉低质量
- DeepSeek-V3 团队的痛点：α 调小则不均衡，调大则掉点

## 三、第二代：Router z-loss（ST-MoE）

[Zoph et al. 2022 — ST-MoE](https://arxiv.org/abs/2202.08906) 在 aux loss 之外又加了一个：

$$L_z = \frac{1}{B} \sum_{b=1}^{B} \left( \log \sum_{j=1}^{N} e^{x_{b,j}} \right)^2$$

其中 $x$ 是 router 的 raw logits。

### 3.1 解决什么问题

- router logits **数值会逐步漂大**（exp 之后某些超大）
- softmax 进入饱和区 → top-K 几乎是 argmax，梯度变小
- 数值上的 fp16 / bf16 还可能 NaN

z-loss 把 logits 拉回合理范围：

```
原本：x = [10, 8, -3, ...]       → softmax 极陡，没法学
+z-loss: x = [1.0, 0.8, -0.3, ...] → softmax 平滑
```

→ z-loss 是 **数值稳定性 loss**，不是直接的负载均衡 loss，但和 aux loss 配合让 MoE 训练更稳。

### 3.2 经验值

- $L = L_{LM} + \alpha L_{aux} + \beta L_z$
- $\alpha = 10^{-2}$, $\beta = 10^{-3}$
- ST-MoE / Mixtral / 早期 DeepSeek-MoE 都用

## 四、第三代：Aux-Loss-Free（DeepSeek-V3）

[DeepSeek-V3 (2024-12)](https://arxiv.org/abs/2412.19437) 创新最大的一处：**完全去掉 aux loss**，改用 **expert-wise bias 自适应调整**。

### 4.1 思路

> aux loss 干扰主 loss → 何不直接在 logits 上加 bias，绕过 loss 通道？

```
原始 router:          gates = softmax(W_g · x)
DeepSeek-V3 router:   gates = softmax(W_g · x + b)          ← b 是可调 bias
                        topK = argtopK(gates + b)            ← 仅用于 topK 选择
                        weights = softmax(gates)[topK]       ← 权重仍用原 gates
```

关键：**bias 只影响 top-K 选择**，**不影响**最终的 expert 权重 — 不污染主 forward。

### 4.2 自适应调整规则

bias **不通过梯度学**，而是按规则更新：

```
每个 step 结束后：
  for expert i in [0, N):
    if expert_i 的负载 > target:
       b_i ← b_i - γ              # 降低优先级
    else:
       b_i ← b_i + γ              # 提升优先级
```

其中 $\gamma$ 是固定步长（如 $10^{-3}$）。
→ "负载高 → bias 减小 → 下次 top-K 不易选中"。

### 4.3 收益

| 维度 | 传统 Aux Loss | Aux-Loss-Free |
|------|-------------|--------------|
| 主 loss 干扰 | 有（α 调难） | 无 |
| 负载均衡度 | 中等 | 更好（实测） |
| 实现复杂度 | 简单 | 略复杂（要维护 bias） |
| 兼容性 | 几乎所有 framework | 需 router 内部改 |

DeepSeek-V3 报告：去掉 aux loss 后，**质量更好 + 负载更均衡**。

### 4.4 仍保留的辅助手段

DeepSeek-V3 完全去掉 aux loss，但仍保留：
- **z-loss**：防数值爆炸
- **sequence-level aux loss**：对单 sequence 内做轻度均衡（避免某 seq 全去一个 expert，对推理 batching 有利）

## 五、Capacity / Token Dropping —— 兜底机制

aux loss / aux-loss-free 都是 **soft** 约束，仍可能短期偏。
工程上有 **hard** 约束 = capacity factor。

### 5.1 Capacity 公式

每个 expert 在一个 batch 内最多处理：
$$C = \text{capacity\_factor} \cdot \frac{T \cdot K}{N}$$

- $T$ = batch token 数，$K$ = top-K，$N$ = expert 数
- $\text{capacity\_factor}$ 通常 1.0 - 1.5

### 5.2 超过 capacity 怎么办

有几种处理：

1. **Token dropping**：超出的 token 跳过此 MoE 层（直接走 residual）
2. **Token shuffling**：把多余 token 转给次优 expert
3. **Expert padding**：在低负载 expert 上填 padding token（仅 expert-choice）

工业实操：训练时用 capacity_factor = 1.25 + token dropping；
推理时通常 capacity_factor 略大，少 drop。

### 5.3 Dropless MoE（MegaBlocks）

[MegaBlocks (Gale et al. 2023)](https://arxiv.org/abs/2211.15841) 提出：**完全不 drop**。
- 用 block-sparse matmul 处理变长 expert 输入
- 实测：消除 token drop 带来 ~5-10% 质量提升
- 工程开销：需要专门 kernel（block-sparse GEMM）

→ DeepSpeed-MoE、vLLM、SGLang 都已集成 MegaBlocks 风格 dropless。

详见 [§9.3 架构变体](./03-细粒度专家.md)。

## 六、负载均衡的全景图

```
                    ┌───────────────────────────────────┐
                    │   Loss-based（让梯度自己调 router）│
                    │   ─ aux loss (GShard)             │
                    │   ─ z-loss (ST-MoE)               │
                    └───────────────────────────────────┘
                                  │
                                  │
                    ┌───────────────────────────────────┐
                    │   Bias-based（DeepSeek-V3）        │
                    │   ─ 不污染主 loss                  │
                    │   ─ 直接调 top-K 选择              │
                    └───────────────────────────────────┘
                                  │
                                  │
                    ┌───────────────────────────────────┐
                    │   Hard constraint                  │
                    │   ─ capacity factor + drop         │
                    │   ─ dropless (MegaBlocks)          │
                    │   ─ expert-choice 天然均衡         │
                    └───────────────────────────────────┘
```

→ 三层叠用：bias / loss（soft）+ capacity（hard）+ kernel（dropless）。

## 七、关键问答

**Q1**：aux loss 为什么要 N · Σ f·P 这种形式？
- $f_i \cdot P_i$ 形式：$P$ 可微（梯度回 router），$f$ 提供"哪些 expert 负载偏高"信号
- 乘以 $N$：让 balanced 时 $L_{aux} = 1$，便于调系数

**Q2**：DeepSeek-V3 去掉 aux loss 后为什么质量更好？
- aux loss 是个"代理目标"（proxy）：它逼着均衡，但牺牲了 router 找到"内容最匹配 expert"的能力
- bias 调整不进 loss → 主 loss 纯净 → router 仍然学"哪个 expert 最适合"
- 均衡靠 bias 强制实现，质量靠 loss 纯净保留

**Q3**：z-loss 和 aux loss 关系？
- z-loss = 数值稳定性（防 logits 爆）
- aux loss = 负载均衡（防 expert collapse）
- 两者正交，可叠加
- DeepSeek-V3 保留 z-loss，但去掉 aux loss

**Q4**：capacity_factor 怎么选？
- 训练：1.25 - 1.5（留 buffer 防 drop）
- 推理：1.5 - 2.0（更保守）
- 太小：drop 太多伤质量
- 太大：浪费显存
- dropless 模型可以 = 1.0（不 drop）

**Q5**：负载不均会导致显存爆吗？
- 会。expert i 收到太多 token → 这块卡的激活显存爆
- 实操：要么 capacity 限死，要么 dropless + 动态 padding
- 在多机 EP 训练中尤其要看（见 §9.4）

**Q6**：训练时 aux loss 一定要从头开到尾吗？
- 早期 step 关键（防 collapse）
- 后期可以衰减或关闭（ST-MoE 实验过）
- DeepSeek-V3 用 bias 完全代替了这套折中

**Q7**：sequence-level aux loss 是什么？
- 不是 batch 内均衡，而是 **单 sequence 内**均衡
- 让一个 sequence 不要全部投到一个 expert
- 好处：推理时该 sequence 的 expert 调用更分散，便于 batch 调度

# 9.2 负载均衡（Aux Loss / Router z-loss / Aux-Loss-Free）

[← 返回框架](../../README.md) · [📎 materials.md → §9.2](../../materials.md)

---

## 〇、本节回答什么

§9.1 末尾提到："Top-K 路由的天敌是 **负载不均**"。

> 训练早期 router 会偏，少数 expert 被高频选中，多数 expert "饿死" → **expert collapse**。
>
> 同时 expert 间负载不均 → 通信 / 显存 / 算力都被最热的 expert 卡住。

本节回答四个递进问题：

1. **量化**：怎么定义"不均衡"？用什么指标看？训练时该 alert 在哪条线？
2. **第一代手段**：Aux Loss（GShard）—— 公式怎么写、梯度怎么走、为什么是 $f_i \cdot P_i$ 而不是 $f_i^2$？
3. **第二代手段**：Router z-loss（ST-MoE）—— 解决的是不同问题（数值稳定），但和 aux loss 是叠加关系
4. **第三代手段**：Aux-Loss-Free（DSv3）—— **完全去掉 aux loss**，改用 bias 自适应。详细规则、$\gamma$ 怎么选、与 sequence-level loss 怎么配

```
第一代：Aux Loss（GShard 2020）         ── 加 loss 约束分布（软）
第二代：Router z-loss（ST-MoE 2022）    ── 控制 logits 数值（防爆）
第三代：Aux-Loss-Free（DSv3 2024）      ── 用 bias 直接调，主 loss 干净（硬）
工程兜底：Capacity factor + Token drop  ── 硬上限
极端方案：Dropless MoE（MegaBlocks）    ── 完全不丢
```

## 一、负载不均的成因与量化

### 1.1 为什么会自我强化

```
初始 router 略偏（W_g 初始化噪声 ~0.01，但不为零）
   ↓
某些 expert 被选中略多（如 5% vs 期望 3.1%）
   ↓
被选中的 expert 收到更多梯度 → 学得快、表示更好
   ↓
router 看到这些 expert 输出更"匹配" → 给更高 score
   ↓
反馈循环 → 几个 expert 包揽 80% token，其他几乎不更新（dead）
```

数学上：router 参数 $W_g$ 的梯度只来自被选中 expert 的 weight 通路（§9.1 第二节）。如果 expert $i$ 从未被选中，**$W_g$ 的第 $i$ 列永远不会被更新**——即 $W_g^{(i)}$ 永远是初始化值，那一列对应的 score $s_i$ 永远偏低，永远不会被选中。这是个**单向陷阱**。

### 1.2 三种量化指标

要监控负载均衡，需要在每个 batch 里观察 expert 的 token 分布。设 $f_i$ 是 expert $i$ 在该 batch 内接到的 token 比例（$\sum_i f_i = K/N \cdot 1$，或归一化到 $\sum_i f_i = 1$）。

**指标 A — Max/Min ratio**：

$$R_{\max/\min} = \frac{\max_i f_i}{\min_i f_i}$$

- 理想均衡：$R = 1$
- 训练健康：$R < 5$
- 警戒线：$R > 10$ 说明有 expert 接近 dead

**指标 B — 路由熵**（Routing Entropy）：

$$H = -\sum_i p_i \log p_i, \quad p_i = \frac{f_i}{\sum_j f_j}$$

- 完全均衡：$H = \log N$
- 完全 collapse 到一个 expert：$H = 0$
- 通常监控 $H / \log N \in [0.8, 1.0]$ 为健康

**指标 C — Coefficient of Variation (CV)**：

$$CV = \frac{\text{std}(f_i)}{\text{mean}(f_i)}$$

- 完全均衡：$CV = 0$
- 健康：$CV < 0.3$
- 不健康：$CV > 1.0$ 意味着部分 expert 是另一些的 2 倍以上

实践中 max/min 和 CV 最常用，因为它们对"个别 dead expert"敏感（熵会被 N-1 个正常 expert 稀释）。

### 1.3 工程后果

```
负载不均的工程伤害：
  ├─ Capacity overflow（热门 expert 装不下） → token 被 drop
  ├─ Dead expert（参数白存）                 → 浪费总参数预算（GPU memory）
  ├─ All-to-All 通信不均衡                   → 单卡成瓶颈（§9.4）
  └─ 梯度更新不均                             → 训练越后差距越大
```

→ 必须**主动干预**，不能指望 router 自己学好。

## 二、第一代：Aux Loss（GShard / Switch）

[Lepikhin et al. 2020 — GShard](https://arxiv.org/abs/2006.16668)：在主 loss 上加一个 **辅助 loss** 来 penalize 不均衡。

### 2.1 完整公式

对一个 batch 内 $T$ 个 token、$N$ 个 expert：

**第一个量**：每 expert **实际接到** 的 token 比例（依赖 top-K 离散选择）

$$f_i = \frac{1}{T} \sum_{t=1}^{T} \mathbb{1}[\text{token } t \text{ 选了 expert } i]$$

**第二个量**：每 expert 的 **router 概率均值**（softmax 输出，连续可微）

$$P_i = \frac{1}{T} \sum_{t=1}^{T} s_i(x_t)$$

**Aux loss**：

$$L_{\text{aux}} = N \cdot \sum_{i=1}^{N} f_i \cdot P_i$$

加到主 loss：

$$L = L_{\text{LM}} + \alpha \cdot L_{\text{aux}}, \quad \alpha \approx 10^{-2}$$

### 2.2 为什么是 $f_i \cdot P_i$？逐项解释

**核心问题**：希望让 router 学到"均衡"行为。理想情况下 $f_i = 1/N$（每 expert 平均），但 $f_i$ **不可微**（来自 argTopK）。怎么把梯度信号注入 $W_g$？

GShard 的 trick：

- $f_i$ 是离散的（每 token 是否选 expert $i$ = 0/1），不可微
- $P_i$ 是连续的（softmax 输出），可微
- **乘积 $f_i \cdot P_i$** 让两者结合：
  - 当 expert $i$ 负载高（$f_i$ 大），$P_i$ 的梯度被放大 → 强烈推 router 把 $P_i$ 降下来
  - 当 expert $i$ 负载低（$f_i$ 小），$P_i$ 的梯度被压低 → 不强行干扰 router 的"喜好"
- 求和 $\sum f_i P_i$ 在 $f_i = P_i = 1/N$ 时取**最小值** $1/N$（柯西不等式 → 取系数 $N$ 后 = 1）

**为什么不是 $f_i^2$**：

- $f_i$ 不可微，$f_i^2$ 也不可微
- 没有梯度信号回 router

**为什么不是 $P_i^2$**：

- $\sum P_i^2$ 是可微的，最小值在均匀分布
- 但它只罚 router 输出概率不均，**不罚实际选择不均**——top-K 是非线性的，router 可能输出"看上去均匀"的概率，但 argTopK 仍然选同一个
- 用 $f_i$ 提供"实际选择信号"，$P_i$ 提供"梯度通路"，是最优组合

### 2.3 梯度通路

```
L_aux = N · Σ f_i · P_i
            │      │
            │      └─→ ∂L_aux/∂P_i = N · f_i
            │                       │
            │                       └─→ ∂L_aux/∂W_g 通过 softmax 反传
            │                           （f_i 当常数）
            │
            └─→ 不可微（stop-gradient）

→ 梯度推 W_g：让 P_i 在 f_i 大的方向上变小
              即"被选中多的 expert，router 给它更小的 score"
```

### 2.4 $\alpha$ 怎么选

| $\alpha$ | 行为 |
|---|---|
| $10^{-3}$（小） | 几乎不约束，可能 collapse |
| $10^{-2}$ | 标配（GShard / Switch / Mixtral） |
| $10^{-1}$（大） | 过度约束，强行均衡，质量下降 |
| $> 1$ | router 几乎完全学均衡，失去内容相关性，质量大幅下降 |

DSv3 团队报告（论文 §2.1.2）：在 256 expert 配置下，$\alpha$ 必须精调到 $\sim 10^{-3}$ 量级，太大严重掉点，太小不能压住 collapse → **这是 DSv3 改用 aux-loss-free 的直接动机**。

### 2.5 实测有效但有副作用

- **优点**：能基本压住 dead expert，工程实现简单
- **缺点**：
  - aux loss 本身会"扰动"主任务 loss——尤其在收敛后期，aux loss 不再有用，反而拉低质量
  - 需要在不同模型尺寸下重新调 $\alpha$，不 scale-invariant
  - DSv3 论文测量：去掉 aux loss 后，benchmark PPL 略降，且负载更均衡（详 §4.3）

## 三、第二代：Router z-loss（ST-MoE）

[Zoph et al. 2022 — ST-MoE](https://arxiv.org/abs/2202.08906) 在 aux loss 之外又加了一个**正交的 loss**：

$$L_z = \frac{1}{B} \sum_{b=1}^{B} \left( \log \sum_{j=1}^{N} e^{x_{b,j}} \right)^2$$

其中 $x$ 是 router 的 **raw logits**（softmax 前）。

### 3.1 先明确：什么是 router logits

回顾 §9.1 的 router 计算链：

```
h（token 隐藏向量）
   │
   ▼
W_g · h  →  x = [x_1, x_2, ..., x_N]     ← logits（softmax 之前的"原始分数"）
   │
   ▼
softmax(x) → s = [s_1, ..., s_N]         ← 概率（每个 expert 的"票"）
   │
   ▼
TopK(s)                                  ← 离散选择
```

**logits = router 对每个 expert 的原始打分，未经过 softmax**。
本节 z-loss 关心的就是这一组数 $x$ 的**绝对数值大小**。

### 3.2 根因：LM loss 看不见 logits 的绝对尺度

**关键事实**：softmax 是**平移不变**（translation-invariant）的——

$$\text{softmax}(x_1, ..., x_N) = \text{softmax}(x_1 + c, ..., x_N + c)$$

（严格来说是"加常数不变"，不是常被误称的 scale-invariant；softmax 对**乘**常数并非不变。）

含义：把所有 logits 一起 +10，softmax 输出完全一样。

而 LM 主 loss 关心的是 expert 选对了没、混合权重对不对——它只看 softmax **之后**的概率。
**所以 LM loss 对 logits 的绝对数值毫无约束**：
$x = [0.5,\ 0.3,\ -0.2]$ 还是 $x = [10.5,\ 10.3,\ 9.8]$，对它来说几乎是同一件事。

**但梯度会持续推 logits 往大处飘**：

```
某 token 路由到 expert 5 → expert 5 输出好 → LM loss 下降
   ↓
反传：希望"下次更确定选 expert 5"
   ↓
W_g 第 5 列变大 → x_5 变大
   ↓
下次 x_5 更大 → softmax 更尖锐 → 更确定选 expert 5
   ↓
雪球放大：logits 标准差从 ~0.1 → 1 → 3 → 8 → 15 ...
```

这就是所谓的 **logits 数值漂移**：训练越久，$x$ 的整体量级越大。
LM loss 没有任何机制拦住它，因为它"看不到"这件事。

### 3.3 漂移的两个独立灾难

**灾难 A — softmax 进饱和区，梯度消失**

softmax 的导数：

$$\frac{\partial s_i}{\partial x_j} = s_i(\delta_{ij} - s_j)$$

- logits 小（$\sigma \approx 0.3$），例 $x = [0.5, 0.3, -0.2, 0.1, ...]$：
  - softmax ≈ $[0.22, 0.18, 0.11, 0.15, ...]$，接近均匀
  - 导数量级 $\sim 1/N$，**有梯度**
- logits 大（$\sigma \approx 5$），例 $x = [10, 8, -3, -1, ...]$：
  - softmax ≈ $[0.88, 0.12, 0.0, 0.0, ...]$，极陡
  - 主项导数 $\approx 0.88 \times 0.12 \approx 0.1$，**其余几乎全为 0**
  - → router 在这种状态下**几乎学不动**，永远卡在当前偏好

**灾难 B — BF16/FP16 数值溢出**

- BF16 上限约 $3.4 \times 10^{38}$
- $e^x$ 增长极快：$x \approx 89$ 时 $e^x$ 就溢出
- 实测 logits 飘到 ~30 量级时 BF16 即出 NaN
- 一次 NaN → 整个 step 梯度作废；严重时 checkpoint 都救不回

### 3.4 z-loss 的工作机制

ST-MoE 的核心想法：**LM loss 不管 logits 的绝对尺度，那就专门加一个管尺度的 loss**。

$$L_z = \left( \log \sum_j e^{x_j} \right)^2$$

中间那个量叫 **LogSumExp（LSE）**，关键性质：

1. **光滑的 max**：当某个 logit 显著大时，$\text{LSE}(x) \approx \max_j x_j$
2. **不是平移不变**：所有 $x_j$ 同加 $c$，LSE 也跟着 $+c$
   → 这正好补上 softmax 缺失的那个维度——LSE **直接反映 logits 的绝对水平**

平方后变成二次惩罚：LSE 离 0 越远，惩罚越大。

```
正常：x = [0.5, 0.3, -0.2, ...]    LSE ≈ 1.0,    L_z = 1     → 弱惩罚
漂移：x = [10,  8,   -3,  ...]     LSE ≈ 10.1,   L_z ≈ 102   → 强惩罚
                                                  ↑
                                  梯度反传 W_g：让所有 logits 整体往下拉
```

**形象理解**：z-loss = 给 router logits 套了一根弹簧，把它们往 0 拉。
LM loss 管"分布形状"，z-loss 管"绝对尺度"——**职责分离**。

→ logits 被锁在 $O(1)$ 范围，softmax 输出平滑，梯度健康，BF16 不溢出。

### 3.5 z-loss 是数值稳定 loss，不是负载均衡 loss

| 维度 | aux loss | z-loss |
|---|---|---|
| 解决问题 | 负载均衡 | 数值稳定 |
| 罚什么 | 不均衡分布 | 大 logits |
| 与 router 关系 | 影响 router 偏好 | 控制 router 输出尺度 |
| 是否必需 | 早期必需（DSv3 已替换为 bias） | **现代 MoE 标配**，DSv3 也保留 |

两者**正交**，可叠加：

$$L = L_{\text{LM}} + \alpha L_{\text{aux}} + \beta L_z$$

经验值：$\alpha = 10^{-2}, \beta = 10^{-3}$。

### 3.6 z-loss 在 DSv3 里仍然保留

DSv3 完全去掉了 aux loss（§4），但**保留了 z-loss**——它解决的是数值稳定，与负载均衡机制无关。具体地：

- DSv3 router 用 sigmoid 而非 softmax，但 sigmoid 也有"饱和"问题（logit 太大时 $\sigma(x) \to 1$，梯度消失）
- z-loss 把 logit 量级控制住，sigmoid 输出保持可学习范围
- 配合 FP32 router 计算，数值稳定性进一步加强

## 四、第三代：Aux-Loss-Free（DeepSeek-V3）

[DeepSeek-V3 (2024-12) §2.1.2](https://arxiv.org/abs/2412.19437) 创新最大的一处：**完全去掉 aux loss**，改用 **expert-wise bias 自适应调整**。

### 4.1 设计哲学

> aux loss 干扰主 loss → 何不直接在 logits 上加 bias，绕过 loss 通道？

把"负载均衡"从**软约束（loss）**改成**硬调整（bias）**。bias 不通过梯度学，而是由观察到的负载直接驱动。

### 4.2 完整算法

**Step 1 — 路由公式**（§9.1 第五节已展开，这里再写一遍）：

$$s_i = \sigma(W_g^{(i)} x)$$
$$\tilde{s}_i = s_i + b_i \quad \text{(加 bias)}$$

**Step 2 — TopK 用 $\tilde{s}$，权重用 $s$**：

$$\text{TopK indices} = \arg\text{TopK}_i(\tilde{s}_i)$$
$$w_i = \frac{s_i \cdot \mathbb{1}[i \in \text{TopK}]}{\sum_{j \in \text{TopK}} s_j}$$

**关键设计**：bias 决定**谁被选中**，但**不污染权重**。

- 如果 bias 进入权重：相当于学了一个等价 $W_g' = W_g + b$，没新意
- 只在 TopK 阶段用 bias：让"硬调整"专门作用于"哪些 expert 进入计算"，不破坏 expert 输出的混合比例

**Step 3 — Bias 更新规则**（核心）：

每个 training step 结束后：

```python
# 每个 step 算一次 expert i 的负载误差
load_i = (该 step 中 expert i 接到的 token 数) / (总 token 数 × K / N)
# load_i = 1 表示恰好均衡；> 1 表示超载

# 按规则更新 bias
for i in range(N):
    if load_i > 1:
        b_i -= γ        # 这个 expert 太满了，降低优先级
    else:
        b_i += γ        # 这个 expert 太闲了，提升优先级
```

**Step 4 — Bias 的初始化与边界**：

- 初始化：$b_i = 0$
- 上下界：实际中限制 $|b_i| < c$ 防止 bias 失控（c 是经验值，DSv3 论文未公开具体数字）
- $\gamma$（步长）：DSv3 使用 $\gamma = 10^{-3}$ 量级，与学习率独立

### 4.3 收益

| 维度 | 传统 Aux Loss | Aux-Loss-Free |
|------|-------------|--------------|
| 主 loss 干扰 | 有（α 调难） | 无 |
| 负载均衡度 | 中等 | **更好（DSv3 实测）** |
| 实现复杂度 | 简单 | 略复杂（要维护 bias） |
| 是否破坏 router 学习 | 是（梯度被 aux 拉扯） | 否（router 只学内容相关性） |
| 兼容性 | 几乎所有 framework | 需 router 内部改 |
| Scale 行为 | 需重调 α | $\gamma$ 不依赖模型大小 |

**DSv3 论文报告**：去掉 aux loss 后：
- 负载更均衡（max/min ratio 从 ~3 降到 ~1.5）
- 主 loss 反而更低 → benchmark 质量提升

**为什么质量更好**：

- aux loss 是"代理目标"——它逼着 router 均衡，**但牺牲了 router "找到内容最匹配 expert" 的能力**
- bias 调整不进 loss → 主 loss 纯净 → router 仍然学"哪个 expert 最适合"
- 均衡靠 bias 强制实现，质量靠 loss 纯净保留
- 这是个**优雅的关注点分离**：把"内容学习"和"负载约束"用不同机制实现

### 4.4 保留的辅助手段：Sequence-level Balance Loss

DSv3 **没有完全裸奔**——它仍然加了一个**轻量 sequence-level** loss：

$$L_{\text{seq-bal}} = \alpha_{\text{seq}} \cdot \sum_{i=1}^{N} f_i^{\text{(seq)}} \cdot P_i^{\text{(seq)}}$$

其中 $f_i^{\text{(seq)}}, P_i^{\text{(seq)}}$ 是**单个 sequence 内**的 expert 频率和概率均值（而不是整 batch）。

**为什么需要 sequence-level**：

- bias 更新是 **batch-level**——保证 batch 内每个 expert 都接到合理数量 token
- 但 **单个 sequence 内** 可能仍偏（如一整段中文文本都路由到 expert 5）
- 推理时若一个 user query 的 token 全部去同一个 expert → 推理 batching 调度灾难（§9.4）
- sequence-level loss 给一个**很小的 $\alpha_{\text{seq}}$**（如 $10^{-4}$），轻度均衡单 sequence

→ DSv3 实际上是 "**aux-loss-free 在 batch level** + **轻 aux loss 在 sequence level**"。

### 4.5 与 z-loss 的关系

- z-loss 保留 → 数值稳定
- batch-level aux loss 去掉 → 主 loss 干净
- 加入 sequence-level mini aux loss → 推理友好
- 加入 bias 调整 → 主要负载均衡机制

→ DSv3 的负载均衡是个**四件套**：bias + z-loss + sequence-level loss + (隐式：grouped TopK 限制通信扇出)。

## 五、Capacity / Token Dropping —— 工程兜底

aux loss / aux-loss-free / bias 都是 **soft** 约束，仍可能短期偏。
工程上有 **hard** 约束 = capacity factor。

### 5.1 Capacity 公式

每个 expert 在一个 batch 内最多处理：

$$C = \text{capacity\_factor} \cdot \frac{T \cdot K}{N}$$

- $T$ = batch token 数，$K$ = top-K，$N$ = expert 数
- $T \cdot K / N$ = 完全均衡时每 expert 接到的 token 数
- $\text{capacity\_factor}$ 通常 1.0 - 1.5：留多少 buffer 防止超载

**实际工程实现**：每个 expert 的输入是一个**固定大小**的张量 $[C, d]$，避免动态分配。

### 5.2 超过 capacity 怎么办

有几种处理：

1. **Token dropping**：超出 capacity 的 token 直接跳过此 MoE 层（走 residual），最常用
2. **Token shuffling**：把多余 token 转给次优 expert（次选 K+1）
3. **Expert padding**：在低负载 expert 上填 padding（仅 expert-choice）

工业实操：

- 训练时用 capacity_factor = 1.25 + token dropping
- 推理时通常 capacity_factor 略大（1.5-2.0），少 drop

### 5.3 Token Drop 的代价

```
丢一个 token = 它在该层只走 residual，没经过任何 FFN
       ─→ 信息丢失 + 训练信号削弱
```

实测 capacity = 1.0 时 drop 率可达 10-30%，质量明显掉。这是 **dropless MoE** 出现的动机。

### 5.4 Dropless MoE（MegaBlocks）

[Gale et al. 2023 — MegaBlocks](https://arxiv.org/abs/2211.15841) 提出：**完全不 drop**。

核心思路：

- 用 **block-sparse matmul** 处理变长 expert 输入
- 不强制 expert 输入张量同样大小
- token 按 expert id 排序后切成 N 个变长 block，统一一次 GEMM

实测：
- 消除 token drop 带来 ~5-10% 质量提升
- 计算开销：block-sparse GEMM 比 dense GEMM 慢 ~10-20%

→ DeepSpeed-MoE、vLLM、SGLang 都已集成 MegaBlocks 风格 dropless。

详见 §9.3 第三节（dropless MoE 的 kernel 实现）。

## 七、关键问答

**Q1**：aux loss 为什么要 $N \cdot \sum f_i P_i$ 这种形式？

- $f_i$（实际负载）不可微，但提供"哪个 expert 偏多"的信号
- $P_i$（router 概率）可微，提供梯度通路
- 乘积形式让"负载高的 expert" 的 router 概率被压低
- 乘以 $N$：让 balanced 时 $L_{\text{aux}} = 1$，便于 $\alpha$ 调
- 详见 §2.2

**Q2**：DeepSeek-V3 去掉 aux loss 后为什么质量更好？

- aux loss 是个"代理目标"：它逼着均衡，但牺牲了 router 找"内容最匹配 expert"的能力
- bias 调整不进 loss → 主 loss 纯净 → router 仍然学"哪个 expert 最适合"
- 均衡靠 bias 强制实现（硬约束），质量靠 loss 纯净保留
- DSv3 论文 §4 测量：去掉 aux loss 后 benchmark 略升

**Q3**：z-loss 和 aux loss 关系？

- z-loss = 数值稳定（防 logits 爆 → softmax/sigmoid 饱和）
- aux loss = 负载均衡（防 expert collapse）
- 两者正交，可叠加
- DSv3 保留 z-loss，但去掉 aux loss
- 现代 MoE 都用 z-loss

**Q4**：capacity_factor 怎么选？

- 训练：1.25 - 1.5（留 buffer 防 drop）
- 推理：1.5 - 2.0（更保守，因为单次 batch 小，统计涨幅大）
- 太小：drop 太多伤质量
- 太大：浪费显存（buffer 是 worst case 张量）
- Dropless 模型可以 = 1.0（不 drop，但需要 block-sparse kernel）

**Q5**：负载不均会导致显存爆吗？

- 会。expert i 收到太多 token → 这块卡的激活显存爆
- 实操：要么 capacity 限死（强行丢），要么 dropless + 动态 padding（buffer 大）
- 在多机 EP 训练中尤其要看（§9.4）

**Q6**：训练时 aux loss 一定要从头开到尾吗？

- 早期 step 关键（防 collapse）
- 后期可以衰减或关闭（ST-MoE 实验过 ramp down）
- DSv3 用 bias 完全代替了这套折中，全程稳定

**Q7**：sequence-level aux loss 是什么？

- 不是 batch 内均衡，而是 **单 sequence 内**均衡
- 让一个 sequence 不要全部投到一个 expert
- 好处：推理时该 sequence 的 expert 调用更分散，便于 batch 调度（§9.4）
- DSv3 用很小的 $\alpha_{\text{seq}} \approx 10^{-4}$，仅作轻度约束

**Q8**：aux-loss-free 的 $\gamma$ 怎么选？

- DSv3 用 $\gamma = 10^{-3}$ 量级
- 关键：$\gamma$ 与学习率独立——bias 不进梯度，所以不受 lr schedule 影响
- 太小：调整慢，前期可能短暂 collapse
- 太大：bias 抖动剧烈，TopK 选择不稳

**Q9**：bias 会 saturate 吗？

- 理论上：如果某 expert 长期"超载"，bias 会一直 -= $\gamma$，可能负到很大
- DSv3 实操：加上下界（论文未公开具体数字，常见做法 $|b_i| < 1$）
- 实测：训练稳定后 $b_i$ 在 $\pm 0.3$ 内浮动

**Q10**：如果 router 本身崩了（NaN），怎么救？

- 首选：z-loss + FP32 router（防 logits 爆）
- 已经 NaN：从 checkpoint 回滚，加大 z-loss 系数
- DSv3 / Megatron-MoE 都有 router fallback：检测 NaN 自动用 uniform 替换该 step 的 router 输出

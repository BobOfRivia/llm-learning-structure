# 12.3 推测解码（Speculative Decoding：Draft Model / Medusa / EAGLE / Lookahead）

[← 返回框架](../../README.md) · [📎 materials.md → §12.3](../../materials.md)

---

## 〇、本节回答什么

> decode 是 LLM 推理最贵的阶段——它是 memory-bound 且严格串行。推测解码（Speculative Decoding, SD）是过去两年最关键的免损（lossless）加速手段：用小模型/小头猜 k 个 token，主模型一次性验证。本节讲清楚为什么 SD 真的免损、有几种代表性流派（draft model / Medusa / EAGLE / Lookahead）、各自的优劣 trade-off，以及生产里 EAGLE-2/3 为什么吃到了主流。

加速比经验区间：**1.5–3× decode throughput**，**输出与原模型完全等价**（采样分布严格相同）。

---

## 一、为什么 decode 可以"猜+验"地加速

### 1.1 prefill vs decode 的算术强度差异

| 阶段 | 处理 token | 算术强度 (FLOPs / byte) | bound |
|------|-----------|--------------------------|-------|
| prefill | N（全 prompt） | 高（N × 模型参数） | **compute-bound** |
| decode | 1 / step | 低（1 × 模型参数） | **memory-bound** |

decode 时**每步要把所有参数从 HBM 读一遍只算 1 个 token 的 FLOPs**——GPU 算力被 bandwidth 锁死，FLOPs 浪费严重。

### 1.2 关键洞察

如果一次 forward 可以**同时算 k+1 个 token 的 logits**（用并行 K/V 拼一个长 query），算力增加的边际成本极低（仍是 memory-bound 直到 k ~ 数十），但**摊薄了串行步骤**。

> **推测解码 = "并行验证 k 个候选"，把 k 次串行 decode 合成 1 次 forward。**

### 1.3 收益 = 接受率 × 串行步骤减少

每轮主模型 forward 一次，接受 0~k 个 token：
- 平均接受 $\alpha k$ 个 token（$\alpha$ = 平均接受比例）
- 单次主模型 forward 等价于产 $\alpha k + 1$ 个 token
- **理论加速比** ≈ $(\alpha k + 1) / 1$，受限于主模型 forward 的固定 overhead

实际：$\alpha$ 越高 / $k$ 越合理 → 加速越大；$\alpha$ 低（draft 跟不上 target 风格）反而会减速（因为 draft + verify 比单步 decode 还贵）。

## 二、经典推测解码（Speculative Sampling, Google 2022 / DeepMind 2023）

### 2.1 基本流程

```
target model: Mt
draft model:  Md (小 N×)

while not done:
  1. draft 自回归生成 k 个候选 token: x1..xk
     同时记录 Md 在每位的概率 q1..qk
  2. target Mt 一次 forward 算出 p1..pk+1
     （拼成 1 个长 query 一起算）
  3. 从左到右接受 token:
       接受 xi 的概率 = min(1, p_i(xi)/q_i(xi))
     一旦拒绝 xj，从 (p_j - q_j)+ 归一化分布里采一个替代 token
  4. 永远多一个 bonus token（即 step k+1，因为 target 已经算出来）
```

### 2.2 为什么"严格等价"（lossless）

数学结论（Chen et al. 2023）：上述拒绝采样策略保证**最终采样到的 token 分布 ≡ 直接从 target 采样**。

直观：
- 接受率为 $\min(1, p/q)$ 是经典 **rejection sampling** 的修正比
- 当 $p > q$（target 更喜欢这个 token），全接受；
- 当 $p < q$（draft 高估），按比例接受，并用残差分布 $(p-q)_+$ 补偿

### 2.3 实操中的两类 draft

| draft 形态 | 例子 | 接受率 | 加速 |
|-----------|------|--------|------|
| 同家族小模型 | Llama-3-70B 的 draft = Llama-3-8B | 70%+ | 2× |
| 提前训练的"小专家" | Vicuna-68m | 60% | 1.5–2× |
| 主模型的早退分支 | LayerSkip / Self-Speculative | 50% | 1.5× |

**问题**：小模型 draft 的开销不可忽略——draft 自回归 k 步同样是 memory-bound，且 KV 不能复用 target。

## 三、Medusa（2024, Princeton + Together）

### 3.1 核心想法：去掉独立 draft，**用 target 模型自己的多头并行 draft**

在 target 模型最后一层 hidden 上加 **K 个"Medusa heads"**：
- head 1 预测 t+1
- head 2 预测 t+2
- ...
- head K 预测 t+K

```
target last hidden h_t
   ├─→ original LM head → next token x_{t+1}
   ├─→ Medusa head 1   → candidate x_{t+1}^(1)
   ├─→ Medusa head 2   → candidate x_{t+2}^(2)
   ├─→ ...
   └─→ Medusa head K   → candidate x_{t+K}^(K)
```

### 3.2 树式候选 + tree attention

K 个 head 各给一个 top-N，组合得到 $N^K$ 条候选 path，太多 → 剪枝成**候选树（speculation tree）**：

```
            t+1 选 3 个 top
           /  |  \
         t+2 各选 2 个
        /|  /|  /|
       ...

     树枝总数 ~ k_tree ≈ 64
```

target 一次 forward 用 **tree attention mask** 同时算所有 candidate path 的 logits：

```
attention mask 形如：
                    parent
candidate j:        ↑
                    sees only its ancestors in the tree
```

一次 forward 等同于评估 64 条 ≤ K-长 path，按拒绝采样接受最长前缀。

### 3.3 Medusa 优缺点

| ✓ | ✗ |
|---|---|
| 不需独立 draft 模型，只加几个轻量 head | head 需要在 target 上训练 |
| 复用 target KV，零额外 KV | head 间独立，t+i 的预测看不到 t+i-1，准确率有限 |
| 工程简单，已被 vLLM/TGI/TRT-LLM 内置 | 接受率比 EAGLE 低（~50–60%） |

## 四、EAGLE 系列（2024–2025，SJTU / Microsoft）

> 当下生产 SD 的事实标准。EAGLE-1/2/3 三代迭代各解决一个问题。

### 4.1 EAGLE-1 (2024)：自回归 draft head + 用 target 的 hidden 当条件

Medusa 的核心缺陷：各头独立预测，t+i 看不到 t+i-1，对长 draft 不利。EAGLE 改成**轻量自回归 draft 网络**：

```
draft network = 1 个轻量 Transformer 层（远小于 target）
input  = target 最后一层 hidden + 上一步采样的 token
output = 下一个 token 的 logits
```

→ draft 是自回归的（能看到自己之前 draft 的 token），但只跑一层、几乎免费。

**关键**：用 **target 模型自己的最后 hidden state** 作为 draft 的输入（不是 embedding）。这让 draft 极快"贴近" target 分布，接受率显著提升（70–85%）。

### 4.2 EAGLE-2 (2024-06)：动态树 + 上下文感知剪枝

EAGLE-1 仍用固定树。EAGLE-2 改成**根据 draft 置信度动态扩张/剪枝**：

```
在 draft 输出每一步：
  confidence > τ → 多扩几个 candidate
  confidence < τ → 仅留 1 个
```

平均接受 token 数 ↑，token 验证开销 ↓。EAGLE-2 在 Vicuna-13B / Llama-3-70B 上**加速 3–4×**，是公开 lossless SD 的高水位。

### 4.3 EAGLE-3 (2025)：multi-layer feature + 跨样本训练数据

EAGLE-3 改两件事：
1. **draft 不只用最后一层 hidden**，用多层 feature 加权（layer skip 风格）
2. **更鲁棒的训练数据采集**，draft 在分布外更稳

→ 加速到 **4–5× decode throughput**，并且对长上下文场景明显改善。

### 4.4 EAGLE 流派优势

| EAGLE 系列 | 接受率 | 加速 | 备注 |
|------------|--------|------|------|
| EAGLE-1 | 70–80% | 2.5–3× | 自回归 draft + target hidden 条件 |
| EAGLE-2 | 75–85% | 3–4× | 动态候选树 |
| EAGLE-3 | 80–90% | 4–5× | 多层 feature，长上下文更好 |

**为什么 EAGLE 比 Medusa 强**：自回归 draft + target 的 hidden 作为条件——本质等价于让 draft "见过 target 的内部表示"，所以预测更准。

## 五、Lookahead Decoding（2023-11, LMSYS）

> 不需要训练任何 draft 模型 / head 的"训练免费"路线。

### 5.1 核心想法：Jacobi 迭代 + n-gram 缓存

把 decode 看成 Jacobi 不动点迭代：

```
原 decode:   x_{t+1} = f(x_1..x_t)            (顺序)
Jacobi:      给一组初值 y_1..y_k，迭代直到收敛
             y_{t+1}^{(i+1)} = f(x_1..x_t, y_1..y_t^{(i)})
```

实际操作：每次 forward 同时预测**多个未来位置的 token**，多次迭代直到位置稳定。

附加：把历史上 forward 看到的 n-gram 缓存起来，下次出现相同 prefix 直接命中（**lookahead n-gram cache**）。

### 5.2 优缺点

| ✓ | ✗ |
|---|---|
| **完全无需训练**，pure runtime | 加速比通常 1.5–2×，低于 EAGLE |
| 适合临时给任何模型加速 | 对长 prompt 改进有限 |
| 已被 vLLM 集成（NGRAM speculator） | 接受率受限于自然语言的 n-gram 命中率 |

## 六、其他变体

### 6.1 Self-Speculative / LayerSkip（Meta, 2024）

target 模型自己**早退**作为 draft：前 L_d 层 forward → 早退一个轻量 head 算 draft；后续完整 forward 验证。

- 不需要额外模型 / head
- 但需在训练或 SFT 时加上 layer-skip loss，让浅层就能预测

### 6.2 Block-wise Parallel Decoding（Google, 2018，SD 的祖师）

最早的"训一个小模型并行预测多个未来 token"工作，奠基。

### 6.3 SpecInfer / Sequoia / Hydra

各种把 EAGLE / Medusa 与树搜索 / 多 draft 结合的扩展，工业落地较少。

### 6.4 prompt-lookup decoding（PLD）

针对 **input-output 高度重叠**场景（RAG / 长上下文 QA）：直接从 input 里搜 n-gram 当 draft，几乎零开销。在文档摘要 / 翻译 / 代码补全等场景加速明显。

## 七、SD 与其他系统组件的关系

```
            ┌── prefix cache（§12.2）  ── 不冲突
            │
推测解码 ──┼── continuous batching   ── batch 内不同请求 draft 步不齐 → 调度复杂
            │
            ├── CUDA Graph（§12.2）   ── 接受数动态，shape 变化 → 多档录制
            │
            └── PD 分离（§12.4）       ── decode 节点上叠加 SD 收益更大
```

### 7.1 与 batching 的 trade-off

- **小 batch**：bandwidth 浪费严重，SD 收益最大（3–5×）
- **大 batch**：compute 已经饱和，SD 收益缩小到 1.2–1.5×
- 因此 SD 是**低 batch / 低 latency 场景**的关键

### 7.2 工程实现要点

- draft 与 target 的 vocab 必须一致（否则拒绝采样数学失效）
- draft 需要"足够小"（开销 < target 单步的 20%）
- 接受率监控：低于 30% → 关 SD，否则减速
- KV cache 在拒绝点需回滚（PagedAttention 上很简单：丢掉对应 block）

---

## 八、什么时候不该用 SD

- 大 batch / 高 utilization 推理（已 compute-bound）
- 输出极短（< 32 token）的请求（draft + verify 摊不开 overhead）
- 长 reasoning（CoT）中拒绝率上升（多步推理 draft 难跟上）
- 严格 token-level 实时要求（streaming first token 已经够低延迟）

## 九、关键问答

**Q1：推测解码真的"完全无损"吗？**
A：**是**，使用 speculative sampling 的拒绝接受规则时，最终采样分布与直接从 target 采样**严格相同**（数学可证）。但有两个 caveat：（1）greedy 解码下接受准则退化为 "argmax 一致才接受"，分布一致是 trivially holds；（2）实现里如果做了某些"加速 trick"（如低精度 draft、early stop on EOS）可能引入轻微偏差，工程上一般可忽略。

**Q2：EAGLE 为什么比 Medusa 强？**
A：核心在两点：（1）EAGLE 的 draft head 是**自回归**的（看得到自己之前 draft 的 token），Medusa 各头独立预测看不到；（2）EAGLE 用 **target 模型的最后 hidden state** 作为 draft 输入，等价让 draft 直接看到 target 的内部表示。这两点让接受率从 ~50% 升到 ~80%。

**Q3：draft 模型用多大合适？**
A：经验上 draft 参数量 = target 的 1/10 ~ 1/30 是甜点。Llama-3-70B + Llama-3-8B（≈ 1/9）效果就很好；70B + 0.5B 也能用。再小则风格漂移、接受率掉；再大则 draft 自己变成瓶颈。

**Q4：树式候选（tree attention）比线性 draft 好在哪？**
A：线性 draft 一次只验证一条 path（k 个候选 token），一旦中间拒绝就丢掉后面所有 draft。树式同时验证 N×K 条 path，**任何一条 path 被全接受都赚到**——期望接受长度提高 30–50%。代价是 verify forward 的 batch 略大但仍 memory-bound。

**Q5：推测解码与 prefix cache 冲突吗？**
A：不冲突。prefix cache 加速的是 prefill，SD 加速的是 decode，作用阶段不同。工程上叠加，并都已在 vLLM / SGLang 默认开启。

**Q6：长 reasoning（CoT、R1 模型）能用 SD 吗？**
A：能但收益打折。长 reasoning 文本中"非典型 token"（公式、变量名、代码）多，draft 模型预测准确率掉，接受率从 80% 降到 50% 左右，加速从 3× 降到 1.5×。EAGLE-3 在长上下文上做了改善。生产里对推理模型常用 **smaller draft + lower k**。

**Q7：为什么 Mooncake / DistServe 把 SD 放在 decode 节点而不是 prefill 节点？**
A：prefill 是 compute-bound，没有 bandwidth 富余给"猜+验"；decode 是 memory-bound，SD 才有效。在 PD 分离架构里，prefill 节点专注吞吐，decode 节点开 SD 摊薄串行步——一个典型的"对症下药"组合。

# 12.1 量化（GPTQ / AWQ / SmoothQuant / FP8 / NVFP4）

[← 返回框架](../../README.md) · [📎 materials.md → §12.1](../../materials.md)

---

## 〇、本节回答什么

> LLM 量化要解决什么瓶颈？W8A8 / W4A16 / FP8 / NVFP4 各自什么场景？为什么 LLM 量化关键不在 weight 而在 activation outlier？GPTQ / AWQ / SmoothQuant 数学上做了什么？2025 训练 + 推理都跑 FP8/NVFP4 是怎么落地的？

量化是推理优化最直接的杠杆——**显存减小 N 倍、带宽提高 N 倍、Tensor Core 算力翻倍**。它直接对准 §4 Roofline 的两个轴：memory-bound 阶段（decode）由 bandwidth 决定，量化让相同 bandwidth 搬 4 倍 token 状态；compute-bound 阶段（prefill）则吃到 FP8/INT4 Tensor Core 的额外算力。

---

## 一、为什么要量化：从 Roofline 看

### 1.1 显存 + 带宽 双重收益

70B 模型 weight：

| 精度 | bytes/param | 总显存 | 1 张 H100 (80GB)？|
|------|-------------|--------|---------------------|
| FP16 / BF16 | 2 | 140 GB | 不行（要 2 张） |
| FP8 (E4M3) | 1 | 70 GB | 临界 |
| INT4 (W4A16) | 0.5 | 35 GB | 余 45 GB 给 KV cache |
| NVFP4 | 0.5 | 35 GB | 同上但带硬件原生 scaling |

decode 阶段是**带宽瓶颈**——每生成 1 个 token 要把整套 weight + KV 从 HBM 搬到 SM。把 weight 从 FP16 压到 INT4，理论 4× 加速（实际 2.5–3×，受 dequant overhead 影响）。

### 1.2 三类对象都可以量化

```
量化对象：
  Weight (W)         ← 静态、离线、量化误差易控
  Activation (A)     ← 动态、随输入变化、有 outlier、最难
  KV Cache (KV)      ← 见 §12.5；单独的 KV 量化派系
```

常见命名 **W4A16** = weight INT4 + activation FP16；**W8A8** = 都 INT8；**W4A8** 两边都压。

### 1.3 LLM 量化的"反直觉"特点

> CV 时代 INT8 PTQ 几乎无损。LLM 不一样：**activation 有极端 outlier**（个别 channel 数量级 100×），简单 per-tensor / per-channel 量化会直接崩。

GPTQ / AWQ / SmoothQuant 三大流派的核心区别就在**怎么处理 activation outlier**。

## 二、量化基础：scale / zero-point / 对称非对称

### 2.1 仿射量化

$$
x_q = \text{round}\left(\frac{x}{s}\right) + z, \quad x \approx s \cdot (x_q - z)
$$

- $s$：scale（一个浮点数）
- $z$：zero-point（整数）
- 对称量化：$z = 0$，scale 由 $|x|_\max$ 算
- 非对称量化：保留 $z$，能更好拟合非零均值分布

### 2.2 粒度（granularity）

```
per-tensor       → 整个张量一个 scale       误差最大、最省
per-channel      → 每个 output channel 一个 scale
per-token        → 每个 token 一个 scale（activation 常用）
per-group        → 每 K 个连续元素一组（K=64/128 常见）
```

W4 通常用 **group-wise（g128）** 才能保持精度：每 128 个权重一个 scale + zero-point。

### 2.3 PTQ vs QAT

| | PTQ（Post-Training Quantization） | QAT（Quantization-Aware Training） |
|---|---|---|
| 何时做 | 训完拿权重直接量化 | 训练时插假量化结点 |
| 数据需求 | 小量 calibration set（128–512 样本） | 全量训练数据 |
| 精度 | INT8 几乎无损；INT4 需精细处理 | 更好但贵 |
| LLM 用谁 | **绝大多数用 PTQ**（训练贵） | 极少（DeepSeek-V3 用 FP8 训练算是 QAT 思想） |

## 三、三大 PTQ 流派

### 3.1 GPTQ（2022, Frantar et al.）

**核心**：逐列 / 逐块量化 weight，**用海森近似补偿剩余列**的量化误差。

数学：对于线性层 $Y = WX$，量化 $W \to \widehat W$ 时，逐列 quantize 后用剩余列调整：

$$
\widehat w_j = \text{quant}(w_j), \quad
\delta = (w_j - \widehat w_j) \cdot \frac{H_{j,:}^{-1}}{H_{jj}^{-1}}
$$

剩余未量化的列加上 $\delta$ 来抵消误差。$H = X X^\top$ 是激活的二阶统计。

| GPTQ 特点 |
|---|
| Weight-only 量化 → W4A16 主流 |
| 一次 calibration（几百样本）→ 离线一次性产物 |
| group-size 128 是甜点；group=32 更准但 metadata 增大 |
| **推理端纯整数 GEMM 反而慢**（dequant 到 FP16 再算）|

> GPTQ 几乎是 2023 年开源社区 W4 量化的事实标准（GPTQ-for-LLaMA、AutoGPTQ）。

### 3.2 AWQ（Activation-aware Weight Quantization, 2023, MIT-Han Lab）

**核心观察**：**1% 的 weight 是 salient 的，对应大的 activation channel**。这些 channel 不要量化，或者给它们一个独立的 scale。

数学技巧：对 weight $W$ 和 activation $X$ 同时做缩放：

$$
W X = (W \cdot s)(X / s) = \tilde W \tilde X
$$

- $s$ 由 $X$ 的 channel-wise 幅度决定（**activation-aware**）
- 对 salient channel 给较大的 $s$，把 weight 推大 → 量化后相对精度高
- $X/s$ 改变了 activation 但 $\tilde X$ 仍可继续走前面的算子（**搜索 $s$ 不重训**）

| AWQ vs GPTQ |
|---|
| AWQ 不需要二阶信息（grid search $s$）→ 实现简单 |
| INT4 W4 精度普遍 ≥ GPTQ |
| **AWQ 的 marlin kernel** 是工程上 W4A16 推理事实最快路径 |
| vLLM、TensorRT-LLM、llama.cpp 都内置 AWQ |

### 3.3 SmoothQuant（2022, MIT）

**针对 W8A8** 这条路：activation outlier 让 A8 不可行 → SmoothQuant 把 outlier 从 activation **数学等价地搬到 weight**。

$$
Y = (X \cdot \text{diag}(s)^{-1}) \cdot (\text{diag}(s) \cdot W) = \tilde X \tilde W
$$

按 channel 选 $s_j = \max(|X_{:,j}|)^\alpha / \max(|W_{j,:}|)^{1-\alpha}$，$\alpha=0.5$ 是平滑点。

> **结果**：activation 的 outlier 被吸收进 weight，两边都好量化 → W8A8 PTQ 落地。
>
> SmoothQuant 是 W8A8 路线的关键，但 W8A8 现在已被 **FP8 + Tensor Core** 大量替代（见 §四）。

### 3.4 选型速查

| 场景 | 选 |
|------|----|
| 单卡跑 70B / 单 4090 跑 13B | **AWQ W4A16**（精度好、kernel 成熟） |
| 已有 GPTQ checkpoint 生态 | GPTQ |
| H100/H200/B200 上线推理 | **FP8（或 NVFP4）** ← 不走 INT 路线 |
| 训练侧降本 | FP8 训练（DeepSeek-V3 / Llama-4） |
| KV cache 是瓶颈 | KV INT8 / FP8 / 4-bit（见 §12.5） |

## 四、FP8 与 NVFP4：硬件原生派

### 4.1 FP8 的两种格式

H100 Tensor Core 支持两种 FP8：

| 格式 | 表示 | 动态范围 | 精度 | 主要用途 |
|------|------|----------|------|----------|
| **E4M3** | 1 sign + 4 exp + 3 mantissa | ~±448 | 高 | weight、activation forward |
| **E5M2** | 1 sign + 5 exp + 2 mantissa | ~±57344 | 低 | gradient backward |

**Per-tensor scaling**：每张量一个 FP32 scale，使用前 dequant 再算（H100 Tensor Core 原生支持 fused scale）。

**Per-token / per-channel scaling**：DeepSeek-V3 用的细粒度版本，weight 按 1×128 块、activation 按 128×1 块各自 scale，精度显著优于 per-tensor。

### 4.2 FP8 vs INT8

| | FP8 | INT8 |
|---|---|---|
| 表达范围 | exp 给的动态范围大 | 线性、需精细 scale |
| outlier 容忍 | 好（指数自动适应） | 差（需 SmoothQuant 等技巧） |
| Tensor Core 吞吐 | H100 = 2× FP16 | A100/H100 都有 |
| 训练可用 | **是**（FP8 训练 2024 主流） | 仅 QAT |

> FP8 出现以后，W8A8 INT 路线在新硬件上很大程度退场。

### 4.3 NVFP4（Blackwell, 2025）

B200 / GB200 引入更激进的 **NVFP4（FP4 E2M1）**：

- 每 16 个元素一组的 micro-scale（E4M3）+ 整体 per-tensor scale（FP32）
- 双层 scale 抵消 4-bit 表达范围窄的问题
- B200 上 NVFP4 Tensor Core 算力 = 2× FP8 = 4× FP16
- TensorRT-LLM、vLLM 已支持 NVFP4 inference；Llama-4 / DeepSeek 后续模型已发布 NVFP4 weight

```
精度演化路线：
  V100 → FP16
  A100 → BF16 + INT8
  H100 → FP8 (E4M3/E5M2)
  B200 → NVFP4（双层 scale 的 FP4）
```

### 4.4 FP8 训练（QAT 雏形）

**DeepSeek-V3** (2024-12) 是首个公开的全 FP8 大规模预训练：

- 主权重、梯度、优化器 state 用更高精度
- forward / backward 的 GEMM 走 FP8
- **细粒度 scaling**：1×128 weight tile + 128×1 activation tile，每块独立 scale
- 关键 dot product 用 **CUDA core FP32 累加**而不是 Tensor Core 默认的 FP22 累加 → 防止精度漂移

工程效果：训练吞吐 1.5–2× BF16，精度对齐 BF16 baseline。

## 五、KV Cache 量化（衔接 §12.5）

KV cache 是 long-context decode 的**第一显存大户**：

$$
\text{KV bytes} = 2 \cdot L \cdot H_{kv} \cdot d_h \cdot T \cdot \text{bytes/elem}
$$

例：Llama-3-70B（L=80, H_kv=8, d_h=128），1 万 token：
- FP16：80 × 8 × 128 × 10000 × 2 × 2 ≈ **3.3 GB / sequence**
- KV INT8：1.6 GB
- KV INT4：0.8 GB

主流方案：
- **KIVI**（NeurIPS 2024）：K per-channel + V per-token 的 2-bit 量化
- **GEAR**：K/V 残差量化
- **vLLM / TensorRT-LLM** 都支持 **KV FP8**（最稳）

> KV 量化与 weight 量化正交，可叠加。

## 六、量化端到端流程示意

```
[Weight] -- PTQ (GPTQ / AWQ) --→ INT4 weight + scales + zeros
                                       │
[Calibration set ~512 samples] -------┘
                                       │
[Runtime]                              ▼
  X (FP16)
   ├── (optional: per-token scale)
   ▼
  GEMM kernel (AWQ Marlin / TRT-LLM cutlass)
   ├── load INT4 weight
   ├── dequant on-the-fly to FP16
   ├── multiply X (FP16)
   ▼
  Y (FP16)
```

**Marlin / Cutlass kernel** 把 dequant 和 GEMM fuse 在 SM 内，避免 dequant→HBM→load 的额外 round trip——这是 W4A16 推理快的工程关键。

## 七、量化的常见坑 & 调参经验

### 7.1 精度崩塌的征兆

- MMLU 掉 > 2pt → 必须排查
- 数学 / 代码任务对量化更敏感（链式依赖长）
- 长上下文场景下，量化误差会沿 KV cache 累积

### 7.2 调参经验

| 调节点 | 推荐 |
|--------|------|
| group size | 128（甜点）；32 给安全裕度 |
| calibration set | 来自目标 domain 的 256–1024 条；与训练分布一致 |
| salient channel ratio (AWQ) | 0.1% –1% 之间搜 |
| α (SmoothQuant) | 0.5；activation 极尖锐时 0.75 |
| KV 量化 | 先 FP8，不够再 INT8 |
| 任务回测 | MMLU + GSM8K + HumanEval + 长上下文 needle |

### 7.3 不要"硬量化"的层

```
embedding         → 信息密度高，量化损失大；保留 FP16
最后一层 lm_head  → 输出 logits 对精度敏感；保留 FP16
LayerNorm/RMSNorm → 仅几个 scale，无需量化
```

## 八、关键问答

**Q1：W4A16 为什么经常比 W8A8 快？**
A：decode 是 **memory-bound**，bandwidth 是瓶颈，W4 让 weight 大小减半 → 等同 2× 带宽；而 W8A8 节省的算力在 decode 阶段并不是瓶颈。所以 W4A16 在 decode 几乎总比 W8A8 快。在 prefill 大 batch 阶段 W8A8 才有优势。

**Q2：AWQ 与 GPTQ 同样是 W4A16，为什么 AWQ 在工程上更流行？**
A：（1）AWQ 不依赖二阶 Hessian 信息，calibration 更稳；（2）AWQ 的 Marlin kernel 是事实最快的 W4 GEMM kernel；（3）AWQ INT4 精度通常略优于 GPTQ；（4）vLLM/TRT-LLM 默认推 AWQ。

**Q3：SmoothQuant 现在还有用吗？**
A：在 H100 之前的硬件（A100、消费卡）做 W8A8 还有意义。H100+ 上有 FP8 Tensor Core 后，SmoothQuant 大多被 FP8 替代——但 SmoothQuant 的思想（**搬运 outlier 到 weight 端**）仍贯穿后续工作（OmniQuant、QServe 等）。

**Q4：FP8 训练为什么需要细粒度 scaling？**
A：FP8 动态范围远小于 BF16；全张量一个 scale 在不同 channel/token 上误差差距巨大。DeepSeek-V3 的 1×128 weight tile + 128×1 activation tile + FP32 累加，把 outlier 误差限制在 tile 内，全局训练才稳定。

**Q5：NVFP4 比 FP8 又激进一倍，怎么避免崩？**
A：**双层 scale**——每 16 个元素一组的 micro-scale（FP8 E4M3）+ 整体 tensor scale（FP32）。等价于给 FP4 强行加上一个动态的"伪指数位"。硬件原生支持，软件层无需 fake quant。

**Q6：KV cache 量化和 weight 量化能叠加吗？**
A：**可以**，两者正交。一个典型生产配置：**weight INT4 / FP8 + KV FP8 + activation FP16/BF16**。叠加后显存压缩比 4–6×。注意叠加后必须重测长上下文质量（KV 量化误差会累积）。

**Q7：为什么 lm_head 与 embedding 通常不量化？**
A：（1）embedding 是非稠密查表，bandwidth 影响有限；（2）lm_head 输出 logits 决定采样分布，任何精度损失会被 softmax 放大；（3）这两层的 FLOPs 相对小，量化收益不大。

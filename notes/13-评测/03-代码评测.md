# 13.3 代码评测（HumanEval / MBPP / LiveCodeBench / SWE-bench）

[← 返回框架](../../README.md) · [📎 materials.md → §13.3](../../materials.md)

---

## 〇、本节回答什么

> 代码评测的核心优势：**执行即验证**——比数学答案匹配更干净。但本节的核心 narrative 是：
>
> 评测重心已从 **函数级 (HumanEval, MBPP)** → **比赛级 (LiveCodeBench)** → **仓库级 + agent (SWE-bench Verified)** 迁移。2025 年面试问"你模型代码能力多强"，应该报 SWE-bench Verified + LiveCodeBench，而**不是 HumanEval**。

---

## 一、难度梯度

```
HumanEval           164 道 function-level     pass@1            饱和（>90）
MBPP                974 道 function-level     pass@1            饱和（>85）
LiveCodeBench       LeetCode-like，月更         pass@1 + contam   抗污染主流
SWE-bench           真实 GitHub issue 修复     resolved rate     2024 主战场
SWE-bench Verified  OpenAI 人工核 500 题       resolved rate     2025 主战场
SWE-bench Multilingual / Multimodal           扩展中
PolyglotBench / Aider Polyglot                多语言代码编辑
```

## 二、HumanEval（Chen et al., 2021） — 函数级 OG

### 2.1 设计

- **164 道**手写 Python 函数题
- 输入：函数签名 + docstring（描述需求）
- 输出：函数体实现
- 评测：跑预设单元测试 → **pass@k**

```python
def has_close_elements(numbers: List[float], threshold: float) -> bool:
    """Check if in given list of numbers, are any two numbers closer
    to each other than given threshold.
    >>> has_close_elements([1.0, 2.0, 3.0], 0.5)
    False
    >>> has_close_elements([1.0, 2.8, 3.0, 4.0, 5.0, 2.0], 0.3)
    True
    """
    # 模型补全
```

### 2.2 pass@k 公式

```
pass@k = E[ 1 - C(n-c, k) / C(n, k) ]
```

- n: 采样次数
- c: 通过的样本数
- k: 报数所选 top-k
- 含义：从 n 次采样里随机抽 k 次，至少一次通过的概率

**实操**：n=200, k∈{1, 10, 100}。论文里 Codex 报的 `pass@1 / pass@10 / pass@100`。

### 2.3 现状

```
Codex (2021):          28.8
GPT-4 (2023):          67.0
Claude 3.5 Sonnet:     92.0
DeepSeek-V3:           82.6（HumanEval+）
o1:                    92.4
SOTA 2025:             >95 已饱和
```

### 2.4 HumanEval+ (EvalPlus, 2023)

- 痛点：原 HumanEval 每题只有 7–10 个测例 → 弱测试用例容易"假阳性"
- HumanEval+ 自动生成 **80×** 测例（基于 mutation + LLM 生成）
- 让分数降 5–15 点

### 2.5 为什么 HumanEval 不再可信

1. **题目已大量污染**（2021 公开，所有现代 LM 训练数据都含）
2. **饱和**：>90 后区分度低
3. **函数级 ≠ 工程能力**：一个 30 行函数 vs 一个 cross-file refactor 完全两件事

→ 旗舰模型已**不报** HumanEval；只在小模型 / 量化 / 蒸馏 ablation 还有用。

## 三、MBPP / MBPP+（Austin et al., 2021）

### 3.1 设计

- **974 道**基础 Python 题（"小学到中学"难度）
- 每题：自然语言描述 + 3 个测例
- 评测：execution-based
- 默认 **3-shot**

### 3.2 现状

```
GPT-4:                  76
Claude 3.5 Sonnet:      89
DeepSeek-V3:            89
SOTA 2025:              >90 饱和
```

### 3.3 MBPP+

同 HumanEval+，加测例，分数下降 5–10 点。

→ MBPP 也是函数级，已不是主流报数。

---

## 四、LiveCodeBench（Jain et al., NeurIPS 2024）

### 4.1 设计动机

- HumanEval / MBPP 污染严重
- 需要**每月新增 + 时间戳**的题
- 来自 **LeetCode / AtCoder / CodeForces**

### 4.2 设计

- 题目按**发布日期**索引
- 评测模型时，只用 **训练 cutoff 之后**的题 → 完全抗污染
- 4 个子任务：
  1. **Code Generation**（从题面生成代码）
  2. **Self-Repair**（给一个错代码 + 错误信息，让模型修）
  3. **Code Execution**（让模型预测程序输出）
  4. **Test Output Prediction**（给代码+输入预测输出）

### 4.3 报数

- 报某个时间窗口内的 pass@1
- 现在主流报 `2024-08 → 2025-02`（约 200 道）

```
GPT-4o:               39.5
Claude 3.5 Sonnet:    38.0
o1:                   63.4
o3-mini-high:         77
DeepSeek-R1:          65.9
QwQ-32B:              ~62
```

→ **LiveCodeBench 已成为 2024-2025 报数代码能力的事实标准**。

## 五、SWE-bench（Jimenez et al., ICLR 2024）

### 5.1 设计 — 真实工程题

- 收集 **12 个流行 Python 仓库**（Django, sympy, flask ...）的真实 GitHub issue
- 每个 task = `(issue 文本, repo 全量代码, 期望补丁)`
- 模型必须**修改多文件**让 hidden test suite 通过
- 默认评 **resolved rate**（通过 hidden test 的比例）

```
输入：
  - issue_text: GitHub Issue 描述
  - repo: 整个仓库（百万行级）
输出：
  - 一个 patch（.diff 文件）
评分：
  - 把 patch apply 到 repo → 跑 hidden test → 全过算 resolved
```

### 5.2 三个变体

| Variant | 题数 | 选自 | 用途 |
| --- | --- | --- | --- |
| **SWE-bench Full** | 2294 | 12 repos | 完整 |
| **SWE-bench Lite** | 300 | 子集 | 学术快速迭代 |
| **SWE-bench Verified** | **500** | 子集 + OpenAI 人工核 | **2025 事实标准** |

#### Verified 为什么主流

OpenAI 找软件工程师审了 1699 道，剔除：
- 测试不可靠 / flaky
- 测试与 issue 描述脱节
- issue 描述含答案泄漏
- 测试覆盖不充分

最终留 500 道**干净题**。

### 5.3 SOTA（2025）

```
SWE-bench Verified 排行（resolved %）：
- Claude 3.7 Sonnet + scaffolding:  ~70
- Claude 3.5 Sonnet + Agentless:     50.8
- o3 + agent:                        ~71
- OpenAI Codex（2025）:              ~75
- 开源 (Qwen2.5-Coder, R1) + scaffold: 30-50
- Agentless 框架 + GPT-4o:           33.2
```

→ Agent + scaffolding 框架贡献巨大，**模型本身**通常 +20–30 点。

### 5.4 评测协议

```
1. 给模型：issue + repo （多种喂法）
2. 模型输出：unified diff
3. Harness:
   a. cd 到该 repo 的 base commit
   b. apply patch
   c. run hidden test
   d. log result
```

**喂仓库的方式**决定差距：
- **Full repo** 喂（百万 token，几乎不可能）
- **Retrieved files** 喂（BM25 / embedding 检索 top-k）
- **Agent navigate**（让模型主动 ls / grep / read）→ SWE-agent / OpenHands / Aider
- **Agentless**（rule-based + chain 的简化框架）

### 5.5 SWE-bench Multimodal / Multilingual

- 2024-12 **SWE-bench Multimodal**：加入需要看截图的 issue
- 2025 **SWE-bench Multilingual**：扩展到 9 种语言（Go / JS / Java...）

## 六、其他重要 benchmark

### 6.1 BigCodeBench（HuggingFace, 2024）

- HumanEval 升级版
- 题目用真实第三方库（numpy / pandas / matplotlib...）
- 1140 道
- 难点：模型要正确**调用 API**

### 6.2 Aider Polyglot Benchmark

- Aider 的官方 benchmark
- **多语言代码编辑**：把一个 buggy 函数改成对的
- 覆盖 6 种语言（Python / JS / Go / Rust / Java / C++）
- 测的是**编辑能力**（diff 格式生成）

### 6.3 RepoBench / CrossCodeEval

- repo-level code completion（不是修 bug，是补全多文件项目）

### 6.4 CodeContests / APPS

- 老 benchmark：CodeContests = CodeForces，APPS = LeetCode 风格
- LiveCodeBench 出现后基本退场

### 6.5 PolyglotBench / CRUXEval

- CRUXEval：execution reasoning（给代码预测输出 / 给输出预测输入）
- PolyglotBench：跨语言

## 七、Agent scaffolding（agent harness 三大流派）

### 7.1 SWE-agent (Princeton, 2024)

- 给模型一个**简化 shell**（ls/cd/cat/edit/test 几个命令）
- 让模型自己探索仓库
- **ACI**（Agent-Computer Interface）：精心设计的工具集

### 7.2 OpenHands（前 OpenDevin, 2024）

- 更通用的 agent 框架
- 支持 bash / python / browser
- 多 agent role 协作

### 7.3 Agentless（PSU, 2024-07）

- 反 agent 流派：不让模型自由探索
- 简单 3 阶段 pipeline：
  1. **Localize**：哪些文件可能有问题
  2. **Repair**：生成 patch
  3. **Validate**：跑测试
- **结果反而比 agent 强**（在 SWE-bench Lite 上 50.8% vs SWE-agent 31%）
- 启示：**agent 的 token 浪费比想象大**，简化 scaffolding 反而高效

→ 2025 行业共识：**模型变强 → agent 框架可以简化**。

---

## 八、评测工程的几个坑

### 8.1 Test 泄漏

HumanEval / MBPP 在 web 上有大量解答，模型可能"记"住答案。LiveCodeBench / SWE-bench Verified 的设计正是为了避免。

### 8.2 Hidden test 不全

SWE-bench 早期被发现部分 hidden test 写得弱 → 错的 patch 也能 pass。
→ Verified 子集解决了这个问题。

### 8.3 Sandbox 安全

跑 SWE-bench 必须用 **Docker 沙箱**（模型可能生成 `rm -rf /` 之类）。
官方提供 docker-compose 的 swebench harness。

### 8.4 算力代价

SWE-bench Verified 500 道 × n 次 retry × agent loop（10-30 步）≈ **每模型几亿 token**。一次完整跑要数小时到数天。

### 8.5 报数对齐

| Benchmark | 默认 metric | 推荐 setting |
| --- | --- | --- |
| HumanEval / + | pass@1 | greedy |
| MBPP / + | pass@1 | greedy |
| LiveCodeBench | pass@1 | greedy, time-window 标注 |
| SWE-bench Verified | resolved % | 注明 scaffolding |
| Aider Polyglot | pass@1 (edit) | diff 输出 |

## 九、与 §11.5 / §12.6 的联动

- **§11.5 RLVR**：代码题 reward = `compile + run + test_pass`，与数学题一同构成 R1 / o1 训练的两大干净 reward
- **§12.6 TTS**：代码 self-repair（"看到错误信息自我修复"）是 test-time scaling 的天然场景
- **agent**：SWE-bench 是 agent 范式与 base model 能力**纠缠最深**的 benchmark

## 十、关键问答

**Q1：HumanEval 现在还报有意义吗？**
A：**旗舰模型不报**。只在三种场景还看：(1) 小模型基线 (2) 量化 / 蒸馏前后对比 (3) 论文向前兼容。报数请加 HumanEval+ 升级版。

**Q2：LiveCodeBench 比 HumanEval 强在哪？**
A：(1) **时间戳**抗污染 (2) 测例丰富 (3) 包含 self-repair / execution / test prediction 四类子任务 (4) 题目难度真实（LeetCode 中-难）。但有一个软肋：仍是**函数级**，未覆盖工程能力。

**Q3：SWE-bench Verified vs Lite 选哪个报数？**
A：**Verified**。Lite 是早期学术用，Verified 是 OpenAI 人工核过的干净 500 道，2025 几乎所有顶级 lab 都报 Verified。Lite 已退场。

**Q4：Agentless 为什么比 SWE-agent 还强？**
A：(1) agent 自由探索浪费 token，分母大反而出错率高 (2) Localize + Repair + Validate 三步是**人写 patch 的核心流程**，固化进 pipeline 反而稳 (3) 模型够强时 scaffolding 简化更鲁棒。但 agent 路径**潜力更高**，2025 Claude 3.7 + agent 仍是 SOTA。

**Q5：SWE-bench 评测能不能在自己机器上跑？**
A：可以但贵。需要：
- 24+ 核 CPU（每个 task 起 docker container）
- 32GB+ RAM
- 500GB+ 磁盘（缓存所有 repo + 镜像）
- 一次 Full SWE-bench 跑可能 24-72 小时

→ 推荐云上（aws/lambdalabs）跑，或用 OpenAI / Anthropic 的官方 score。

**Q6：怎么衡量"代码 agent 工程能力"？**
A：组合 benchmark：
- **SWE-bench Verified**：跨文件修 bug
- **Aider Polyglot**：多语言编辑
- **BigCodeBench**：库调用
- **LiveCodeBench**：算法
- **τ-bench**：tool use

任一单项都不能代表"工程能力"。

**Q7：代码 RL 训练为什么用 LeetCode 风格题不用 SWE-bench？**
A：(1) LeetCode 题 reward 周期短（compile + 测试 <1s），适合 RL 的高频反馈 (2) SWE-bench 每个 task 跑测试 1-5 分钟，RL 训不动 (3) LeetCode 题数量大、答案唯一 → DeepSeek-R1 / Qwen2.5-Coder 都用类似数据集。SWE-bench 主要做**最终评测**而非训练 reward。

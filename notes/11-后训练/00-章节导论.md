第 11 章 7 个小节单独读都自洽，但**串起来读**容易感觉跳跃——一会儿 PPO clip、一会儿 LoRA r/α、一会儿又回到 GRPO group baseline。问题不在每节本身，而在**整章的脉络**：

> **后训练不是一条单向线，而是"算法主线 + 两条正交话题"组成的三轴**。

本节给出这张地图，让你在打开任何一节时都知道**自己站在哪、来自哪、要去哪**。

## 一、一张全景图

```
            ┌─────────────────────────────────────────────┐
            │     算法主线：SFT → PPO → DPO → GRPO → Agent │
            │     (减法演化 + 复杂度递减的训练范式)         │
            └────────────┬────────────────────────────────┘
                         │
                         │  ↕ 任一阶段都可叠加
                         │
         ┌───────────────┴────────────────┐
         │                                │
   正交话题 A                       正交话题 B
   §11.2 PEFT                       §11.7 CAI / RLAIF
   "怎么用更少显存训"               "训练数据从哪来"
   (LoRA / QLoRA / DoRA …)         (人类标 vs AI judge 标)
```

**主线**是"训什么 + 怎么训"的演化轨迹；**两条正交话题**是"工程效率"和"数据来源"——它们和主线**可任意组合**：SFT 可以是 full FT 或 LoRA，DPO 数据可以来自人也可以来自 GPT-4 judge，GRPO 既可以 full 训也可以 LoRA 训。

理解这个结构后，每一节的位置就不再扁平。

## 二、算法主线的"减法故事"

这条主线不是 5 个互不相干的算法，而是一条**层层做减法**的演化链——每一步去掉前一步的一个工程负担，但保留它的核心数学骨架。

```
SFT (§11.1)
    给问题 + 给完美答案
    损失 = 条件 MLE，1 个模型
    ↓ 缺：只能学示范，学不到"A 比 B 好"的比较信号
       
PPO (§11.3, "母算法")
    learned RM 把比较信号转成 reward
    + on-policy RL 在 reward 上爬山
    + KL anchor 防 reward hacking
    损失 = clipped surrogate，4 个模型（actor + critic + ref + RM）
    ↓ 缺：4 模型 + on-policy rollout 工程极重

DPO (§11.4, "offline 简化")
    用 KL-regularized 最优策略的闭式解
    直接把偏好概率写成一个 BCE-like loss
    损失 = log σ(β · log-ratio 差)，2 个模型（policy + ref）
    去掉了：RM、critic、PPO rollout 循环
    ↓ 缺：offline 限制；通用 chat 够用，reasoning 上限不足

GRPO / RLVR (§11.5, "去 critic + verifiable reward")
    保留 PPO 的 on-policy + clip 骨架，但
    用 group baseline 替 critic（4→3 模型）
    用 verifiable reward 替 learned RM（3→2 模型）
    损失 = PPO-clip + group-relative advantage + KL
    ↓ 缺：仍是单轮设定

Agentic RL (§11.6, "多轮 + 长 horizon")
    把 GRPO 套在多轮 trajectory 上
    + observation token mask（环境给的不算 loss）
    + dense process reward 处理长 horizon credit assignment
    + 环境/沙盒 + verifier 三层基础设施
```

**关键观察**：

- 模型数量从 **4 → 3 → 2**，但每一步**核心数学**（policy gradient + 比较信号 + KL 锚定）**没变**；
- Reward 来源从 **learned RM → 偏好对的隐式 RM → 程序化 verifier**，一步比一步刚性；
- DPO 是 PPO 的 **offline 简化**，GRPO 是 PPO 的 **critic 减法 + verifiable reward**——**DPO 和 GRPO 不是同一支路的演化**，而是 PPO 的**两条相互正交的简化路径**。

```
            PPO (4 模型)
               │
       ┌───────┴────────┐
       │                │
   offline 简化      去 critic + verifiable
       │                │
      DPO             GRPO
   (适配 chat)       (适配 reasoning)
```

→ 工业上"先 DPO 做 chat，再 GRPO 做 reasoning"是把这两条支路**串行使用**：每条解决一个问题域，互不替代。

## 三、两条正交话题为什么放章末

### 3.1 §11.2 PEFT：显存效率轴

PEFT 全家桶（LoRA / QLoRA / DoRA / LongLoRA / S-LoRA / ...）的本质：**冻结 base + 训一个低秩增量**——它和"训什么阶段"无关，可以叠加在 SFT、DPO、PPO、GRPO 任意阶段上。

- **SFT + LoRA** = 中小团队的 SFT 起手式（QLoRA 单卡训 70B）；
- **DPO + LoRA** = Zephyr-7B、TÜLU 的开源对齐路径；
- **GRPO + LoRA** = 显存紧张时跑 reasoning RL 的方案；
- **Multi-LoRA serving** = 一份 base + N 份 adapter 在生产环境 hot-swap。

正因为它"哪都能用"，所以**不属于算法主线的某个节点**。它的本质是"训练阶段的工程效率优化"，和混合精度（§10.2）、显存四块（§10.3）是同一类话题。

→ 阅读路径：**读完主线某一节后，需要做的时候回到 §11.2 找对应配方**。

### 3.2 §11.7 Constitutional AI / RLAIF：数据来源轴

CAI / RLAIF 的本质：**用 LLM 当 annotator 替代/补充人类标注**——它解决的是"DPO/PPO/GRPO 训练所需的偏好数据从哪来"，**不替换任何 RL 算法**。

- **PPO + RLAIF**：Google 2023 的 RLAIF 原始论文路径；
- **DPO + RLAIF**：UltraFeedback、Magpie-DPO、Tülu-3 路径；
- **GRPO + RLAIF judge**：reasoning 任务中通用 chat 部分仍需 LLM judge；
- **Constitutional AI**：在 SFT 阶段用 self-critique + self-revision 产生数据，在 RL 阶段用原则做 judge。

正因为它"在所有阶段都可以替换数据来源"，所以也**不属于算法主线的某个节点**。它是"alignment 数据规模化"的工程范式，和 §11.2 类比意义上同属正交话题。

→ 阅读路径：**先读主线了解每个算法吃什么数据，再读 §11.7 了解这些数据怎么自动产生**。

## 四、后训练在更大的全景中的位置

```
[第 1-2 章] 数据 + Transformer 架构
[第 3-9 章] 架构变体（KV cache / 注意力 / SSM / MoE / 长上下文）
[第 10 章]  预训练：parallel + 显存 + 蒸馏
    ↓ 得到 base model（next-token predictor）
[第 11 章]  后训练（本章）
    ↓ 得到 chat / reasoning / agentic model
[第 12 章]  推理优化（量化、speculative decoding、serving）
[第 13 章]  评测
[第 14 章]  面试考点
```

**与上下游章节的接力**：

- **来自 §10.5 知识蒸馏**：base model + 大模型 RL trajectory 蒸馏到小模型（R1-Distill 范式 → §11.5 §八）；
- **来自 §10.3 显存四块 / §10.2 混合精度**：§11.2 PEFT 的"显存账"直接继承（4 块 × 16 bytes/param 的 BF16 mixed-precision 公式）；
- **来自 §8 长上下文**：§11.6 Agentic 的长 trajectory 训练直接吃 long-context 能力；
- **下接 §12 推理优化**：reasoning 模型的 long CoT 让 KV cache（§12.4）、test-time scaling（§12.6）成为部署关键；
- **下接 §13 评测**：每节末尾提到的 IFEval / MT-Bench / AlpacaEval / AIME / SWE-Bench 都在 §13 集中展开。

## 七、2026 工业标准 pipeline（速查）

```
base model (来自 §10)
    ↓
SFT (§11.1)         ─── 教格式 + 激发能力（不灌新知识）
[可选 §11.2 PEFT 节省显存]
    ↓
DPO / Iterative DPO (§11.4) ──── ← RLAIF 提供偏好数据（§11.7）
    ↓
RLVR / GRPO (§11.5) ─── reasoning 强化（verifiable reward）
    ↓
[可选] Agentic RL (§11.6) ─── 多轮工具 + 长 horizon
    ↓
[可选] 推理蒸馏（§10.5 + §11.5）大模型 → 小模型
    ↓
部署（§12 推理优化 / §13 评测）
```

**几个值得记的趋势（websearch 印证）**：

1. **DPO 取代 PPO** 成为开源偏好对齐主流（PPO 仍是大厂内部主力）；
2. **GRPO 取代 PPO** 成为 reasoning RL 主流（DeepSeek-R1 之后）；
3. **RLAIF 取代纯 RLHF** 成为数据来源主流（成本与速度优势压倒一切）；
4. **Reasoning model 取代纯 chat model** 成为主流（o1/R1 之后）；
5. **Agent 训练正在成为下一个主战场**（2026+）。

## 八、与本章无关但易混的话题

读完导论后，几条边界要明确：

| 看似在后训练，实际在别处 | 实际章节 |
|---|---|
| 灌新事实/新知识 | §10.1 continued pretraining（**不是** SFT） |
| 推理时 best-of-N、self-consistency | §12.6 test-time scaling |
| Speculative decoding、量化部署 | §12.1 / §12.3 |
| 长上下文位置编码 | §8 长上下文 |
| 蒸馏算法本身（loss / 温度） | §10.5 知识蒸馏 |
| 评测细节（IFEval / MT-Bench / AIME） | §13 评测 |

→ 后训练章节**只讨论"怎么改模型权重让它对齐"**，不讨论"推理时怎么更聪明"和"训完后怎么评测"。

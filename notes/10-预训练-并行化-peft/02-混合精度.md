## 〇、本节回答什么

> 训练/推理时不同算子用什么精度？为什么 BF16 取代 FP16？FP8 / FP4 在 2024-2025 是怎么实战落地的？

低精度的本质：**用比特换算力 + 带宽 + 显存**，但要付出"数值范围 / 精度损失"代价。工程关键是搞清"哪些环节能掉精度、哪些必须保留高精度"。

---

## 一、浮点数基本概念

IEEE 754 浮点 = `sign · 2^exponent · (1 + mantissa)`

| 格式 | total bits | exp bits | mantissa bits | 动态范围 | 精度 (eps) |
|------|-----------|----------|---------------|---------|----------|
| FP32 | 32 | 8 | 23 | ~10^±38 | 1.2e-7 |
| TF32 | 19* | 8 | 10 | ~10^±38 | 1e-3 |
| **BF16** | 16 | **8** | 7 | ~10^±38 | 8e-3 |
| **FP16** | 16 | 5 | **10** | ~10^±5 | 1e-3 |
| **FP8 E4M3** | 8 | 4 | 3 | ~10^±2 | 0.125 |
| **FP8 E5M2** | 8 | 5 | 2 | ~10^±5 | 0.25 |
| FP4 E2M1 | 4 | 2 | 1 | ~10^±1 | 0.5 |

*TF32 实际占 32-bit 存储，仅在 GEMM 中按 19-bit 计算。

```
关键认知：
  BF16: 「范围与 FP32 相同，精度差」    ← 训练友好（梯度小）
  FP16: 「范围小，精度比 BF16 高」      ← 早期使用，已被淘汰
  FP8 : 「范围又缩，需要 scale 缓存」
```

## 二、为什么 BF16 取代 FP16

### 2.1 FP16 的致命缺陷：**指数范围太窄**

FP16 最大值约 65504。训练中梯度容易 underflow（→ 0）或 overflow（→ Inf）。

经典方案 [**Loss Scaling**](https://arxiv.org/abs/1710.03740)（Apex / amp）：
```
forward:  loss * S          ← S 通常 2^16 ~ 2^24
backward: 梯度 ×S
更新前:   梯度 ÷S
```
工程上复杂 + 经常 spike → BF16 出来后被快速淘汰。

### 2.2 BF16 的好处

- 指数 8-bit 与 FP32 一致 → 没有 overflow 问题，**不需要 loss scaling**
- 精度比 FP16 差（mantissa 7 vs 10），但**梯度噪声本身远大于此**
- A100 / H100 / TPU v3+ 都原生支持

→ 现代 LLM 训练 **统一用 BF16**。FP16 只在老显卡（V100、T4）上还出现。

## 三、Mixed Precision 训练的标准做法

```
weight:           BF16  (forward / backward 都用)
gradient:         BF16  (allreduce 也用 BF16，省一半带宽)
master weight:    FP32  (optimizer step 在 FP32 进行)
optimizer state:  FP32  (m, v)
activations:      BF16
loss:             FP32  (避免 reduce 累加误差)
norm 层:          FP32  ← 关键！
```

为什么 LayerNorm / RMSNorm 要 FP32？
- norm 内部要算 `mean / var`，对累加误差敏感
- BF16 mantissa 太少 → var 容易塌掉
- PyTorch autocast 默认把 LN 留在 FP32

### 3.1 显存占用对比

70B 模型（单卡）：

| 项 | FP32 训练 | BF16 mixed | 注 |
|----|---------|-----------|---|
| weight | 280 GB | 140 GB | bf16 weight 一份 |
| gradient | 280 GB | 140 GB | |
| optimizer m | 280 GB | 280 GB | FP32 |
| optimizer v | 280 GB | 280 GB | FP32 |
| **fp32 master weight** | — | 280 GB | |
| 合计 (per param) | 16 B | **18 B** | bf16 mixed 反而多 |
| activations | 视 batch/seq | 视 batch/seq | bf16 减半 |

→ BF16 mixed 主要**省 activation 显存**和**加快算子**，而不是省 optimizer state（被 ZeRO/FSDP 解决，见 §10.3）。

## 四、FP8 训练（2024 的工业突破）

[**Transformer Engine** (NVIDIA)](https://github.com/NVIDIA/TransformerEngine) + H100 / H200 / B200 硬件支持。

### 4.1 H100 FP8 双格式

- **E4M3**：精度高范围窄 → 用于 **forward**
- **E5M2**：范围广精度低 → 用于 **backward gradient**

```
forward:    weight (e4m3) @ act (e4m3) → out (bf16)
backward:   d_act (e5m2) @ weight^T (e4m3) → d_x (bf16)
```

### 4.2 Per-Tensor Scale

FP8 范围太窄，每个 tensor 必须配一个 `scale`：

$$
x_{fp8} = \mathrm{cast\_fp8}\!\left(\frac{x_{bf16}}{s}\right), \quad s = \frac{\max|x|}{\text{fp8\_max}}
$$

每步动态更新 scale，叫 **delayed scaling**（用上一步的统计估计当前 scale，免一次 reduce）。

### 4.3 FP8 训练带来的收益

- **吞吐 ↑ 1.8-2× vs BF16**（H100 实测）
- 显存 activation 减半
- All-reduce 流量减半

### 4.4 实战案例

- [DeepSeek-V3](https://arxiv.org/abs/2412.19437)：**业界首个完整 FP8 训练的 SOTA 大模型**。论文专门一章谈 FP8 工程：fine-grained scaling、accumulator 精度提升、E4M3 全程使用
- Llama-3：FP8 微调（pretrain 仍 BF16）
- Mistral / Qwen：FP8 训练在 2025 普及

### 4.5 FP8 的坑

1. **Outlier 让 scale 算坏** → DeepSeek-V3 用更细粒度（per-128-channel scaling）
2. **Accumulator 精度** → FMA 累加必须用 FP32 累加，否则容易 NaN
3. **Loss spike 比 BF16 多** → 需要更激进的 grad clip
4. **支持矩阵**：H100 / B100 / B200，A100 不支持 FP8

## 五、FP4 / INT4（推理为主）

### 5.1 推理量化

```
压缩链:  BF16  →  INT8 / FP8  →  INT4 / FP4  →  binary (1-bit)
                  (W8A8)         (W4A16/W4A8)
```

> 训练用低精度 = 加速；**推理量化 = 省显存 + 提高吞吐 + 降低延迟**。

详见 §12 推理优化。

### 5.2 FP4 训练（2025 新前沿）

[**NVIDIA NVFP4 (2024)**](https://blogs.nvidia.com/blog/blackwell-fp4-architecture/) / [Microsoft FP4 training (2024)](https://arxiv.org/abs/2310.10537)：

- B200 硬件支持 FP4 GEMM，理论吞吐 2× of FP8
- 训练要更精细的 block-wise scaling
- DeepSeek、Mistral 在 2025 探索
- 还不成熟，1-2 年内仍是研究为主

### 5.3 1-bit / BitNet（更激进）

[BitNet b1.58 (2024)](https://arxiv.org/abs/2402.17764)：weight 仅 {-1, 0, +1}，号称同质量。
- 学术热度高，工业仍观望
- 推理硬件还没专门优化 1-bit GEMM

## 六、不同算子的精度策略汇总

| 算子 | 精度 | 备注 |
|------|------|------|
| Linear / FFN | BF16 或 FP8 | hot path |
| Attention QK^T | BF16 / FP8 | FlashAttn 支持 FP8 |
| Softmax | FP32 内部 | exp 易溢出 |
| LayerNorm / RMSNorm | FP32 内部 | 见 §3 |
| Embedding | BF16 | 大表，BF16 即可 |
| Loss / Cross-Entropy | FP32 | reduce 累加 |
| Optimizer Step | FP32 master + FP32 m,v | 见 §3 |
| AllReduce (gradient) | BF16 / FP8 | 通信省带宽 |
| LM head | BF16 | 与 embedding 解耦时单独 |

## 七、关键问答

**Q1**：为什么 BF16 mixed 不省 optimizer state？
- 因为 optimizer 的 m, v 仍要 FP32（防止累加误差）
- master weight 也 FP32（更新精度）
- 所以 "BF16 mixed" 主要省 activation 和加速 GEMM
- 想真省 optimizer state → ZeRO Stage 1+ 或 FP8 optimizer (实验性)

**Q2**：FP8 训练目前稳定吗？
- 大厂内部：稳定可用（DeepSeek-V3 整个 pretrain 都用 FP8）
- 开源 framework：Megatron-LM、TE、ColossalAI 都已支持
- 注意点：H100+ 才行；细粒度 scaling 关键；activation FP8 比 weight FP8 风险更大

**Q3**：BF16 和 FP16 在推理上有差别吗？
- 推理：差异不大，但 BF16 已是默认
- FP16 主要在老硬件（V100）上还活着
- 2024+ 工业推理：BF16 → INT8 / FP8 → INT4

**Q4**：FP8 训练 + FP8 推理可以无缝吗？
- 不完全：训练 FP8 用 E4M3 + dynamic scale，推理 FP8 通常用 static scale + per-tensor
- 大厂正在合并这条 pipeline（TensorRT-LLM、SGLang 已部分支持）

**Q5**：为什么 norm 层一定要 FP32？
- LN/RMSNorm 中 var = E[x²] - E[x]²
- BF16 下 var 容易 cancellation 塌成 0 → 除 0 → NaN
- 把 mean/var 计算放 FP32 即可，存储仍 BF16

**Q6**：训练突然 NaN，是不是精度问题？
- 先排查：
  1. 数据有 NaN/Inf？
  2. softmax / log 输入溢出？
  3. grad clip 是否生效？
  4. mixed precision 配置（哪些算子 cast）？
- 试 BF16 → FP32 重训该 step 验证

**Q7**：1-bit 模型靠谱吗？
- BitNet 在 1-3B 上看起来 ok
- 70B+ 尚无可信 reproduce
- 硬件支持 1-bit GEMM 还没普及
- 2025 当前观望

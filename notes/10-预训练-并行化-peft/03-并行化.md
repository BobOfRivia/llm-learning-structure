# 10.3 并行化（DP / TP / PP / SP / EP / CP / ZeRO / FSDP）

[← 返回框架](../../README.md) · [📎 materials.md → §10.3](../../materials.md)

---

## 〇、本节回答什么

> 训练 70B+ 模型，单 GPU 显存（80-141 GB）远远不够。如何把模型 / 数据 / 计算切到几百甚至上万张 GPU 上？

七种并行维度，**正交可组合**：

| 维度 | 切什么 | 单位 |
|------|--------|------|
| DP (Data Parallel) | batch | 不同 GPU 不同样本 |
| TP (Tensor Parallel) | 矩阵 | 横/竖切权重 |
| PP (Pipeline Parallel) | 层 | layer 分组 |
| SP (Sequence Parallel) | seq | activation 沿 seq 维切 |
| EP (Expert Parallel) | expert | MoE 专属（§9.4） |
| CP (Context Parallel) | seq | 长 context 专用 |
| ZeRO / FSDP | optim state + param | DP 的精细化 |

实操：**5D-7D 并行**嵌套（DeepSeek-V3 用了 5D）。

---

## 一、Data Parallel (DP)

### 1.1 经典 DDP

```
GPU0:  weight_full + batch_chunk_0
GPU1:  weight_full + batch_chunk_1
GPU2:  weight_full + batch_chunk_2
...
backward 后 AllReduce(gradients)
```

通信：每 step 1 次 AllReduce 全部 gradient，**通信量 = 2(N-1)/N · |W|**（ring all-reduce）。

显存：每卡都有完整 weight + grad + optimizer state → 大模型存不下。

→ 故而引入 ZeRO / FSDP。

---

## 二、ZeRO（DeepSpeed）/ FSDP（PyTorch）

[ZeRO: Memory Optimizations Toward Training Trillion Parameter Models (Rajbhandari 2019)](https://arxiv.org/abs/1910.02054)

把"全部冗余存在每卡"的 DP 模式拆分：

| Stage | 切分什么 | 每卡显存 (per param) | 通信增量 |
|-------|---------|---------------------|---------|
| Baseline DDP | 都不切 | 16 B | AllReduce(grad) |
| **ZeRO-1** | optimizer state 分片 | 8 B + 4 B / N | 同 DDP |
| **ZeRO-2** | + grad 分片 | 4 B + 12 B / N | ReduceScatter + AllReduce |
| **ZeRO-3 = FSDP** | + param 分片 | 16 B / N | AllGather(param) × 2 + ReduceScatter(grad) |

（per param：bf16 weight 2B + bf16 grad 2B + fp32 master 4B + fp32 m 4B + fp32 v 4B = 16B）

### 2.1 ZeRO-3 / FSDP 关键流程

```
forward:    AllGather(param_shard) → 算 → 释放
backward:   AllGather(param_shard) → 算梯度 → ReduceScatter(grad)
update:     local optimizer step on shard
```

通信代价：**每个 layer 2 次 AllGather + 1 次 ReduceScatter**，比 DDP 通信量 × 1.5。

但显存几乎 = `total / N`，N=64 时单卡只需 1/64 的 state。

### 2.2 ZeRO-Offload / Infinity

- 把 optimizer state offload 到 CPU 内存
- 把 param 也 offload 到 NVMe（disk）
- 小集群训大模型用，**速度大幅下降**，仅 hobbyist 用

### 2.3 ZeRO 与 FSDP 区别

- **ZeRO**：DeepSpeed 实现，3 个 stage，配置灵活
- **FSDP**：PyTorch 官方，等价 ZeRO-3，集成更好（autograd hook），2024 主流
- 工业默认 FSDP，HF Accelerate / TorchTitan / Megatron-FSDP 都基于它

## 三、Tensor Parallel (TP)

[Megatron-LM (Shoeybi 2019)](https://arxiv.org/abs/1909.08053)

> 把单个矩阵乘法 W ∈ ℝ^(d×d) 横切或竖切，多卡同时算一部分。

### 3.1 FFN 的 TP 切法

$$
Y = \text{GeLU}(XW_1)W_2
$$

- $W_1 \in \mathbb{R}^{d \times 4d}$ → **按列切** $[W_1^{(1)}, W_1^{(2)}]$
- $W_2 \in \mathbb{R}^{4d \times d}$ → **按行切** $[W_2^{(1)}; W_2^{(2)}]$

```
                    AllReduce
X ─┬─→ GPU0: X·W1^(1) → GeLU → ·W2^(1) ─┐
   │                                     ├─→ Y
   └─→ GPU1: X·W1^(2) → GeLU → ·W2^(2) ─┘
```

每 transformer block **2 次 AllReduce**（一次 attention 后、一次 FFN 后）。

### 3.2 Attention 的 TP 切法

按 head 切：每张 GPU 负责 N/TP 个 head，最后输出投影也按行切。

### 3.3 TP 通信特性

- 通信粒度：layer 内（fine-grained），**必须 NVLink 级别**才不卡
- 工业：TP ≤ 8（单机 8 卡 NVLink）
- TP > 8 跨机：通信极慢，几乎不用
- DeepSeek-V3 用 TP=1（用 EP 取代）

### 3.4 TP 与 SP（Sequence Parallel）

[Megatron-SP (Korthikanti 2022)](https://arxiv.org/abs/2205.05198)：

> TP 后 dropout/layernorm 之类的 elementwise 操作仍冗余，沿 sequence 维再切一刀。

- Activation 显存进一步减 / TP 倍
- 通信：AllReduce → AllGather + ReduceScatter（同总流量）
- 几乎是 TP 的"免费午餐"，工业默认开

## 四、Pipeline Parallel (PP)

> 把模型按 layer 切成 stage，stage 间用点对点通信传 activation。

### 4.1 朴素 PP 的 bubble

```
Stage 0: [F0] [F1] [F2] [F3]                    [B3] [B2] [B1] [B0]
Stage 1:      [F0] [F1] [F2] [F3]          [B3] [B2] [B1] [B0]
Stage 2:           [F0] [F1] [F2] [F3] [B3] [B2] [B1] [B0]
                                       ↑ bubble ↑
```

bubble 比例 = `(P-1) / (P + M - 1)`，P=stage 数，M=micro-batch 数。

→ 想缩小 bubble：**micro-batch 多**或用更精细的 schedule。

### 4.2 经典 schedule

| schedule | bubble | 备注 |
|---------|--------|------|
| GPipe (2018) | `(P-1)/M` | 朴素 F-then-B |
| **1F1B (PipeDream)** | `(P-1)/M` | 交替执行，act 显存减半 |
| **Interleaved 1F1B (Megatron)** | `(P-1)/(M·V)` | 每 stage 多 chunk |
| **Zero Bubble PP** (2024) | ~0 | 重排 backward |
| **DualPipe** (DeepSeek-V3 2024) | ~0 | 同时跑两个方向 |

### 4.3 PP 通信

- 每 stage 边界发 activation（forward）+ gradient（backward）
- 通信量小（仅 activation tensor），**跨机 InfiniBand 即可**
- 适合大模型纵向扩展（PP=8、16 常见）

### 4.4 PP 显存

- 每 stage 只存 1/P 模型 → 大模型必备
- 但要存 in-flight micro-batch activation → activation checkpointing 几乎必开

---

## 五、Expert Parallel (EP)

详见 §9.4。简述：

```
EP:  把 N 个 expert 分到 N/EP 卡上，每 token 通过 All-to-All 发送到目标 expert。
```

- 与 TP 互斥（不能既切 expert 又切 expert 内 GEMM，碎成粉）
- 与 DP / PP / SP 兼容
- DeepSeek-V3: EP=64 跨 8 节点

---

## 六、Context Parallel (CP)

> Sequence 过长（>128K），单卡 activation 都存不下。沿 seq 维度切。

类似 [**Ring Attention**](https://arxiv.org/abs/2310.01889) / [**Tree Attention**](https://arxiv.org/abs/2408.04093) / Llama-3 的 CP 实现：

```
GPU0: tokens[0:32k]   ─┐
GPU1: tokens[32k:64k] ─┤  →  循环 / tree 状交换 K,V 算 attention
GPU2: tokens[64k:96k] ─┤
GPU3: tokens[96k:128k]─┘
```

通信：每 step Q 不动，K/V 在 GPU 间 ring 传递（O(seq)）。

应用：
- Llama-3 训练 128K context 用 CP=8
- Gemini 1.5 / Kimi K2 等长 context 模型必备
- 推理时也可用（详见 §12）

详见 §8（长上下文章节）。

## 七、5D / 7D 并行的实战组合

### 7.1 DeepSeek-V3 配置（671B，2k+ H800）

```
DP = 32   (FSDP-like, ZeRO-1 仅 optim state 切)
TP = 1    (没用 TP, 因 EP 已足够分散显存)
PP = 16   (DualPipe schedule, near-zero bubble)
SP = 1    (与 TP 配对)
EP = 64   (MoE expert 切到 64 路)
CP = 1    (训练时 context 4K-128K，没必要)
ZeRO-1
```

总卡数 ≈ DP × PP × EP = 32 × 16 × 64 / overlap = ~2048

### 7.2 Llama-3.1 405B 配置

| 维度 | 值 |
|------|---|
| DP (FSDP) | 16 |
| TP | 8 (单机 8 卡 NVLink) |
| PP | 16 |
| CP | 8 (训 128K) |
| 总卡数 | 16,000+ H100 |

### 7.3 选型经验

```
单机 ≤ 8 卡:  DP + ZeRO-3 (FSDP) 就够
8-64 卡:      DP + TP=8 + ZeRO-1
64-512 卡:    DP + TP=8 + PP=4-8
512+ 卡:      DP + TP + PP + (EP / CP)
万卡:         5D-7D 全开
```

## 八、通信原语速查

| 原语 | 含义 | 用例 |
|------|------|------|
| **AllReduce** | 所有节点 reduce 后广播 | DDP grad、TP block 末 |
| **AllGather** | 所有节点拼到所有节点 | ZeRO-3 param 收集 |
| **ReduceScatter** | reduce 后只分片到各节点 | ZeRO grad 分片 |
| **All-to-All** | 转置式全交换 | EP dispatch / combine |
| **Send/Recv** | 点对点 | PP 边界 |
| **Broadcast** | 一对多 | 初始化 |

带宽硬件：
- **NVLink 4 / NVSwitch**：~900 GB/s（H100 within node）
- **InfiniBand HDR/NDR**：50-100 GB/s（跨节点）
- **以太网 RDMA**：25-100 GB/s

→ **TP 必须在 NVLink 内、PP 可跨 IB、DP/EP 跨 IB 也可**。

## 九、Activation Checkpointing（重要补充）

> 不存中间 activation，反向时 recompute。

```
forward:     存 layer 0, 5, 10, ...  (每 N 层一个 ckpt)
backward:    用最近 ckpt 重新 forward 拿到 activation，再 backward
```

- **显存减 ~5-10×**
- **算力多 ~30%**（多一次 forward）
- 工业训练必开。SP+ckpt+ZeRO 是显存三件套

Selective checkpointing：只 ckpt 算力小的层（norm/attention），不 ckpt 大算力 FFN —— 更优 trade-off。

## 十、关键问答

**Q1**：DP / TP / PP 哪个通信最贵？
- 单 step 通信量：DP ≈ TP（都 AllReduce）> PP（仅点对点）
- 单 step 通信频率：TP（每 layer 2 次） > PP（每 stage 边界） > DP（每 step 1 次）
- 经验：**TP 必须 NVLink，PP 可跨机，DP 跨机也可**

**Q2**：FSDP 与 ZeRO-3 完全等价吗？
- 数学上等价
- 实现：FSDP 集成 autograd 更紧，hook 更轻；DeepSpeed ZeRO 配置更灵活
- 2024+ 推荐 FSDP（PyTorch 官方，TorchTitan 默认）

**Q3**：DeepSeek-V3 为什么不用 TP？
- TP 通信粒度细 + 必须 NVLink 8 卡内
- 用 EP 已经分散显存
- TP=1 让单节点 8 卡都参与 DP / EP，集群利用率高
- 节省了 TP allreduce 流量

**Q4**：什么时候必须用 PP？
- 模型层数大（70B+ 30+ 层）+ 单 stage 显存放不下
- 跨节点扩展时，比起 TP 通信更友好
- PP 唯一缺点 = bubble，但有 DualPipe / Zero Bubble 缓解

**Q5**：activation checkpointing 必开吗？
- 长 context、大 batch、大模型 → 必开
- 短 context（< 2K）、小模型 → 可选关闭

**Q6**：为什么 Llama-3 用 TP=8 而 DeepSeek-V3 用 TP=1？
- Llama-3 是 dense → 没有 EP 这条切割维度 → 必须 TP+PP+CP 切显存
- DeepSeek-V3 是 MoE → EP 已经替代了大部分 TP 功能

**Q7**：训练 1B 模型还要并行吗？
- 1-3B：FSDP / ZeRO-3 单机 8 卡足够
- 7B：FSDP + activation ckpt，单机即可
- 13B-30B：FSDP + 多机
- 70B+：必须 PP + TP

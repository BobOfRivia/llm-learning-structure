# 7.4 架构选型判断（attention vs sparse vs linear vs SSM vs hybrid）

[← 返回框架](../../README.md) · [📎 materials.md → §7.4](../../materials.md)

---

## 〇、这一节回答什么

从 §5 到 §7 已经过完了 LLM 序列建模的所有主流路径。本节是**收束**：

> 给定一个具体场景（context 长度、质量要求、硬件预算、训练 vs 推理），到底该选哪个？

---

## 一、四象限地图

```
                  retrieval 强（含复杂 reasoning / 精确召回）
                            ▲
                            │
       Softmax + MLA        │     Softmax + MLA
       Sparse (NSA/MoBA)    │     Sparse (NSA/MoBA)
                            │
   ─────────────────────────┼─────────────────────────► context 长
                            │
       纯 Linear / RWKV     │     Hybrid (Jamba / MiniMax)
       纯 Mamba             │     Mamba + Attn (Nemotron-H)
                            │
                            ▼
                  retrieval 弱（侧重 throughput / 短-中任务）
```

**四个角的典型代表**：
- 左上（短+强）：Llama-3、Mistral、DeepSeek-V3（softmax + GQA/MLA）
- 右上（长+强）：DeepSeek-V3.2（MLA + DSA）、Kimi K2（MLA + MoBA + MoE）
- 左下（短+轻）：RWKV-7、纯 Mamba（端侧 / 嵌入式）
- 右下（长+轻）：Jamba、MiniMax-01、Nemotron-H

---

## 二、按"训练 / 推理"两阶段分别选

### 2.1 训练阶段

| 目标 | 推荐架构 | 理由 |
|------|---------|------|
| 通用预训练，质量优先，规模 ≤ 100B | **Softmax + GQA + RoPE** | 工程标配，所有 toolchain 都最熟 |
| 通用预训练 + 长 context 需求 | **Softmax + MLA + RoPE/YaRN** | MLA 让 KV 训练/推理都省 |
| MoE + 长 context 极致优化 | **MoE + MLA + Sparse Attn**（V3.2、Kimi K2 路线） | 三个正交轴叠满 |
| 中小规模（≤ 14B）+ 极致长 context | **Hybrid (Jamba / MiniMax style)** | KV 省得最猛，仍可用 |
| 端侧 / 边缘 / 实时性最优先 | **Pure Mamba / RWKV** | state 固定，推理极轻 |

### 2.2 推理阶段（如果模型已经训好）

| 模型已训为 | 推理优化主路径 |
|-----------|---------------|
| Softmax MHA | GQA shrinkage 蒸馏 → KV 量化 → PagedAttention |
| Softmax GQA | KV 量化 INT8 → PagedAttention → sliding window（短 task） |
| Softmax MLA | FlashMLA + INT8/FP8 → 已经够省 |
| Sparse-trained (NSA/MoBA) | 用对应官方 kernel，无需另外改 |
| Mamba / Hybrid | selective scan kernel + 标准 attention kernel 混合调度 |

## 三、按"context 长度"硬切

**$L \le 8k$（常规对话、代码补全）**：
- 用什么都行，softmax + GQA 是事实标准
- 别为了"未来可能长 context"提前付出复杂度

**$8k < L \le 32k$**：
- Softmax + GQA + RoPE 仍是 baseline
- 推理上叠 KV 量化即可

**$32k < L \le 128k$**：
- 强烈建议 **MLA** 或 **GQA + INT8 KV 量化**
- 推理引擎要支持 PagedAttention
- sparse attention（NSA/MoBA）开始有可观收益

**$128k < L \le 1M$**：
- **必须** sparse 或 hybrid
- 选型：DeepSeek 路线（MLA + DSA）or Kimi 路线（MLA + MoBA + MoE）or 混合架构路线（Jamba / Nemotron-H / MiniMax）
- 纯 softmax 即使有 MLA 也开始吃力

**$L > 1M$**：
- 当前公开 SOTA：MiniMax-01、Kimi K2、Gemini 1.5 Pro
- 都是 hybrid 或 sparse-attention 路线
- 评测体系仍在演化（RULER、∞Bench、HELMET），单纯能"读完" ≠ 真能用

---

## 四、按"任务类型"对偶

| 任务类型 | 关键诉求 | 推荐 |
|---------|---------|------|
| **代码生成**（≤ 64k） | retrieval 精确性 + 局部依赖强 | Softmax + GQA + sliding window 混合 |
| **长文档 QA / RAG** | 长 context retrieval 优先 | Softmax + MLA（精度），或 hybrid（成本） |
| **小说续写 / 长对话** | 流式生成 + KV 不爆 | Streaming-LLM + sink + window，或 hybrid |
| **agentic / tool-use** | 复杂 reasoning + 多轮 | Softmax + MoE，避免纯线性 |
| **embedding / retrieval encoder** | 通常 ≤ 8k | 任何 baseline 都行，差异极小 |
| **端侧 LLM**（手机、边缘） | 内存极受限 | RWKV / Mamba（state 小），或 quantized hybrid |

---

## 五、按"硬件 / 预算"

| 硬件 | 限制点 | 推荐 |
|------|--------|------|
| 单卡 24GB 消费级（4090） | KV 显存 | Mistral 风格（GQA + sliding window），≤ 7B 模型 |
| 单卡 80GB（A100/H100） | KV + 算力 | GQA + INT8 KV，可跑 70B + 32k |
| 多卡 8×H100 | 通信 | TP=8 + MLA（DeepSeek-V3）或 sparse |
| H100 多卡集群 + 1M context | 显存爆 | hybrid（Jamba / MiniMax） + MoE |
| 推理为主，要省 KV | KV 大小 | MLA + KV 量化 → 一个数量级以上的节省 |
| 训练为主，要短 wall time | 训练吞吐 | Mamba/SSD 路径（同质量下吞吐略高） |

---

## 六、三个共识 + 三个分歧

### 共识（2025-05 业界基本同意）

1. **softmax + GQA + RoPE 仍是默认 baseline**：任何新方案都要先证明能打过它。
2. **长 context 推理必须做点什么**：MLA / sparse / hybrid 三选一，不能纯 dense softmax 硬撑。
3. **block-level 是稀疏 / 选择的工程主路**：NSA、MoBA、Mamba-2 都收敛到 block 粒度（FA-friendly）。

### 分歧（还没有定论）

1. **sparse vs hybrid 哪个赢长 context？**
   - DeepSeek/Kimi 押 sparse；AI21/MiniMax/NVIDIA 押 hybrid
   - 现在两条线都有 SOTA，没有结论

2. **SSM 能 scale 到 70B+ 吗？**
   - Nemotron-H 56B 已经接近，但还没有纯 SSM 70B+ 公开模型
   - 大概率会走"混合"过去而不是"纯 SSM 长肌肉"

3. **Mamba-2 SSD 视角统一 SSM 和 attention，未来会不会出现"统一架构"？**
   - 理论上 SSM ↔ structured-masked-attention 已等价
   - 实战上各家还在分别迭代 kernel，统一化还没发生

---

## 七、踩坑提醒（来自工业实战）

1. **"先选 attention 变体，再上 sparse / SSM"**——别一上来就 hybrid + sparse + MoE 全开，调试地狱
2. **训练目标 context 不要小于部署 context**：训 8k 部署 128k 会显著掉点（即使加 YaRN）
3. **MLA / Mamba 的 kernel 要先验证再上**：FlashMLA、Mamba selective scan 都有版本相关性
4. **评测要选对**：MMLU 评不出长 context 能力；要用 RULER、∞Bench、Long-bench（见 §13）
5. **推理引擎兼容性**：vLLM 优先支持 attention-based；SSM 集成会延后一两个版本
6. **量化叠 sparse / MLA 时要小心**：误差累积可能大于单独使用之和

## 八、关键问答

**Q1**：作为面试者，被问"你会怎么设计一个 1M context 的 LLM"，怎么答？
- 第一步：选 GQA 还是 MLA（KV 体积）→ MLA 优
- 第二步：是否加 sparse 或 SSM（attention 算量）→ NSA/DSA 或 hybrid
- 第三步：位置编码 → RoPE + YaRN/NTK
- 第四步：推理引擎 → vLLM / SGLang + PagedAttention + INT8/FP8 KV
- 第五步：评测 → RULER 而不是 MMLU

**Q2**："纯 Mamba 能不能挑战 Llama 70B?"
- 当前不能（NIAH 弱、最大公开纯 Mamba 7B）
- 混合 Mamba 可以（Nemotron-H 56B 已接近）

**Q3**："新创业团队做 LLM，从零开始要选什么架构？"
- 默认：Softmax + GQA + RoPE + MoE（Llama/DeepSeek 路线）
- 如果定位长 context：MLA + Sparse（DeepSeek-V3.2 路线）
- 如果资源有限要追长 context：Hybrid（Jamba 风格）
- 不建议：从零做纯 SSM / 纯 RWKV，工具链生态相对薄

**Q4**：openai/anthropic 在做什么架构？
- 不公开。从 API 行为推测：
  - 都支持 100k+ 上下文 → 内部一定做了 KV 优化
  - 推测：MLA-like + sliding window + 某种 sparse 混合
  - 但缺乏实证，谨慎假设

**Q5**：怎么选稀疏（§6）和 SSM/线性（§7）？
- 稀疏：还在 softmax 框架内，对现有 toolchain 兼容性最好，retrieval 不掉
- SSM/线性：架构层面换骨，长 context 极便宜，但 retrieval 风险
- → 工业团队"稳"选稀疏；学术/创新团队"激进"选 SSM/Hybrid

**Q6**：未来 2-3 年（2025-2027）的主流架构会是？
- **个人判断**（不是定论）：
  - 短-中 context（≤ 32k）：仍以 softmax + GQA/MLA + MoE 为主
  - 长 context（128k-1M）：sparse-attention 和 hybrid 并行，大概率 hybrid 赢
  - 端侧：Mamba / RWKV / 极简 hybrid
  - 大概率不会出现"一个架构统治一切"，而是"按任务分流"

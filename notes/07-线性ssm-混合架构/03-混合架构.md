## 〇、为什么必然走向"混合"

§7.1 / §7.2 的结论：

| 路线 | 优势 | 死穴 |
|------|------|------|
| **Transformer (softmax + GQA/MLA)** | retrieval / in-context learning 极强 | KV-cache 随 L 增长，长 context 推理贵 |
| **Linear attention (RWKV / RetNet / GLA)** | state 固定，长 context 推理便宜 | 长程精确 recall 弱 |
| **SSM (Mamba / Mamba-2)** | 长 context 推理便宜 + 训练效率高 | NIAH / 复杂 reasoning 弱 |

→ **没人是单点最优**。混合架构 = 用 attention 补 SSM/线性的"retrieval 弱"，用 SSM/线性 补 attention 的"KV 贵"。

```
2024-2025 的工业共识：
   "每 K 层 SSM/linear 中夹 1 层 attention"
                  ↓
        长 context 便宜  +  retrieval 不掉
```

## 一、混合的几种模式

```
模式 A: 层间夹（interleave）
  [SSM] [SSM] [SSM] [Attn] [SSM] [SSM] [SSM] [Attn] ...
  代表：Jamba / Zamba / Nemotron-H / Bamba

模式 B: 层内并联（parallel branches）
  每层：SSM 分支 + Attn 分支 + gate 融合
  代表：早期 Mamba 实验、部分研究模型

模式 C: 序列分段（chunk-level 切换）
  前 N 个 token 用 attention（短-prompt）
  后续生成用 SSM / linear（长-decode）
  代表：尚未规模化的研究方向

模式 D: 多种 attention 混合（不含 SSM）
  少量 full attention + 多数线性/稀疏 attention
  代表：MiniMax-01（Lightning Attention + softmax）
```

实证：**模式 A（interleave）是 2024-2025 的工业首选**，工程简单，效果稳。

## 二、代表模型详解

### 2.1 Jamba（[AI21 2024-03](https://arxiv.org/abs/2403.19887)）

第一个"严肃"的混合 LLM。

```
Jamba block 结构 (每 8 层一组):
   [Mamba] × 7 + [Attention] × 1     ← 1:7 interleave
   每层 FFN 全用 MoE (sparse)
```

- 52B 总参数（12B 激活，MoE）
- 256k context 训练，1M 可用
- KV-cache 占用 ≈ 纯 Transformer 的 **1/8**
- benchmark：长 context（RULER）超过同期 Llama-2 70B

**为什么 1:7 而不是 1:1？**
- 1:1 太多 attention，KV 仍重
- 1:15 太少 attention，retrieval 不够
- 实验扫出来的甜点，后续模型也大致沿用 1:6~1:8

### 2.2 Zamba / Zamba2（[Zyphra 2024](https://arxiv.org/abs/2405.16712)）

走的是 "全局共享 attention" 的思路：

```
Zamba:
   [Mamba] × N，每隔 6 层插一个 attention 层
   但所有 attention 层共享同一份 Q/K/V/O 权重 ← 极省参数
```

- 7B 总参数，但 attention 部分只占 < 5%
- 适合**显存受限**场景（端侧、消费级 GPU）
- Zamba2 上做了 grouped attention sharing 细化

### 2.3 Nemotron-H（[NVIDIA 2024-10](https://research.nvidia.com/labs/adlr/nemotron-h/)）

NVIDIA 把混合架构推到 8B / 56B / 340B 规模：

```
Nemotron-H:
  [Mamba-2] × 多 + [Attention] × 少 + [FFN]
  在每个 block 内：Mamba-2 → FFN → 偶尔 Attention → FFN
```

- 训练数据 ~2T token
- 长 context 用 RoPE + position interpolation
- 56B 模型在 RULER 256k 上 ≈ Llama-3.1 70B（参数少 25%）

→ NVIDIA 通过这个项目想验证："混合架构能 scale 到大模型"，目前看是正向的。

### 2.4 MiniMax-01（[MiniMax 2025-01](https://arxiv.org/abs/2501.08313)）

中国混合架构的代表，**走的是"Lightning Attention + softmax"路线（没用 SSM）**：

```
MiniMax-01 (456B 总参，45.9B 激活 MoE):
  每 8 层 = 7 层 Lightning Attention + 1 层 softmax attention
  整体相当于：线性 attention block × 7 + 标准 attention × 1
```

- 1M context 训练（行业里最早的 1M 训练 paper 之一）
- 推理 KV 仅为纯 softmax 的 1/8 左右
- benchmark：长 context（LongBench / RULER）开源 SOTA 之列

**和 Jamba 的区别**：MiniMax-01 用的是 §7.1 的 Lightning Attention（线性 attention 家族），不是 §7.2 的 Mamba。但**混合的层数比例（7:1）几乎一致**——巧合还是普遍规律？

→ 大概率是规律：1:7 ~ 1:8 在多家独立实验里收敛。

### 2.5 Bamba（IBM 2024-12）

IBM 把 Llama-3 蒸馏成 Mamba-混合架构：

- 起点：Llama-3 8B 的权重
- 替换：把部分 attention 层换成 Mamba-2 层
- 继续 train 少量 token 做对齐
- 结果：长 context 推理省 40%，质量保住 95%+

→ **distillation-based hybrid** 路线，工程上比"重训一遍"便宜很多。

### 2.6 Hunyuan-Hybrid（Tencent 2024）、Falcon-Mamba（TII 2024）等

- Falcon-Mamba：纯 Mamba 7B，是开源里"最 large"的纯 SSM 模型
- Hunyuan 系列也在试混合，但公开细节少

## 三、混合架构的关键设计问题

### 3.1 attention 层放哪？

```
均匀间隔（每 8 层一个 attention）         ← Jamba、Nemotron-H 等
前后多、中间少                           ← 早期实验
只在浅层放 attention                     ← 某些 ablation
```

实证：**均匀间隔最稳**。深层放 attention 对 retrieval 帮助更大；浅层放对 syntax 帮助大。

### 3.2 attention 用什么变体？

| 选项 | 优点 | 缺点 |
|------|------|------|
| Full MHA | 表达力满 | KV 大 |
| GQA | 工程标配 | 还是 $O(L)$ KV |
| MLA | KV 极省 | 实现复杂 |
| Sliding window | 局部 OK | 长距离弱 |

Jamba：GQA。Nemotron-H：GQA。MiniMax-01：softmax + GQA。
→ 没人在混合架构里用 MLA（实现复杂度叠加）。

### 3.3 KV-cache 怎么管理？

- 只有 attention 层有 KV-cache（占 1/8 ~ 1/15 层数）
- SSM/线性层只有固定 state
- 总 KV 体积 ≈ 纯 Transformer × (attention 层数 / 总层数)

对推理引擎的影响：
- 一个 batch 里"有 attention 的层" 和 "纯 SSM 的层" 内存形态不同
- PagedAttention 仍可用于 attention 层
- SSM state 的 paging 是新课题（state 大小固定，但要每个序列独享）

### 3.4 训练稳定性

- SSM 层和 attention 层初始化分布不同 → 信号方差可能不平衡
- Jamba 用了 "MoE + attention + Mamba" 三类，初始化、LR 都要分别调
- 普遍做法：**warmup 时混合系数小**（多用 attention），后期渐进切到目标比例

## 四、性能数字汇总

| 模型 | 总参数 | 激活参数 | 架构比例 | 长 context | 长 context 推理速度 vs 同规模 Transformer |
|------|--------|---------|---------|-----------|------------------------------------------|
| Jamba | 52B | 12B MoE | Mamba:Attn = 7:1 | 256k 训练，1M 实测 | 3-8× faster |
| Zamba2 | 7B | 7B dense | Mamba + shared Attn | 16k | 同 size 7B 4× faster |
| Nemotron-H 56B | 56B | 56B dense | Mamba-2 + Attn (~8:1) | 256k | ≈ Llama-3.1 70B 速度但参数少 |
| MiniMax-01 | 456B | 45.9B MoE | LinAttn:Softmax = 7:1 | 1M 训练 | ~ 4-6× faster |
| Bamba 9B | 9B | 9B dense | 蒸馏自 Llama-3 | 32k | 1.5-2× faster |

→ 共识趋势：**1:7 ~ 1:8** + GQA + MoE = 长 context 友好的工业架构。

## 五、关键问答

**Q1**：混合架构为什么不直接 1:1？
- 1:1 attention 层数仍是纯 Transformer 的一半 → KV 只省 50%
- 1:7 → KV 省 87.5%，性价比好得多
- 同时 1:7 留的 attention 已经够做 retrieval（实证）

**Q2**：Jamba 和 MiniMax-01 谁更好？
- Jamba：Mamba + Attn，state 维度大（Mamba-2 ≥ 64），有 SSM 的连续动力学
- MiniMax-01：Lightning + Softmax，纯 attention 家族，工程上更通用
- 评测互有胜负，目前都还没出"决定性"的对比
- **趋势**：两条路并行，可能最终都会被规模更大的实验筛选

**Q3**：混合架构能跑 vLLM/SGLang 吗？
- Jamba：vLLM 0.5+ 已支持
- Nemotron-H：NVIDIA TensorRT-LLM 支持
- MiniMax-01：官方推理代码已开源
- Mamba 的 selective scan kernel 集成进推理引擎是 2024 下半年的事

**Q4**：混合架构能 fine-tune / LoRA 吗？
- 可以。SSM 层的 LoRA 通常加在 $B, C, \Delta$ 投影上
- attention 层的 LoRA 和普通 Transformer 一样
- Bamba 用的就是"蒸馏 + 继续 train"，已验证可行

**Q5**：混合架构会取代纯 Transformer 吗？
- 短期：不会。Transformer + MoE + MLA + GQA 在大厂内仍最优
- 中期（2025-2026）：在长 context（256k+）任务上混合架构会更占优势
- 长期：可能"通用任务 Transformer，长 context 专用混合"，或"混合成为默认"

**Q6**："1:7 比例"是为什么？有理论吗？
- 没有严格理论，是实验扫出来的甜点
- 直觉：attention 是 retrieval 的"sharp lookup"，1:7 已经足够覆盖
- 多家独立工作（Jamba、MiniMax、Nemotron-H）都收敛到这个量级 → 经验性规律

**Q7**：混合架构的训练成本和纯 Transformer 比？
- SSM 层 train 比 attention 略慢（kernel 优化还在迭代）
- 但参数总量可以略小（同质量下）
- 总训练成本：通常持平或略低，主要省的是**推理成本**

## 六、未来方向（2025+）

```
1) "更多元的混合"：SSM + linear attention + softmax + sliding window 多种共存
2) "router-style hybrid"：每层根据输入动态选用 SSM/Attn（类似 MoE 路由 architecture）
3) 端侧专用 hybrid：state 极小 + 极少 attention（手机、边缘）
4) Mamba-3 / 下一代 SSM：state 维度继续拉大，逼近 attention 的精确召回
```

**和 §6 sparse attention 的协同**：可以预见，sparse attention（NSA、MoBA） + 混合 SSM 会进一步叠加，形成"sparse-hybrid"——这是 2026 的可能方向之一。

## 一、手撕代码（白板 / PyTorch）

### Q1.1 写一个 Scaled Dot-Product Attention（含 causal mask）⭐

**【参考实现】**

```python
import torch
import torch.nn.functional as F

def scaled_dot_product_attention(q, k, v, mask=None):
    """
    q, k, v: [B, H, T, D]
    mask: [T, T] additive (-inf for masked positions)
    """
    B, H, T, D = q.shape
    scores = q @ k.transpose(-2, -1) / (D ** 0.5)   # [B, H, T, T]
    if mask is not None:
        scores = scores + mask
    attn = F.softmax(scores, dim=-1)
    out = attn @ v   # [B, H, T, D]
    return out

# Causal mask
def causal_mask(T, device):
    m = torch.full((T, T), float('-inf'), device=device)
    return torch.triu(m, diagonal=1)
```

**【面试官常考点】**
- 是否记得除 √D
- 是否记得 softmax 数值稳定（实际 F.softmax 内置）
- mask 是加 `-inf` 还是乘 0？（加 `-inf`，softmax 后变 0）
- 顺手讲 FlashAttention 怎么避免显式 materialize `scores`

### Q1.2 写一个 Multi-Head Attention（含 GQA 支持）⭐⭐

```python
import torch.nn as nn

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_q_head, n_kv_head, max_seq=8192):
        super().__init__()
        assert n_q_head % n_kv_head == 0
        self.n_q_head, self.n_kv_head = n_q_head, n_kv_head
        self.d_head = d_model // n_q_head
        self.group = n_q_head // n_kv_head

        self.W_q = nn.Linear(d_model, n_q_head * self.d_head, bias=False)
        self.W_k = nn.Linear(d_model, n_kv_head * self.d_head, bias=False)
        self.W_v = nn.Linear(d_model, n_kv_head * self.d_head, bias=False)
        self.W_o = nn.Linear(n_q_head * self.d_head, d_model, bias=False)
        self.register_buffer("mask", causal_mask(max_seq, "cuda"))

    def forward(self, x):
        B, T, _ = x.shape
        q = self.W_q(x).view(B, T, self.n_q_head, self.d_head).transpose(1, 2)
        k = self.W_k(x).view(B, T, self.n_kv_head, self.d_head).transpose(1, 2)
        v = self.W_v(x).view(B, T, self.n_kv_head, self.d_head).transpose(1, 2)

        # GQA: repeat KV heads
        k = k.repeat_interleave(self.group, dim=1)
        v = v.repeat_interleave(self.group, dim=1)

        out = scaled_dot_product_attention(q, k, v, self.mask[:T, :T])
        out = out.transpose(1, 2).contiguous().view(B, T, -1)
        return self.W_o(out)
```

**【面试官常考点】**
- W_q/k/v 维度（GQA 下 K,V 投影到 `n_kv_head * d_head` 而不是 `d_model`）
- 是否懂 `repeat_interleave` 在实际 attention kernel 里不会真复制
- 加 KV cache 怎么改？（外部传入 `kv_cache` dict + 拼接）

### Q1.3 写 RoPE + 应用到 Q,K ⭐⭐

```python
def precompute_rope(d_head, max_seq, base=10000.0, device="cuda"):
    """返回 cos, sin: [max_seq, d_head // 2]"""
    half = d_head // 2
    inv_freq = 1.0 / (base ** (torch.arange(0, half, device=device).float() * 2 / d_head))
    pos = torch.arange(max_seq, device=device).float()
    freqs = pos[:, None] * inv_freq[None, :]   # [max_seq, half]
    return freqs.cos(), freqs.sin()

def apply_rope(x, cos, sin):
    """
    x: [B, H, T, D]
    cos, sin: [T, D//2]
    """
    x1, x2 = x[..., ::2], x[..., 1::2]   # 偶/奇 dim 对
    cos = cos.unsqueeze(0).unsqueeze(0)   # [1,1,T,D//2]
    sin = sin.unsqueeze(0).unsqueeze(0)
    rotated = torch.stack([x1*cos - x2*sin, x1*sin + x2*cos], dim=-1)
    return rotated.flatten(-2)
```

**【面试官常考点】**
- "复数旋转"直觉：每对 dim 视为复数 `x1 + i·x2`，乘 `e^{i·m·θ}`
- 是否在 Q 和 K 上都 apply（必须）
- 长上下文扩展：把 `pos` 缩放（PI）或把 `base` 拉大（NTK）
- DeepSeek MLA 为什么"decoupled RoPE"？（压缩 KV 后旋转结构不保留，要单独留 RoPE 维）

### Q1.4 写 LoRA Linear ⭐

```python
class LoRALinear(nn.Module):
    def __init__(self, in_dim, out_dim, r=16, alpha=32):
        super().__init__()
        self.base = nn.Linear(in_dim, out_dim, bias=False)
        self.A = nn.Parameter(torch.randn(r, in_dim) * (1.0 / r ** 0.5))
        self.B = nn.Parameter(torch.zeros(out_dim, r))    # 初始 ΔW=0
        self.scale = alpha / r
        for p in self.base.parameters(): p.requires_grad = False

    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.t()) @ self.B.t()
```

**【面试官常考点】**
- `B` 必须初始化为 0（保证 ΔW 初值=0，base 模型行为不变）
- `scale = α/r` 通常 α=2r
- LoRA merge 推理：`W' = W_base + scale·B·A`
- 多 LoRA 服务（S-LoRA）：不 merge，运行时叠加

### Q1.5 写 Top-K MoE Router + 加权 expert 输出 ⭐⭐

```python
class MoE(nn.Module):
    def __init__(self, d_model, n_expert, top_k=2):
        super().__init__()
        self.top_k = top_k
        self.router = nn.Linear(d_model, n_expert, bias=False)
        self.experts = nn.ModuleList([
            nn.Sequential(nn.Linear(d_model, 4*d_model), nn.SiLU(),
                          nn.Linear(4*d_model, d_model))
            for _ in range(n_expert)
        ])

    def forward(self, x):
        # x: [B, T, D]
        B, T, D = x.shape
        x_flat = x.view(-1, D)                       # [N, D]
        logits = self.router(x_flat)                 # [N, E]
        topk_val, topk_idx = logits.topk(self.top_k, dim=-1)
        weights = F.softmax(topk_val, dim=-1)        # [N, k]

        out = torch.zeros_like(x_flat)
        for k in range(self.top_k):
            for e in range(len(self.experts)):
                mask = (topk_idx[:, k] == e)
                if mask.any():
                    out[mask] += weights[mask, k:k+1] * self.experts[e](x_flat[mask])
        return out.view(B, T, D)
```

**【面试官常考点】**
- 真实工程会用 `gather` / `scatter`、按 expert 分桶批处理
- 需要 aux loss（load balancing）或 Aux-Loss-Free（bias 调整）
- 推理时要把 expert 分发到不同 GPU（EP）+ all-to-all
- top-k=1 是 Switch，k=2 是 GShard，k=8 是 DeepSeek 细粒度

### Q1.6 实现温度采样 + Top-k + Top-p ⭐

```python
def sample(logits, temperature=1.0, top_k=0, top_p=1.0):
    """
    logits: [V]
    """
    logits = logits / max(temperature, 1e-5)

    if top_k > 0:
        v, _ = logits.topk(top_k)
        logits[logits < v[-1]] = -float("inf")

    if top_p < 1.0:
        sorted_logits, sorted_idx = logits.sort(descending=True)
        cum_probs = sorted_logits.softmax(-1).cumsum(-1)
        keep = cum_probs <= top_p
        keep[0] = True   # 至少留一个
        mask = torch.zeros_like(logits, dtype=torch.bool)
        mask[sorted_idx[keep]] = True
        logits[~mask] = -float("inf")

    probs = logits.softmax(-1)
    return torch.multinomial(probs, 1)
```

**【面试官常考点】**
- temperature → 0 等价 greedy
- top-k vs top-p 区别：k 截前 k 个；p 累积概率
- 现代用 min-p / top-a 等新策略
- repetition penalty 加在 logits（出现过的 token logit 除以 1.1）

### Q1.7 实现简易 KV cache 自回归生成 ⭐⭐

```python
@torch.no_grad()
def generate(model, prompt_ids, max_new=128):
    kv_cache = {}   # layer_idx -> (K, V)
    x = prompt_ids   # [1, T_prompt]
    out_ids = []

    # Prefill
    logits = model.forward_with_cache(x, kv_cache)   # 一次 forward 全部
    next_id = sample(logits[:, -1])
    out_ids.append(next_id)

    # Decode
    for _ in range(max_new - 1):
        logits = model.forward_with_cache(next_id, kv_cache)   # 只 forward 新 token
        next_id = sample(logits[:, -1])
        if next_id == EOS: break
        out_ids.append(next_id)
    return out_ids
```

**【面试官常考点】**
- prefill 一次 forward 整个 prompt；decode 每步 forward 1 token
- 每层 attention 内部要把新 K,V 拼到 cache 末尾
- 显存增长：随 seq_len 线性
- 怎么扩到 PagedAttention：每个 block 16 token 一页 + block table

## 二、系统设计

### Q2.1 设计一个 LLM serving 系统支持 1000 QPS, P99 TTFT < 500ms ⭐⭐⭐

**思路（30 分钟回答模板）**

1. **需求量化**
   - 1000 QPS、avg input 1K token、avg output 500 token
   - P99 TTFT < 500ms（prefill 端约束）、P99 TPOT < 50ms

2. **容量估算**
   - 7B fp16 single H100：~120 token/s decode (batch 1)；batch 32 ~3000 token/s
   - 1000 QPS × 500 token = 500K token/s output；÷ 3000 ≈ 170 H100（decode 池）

3. **架构**
   ```
   Client → LB → Gateway (auth/rate-limit/route by model)
                       ↓
                Prefill Pool (M GPU, large-batch, throughput)
                       ↓ KV (RDMA)
                Decode Pool (N GPU, continuous batching, latency)
                       ↓
                Stream token → Client (SSE)
   ```

4. **关键优化**
   - 用 vLLM/SGLang + PagedAttention + Continuous Batching
   - Prefix Caching（system prompt 复用）
   - Spec Decoding（若 batch 不大）
   - KV INT8 量化
   - Autoscale based on queue depth + P99 latency

5. **监控**
   - per-stage：TTFT、TPOT、queue depth、GPU util、HBM 占用
   - 告警：P99 TTFT > 400ms 提前扩容

**【加分项】**
- 谈 PD 分离触发条件（avg input > 4K 必须 PD）
- 谈多模型混合部署 → MIG 切分 / model swap
- 谈 SLO 失效降级（量化精度降级、reject low-priority）
- 安全：rate limit、prompt injection 防护、output filter

**【常见追问】**
1. 突然来一波 100K token 的请求怎么办？→ chunked prefill + 优先级降级
2. multi-tenant 数据隔离？→ KV pool 加 namespace、prefix cache 不跨 tenant share
3. 同时支持 70B 和 7B 怎么调度？→ 不同 pool；KV 不共享

### Q2.2 设计一个 1M context RAG 系统 ⭐⭐⭐

**【拆解】**

1. **需求**：长文档（百万 token）QA，准确率 > native context、延迟可控

2. **取舍：long context vs RAG**
   - 全塞 1M context：贵（KV ~200GB+）、Lost in the Middle
   - 纯 RAG：可能漏关键信息、reference 散
   - **混合**：retrieve top-k + 喂 64K context（黄金区间）

3. **架构**
   ```
   Documents → Chunk (512 tok overlap 64) → Embed (BGE-M3 / GTE)
              → Vector DB (Milvus / Qdrant) + Sparse (BM25)
   Query → Hybrid retrieve top-50 → Rerank (BGE-Reranker / Cohere) top-10
        → Compose prompt (system + chunks + Q) → LLM (64K context)
        → 生成 + 引用 source
   ```

4. **关键工程**
   - **chunking**：按段落 / heading，不按固定长度
   - **hybrid search**：dense + sparse + rerank
   - **prompt 模板**：每个 chunk 标 `[1]`...，让模型 cite
   - **citation grounding**：post-check 模型 cite 的段落确实存在

5. **优化**
   - prefix caching：固定 system prompt + 常用 doc 缓存
   - Multi-vector / late interaction (ColBERT-style)
   - Query rewrite / HyDE

**【追问】**
1. 召回不到怎么办？→ Query 改写、HyDE、扩 top-k、加 graph RAG
2. 多模态（PDF 含图）？→ DeepSeek-OCR / GPT-4o vision 提取 + multimodal embed
3. 1M context 直接喂 vs RAG 哪个准？→ 信息分散时 RAG 准；信息互相依赖时 context 准

### Q2.3 设计一个数学 reasoning 模型训练 + 服务一体系统 ⭐⭐⭐

**【拆解】**

1. **训练侧**（参考 R1）

   - rollout：vLLM single batch；reward 计算异步

5. **评测**
   - AIME 2025（防污染）每周跑
   - 内部 hold-out math set
   - 人工 spot-check reasoning trace 质量

**【加分项】**

### Q2.4 设计一个 agent 系统跑 SWE-bench Verified ⭐⭐⭐

**【拆解】**

1. **agent scaffolding**
   - OpenHands / SWE-agent / Agentless 三选一
   - **Agentless 流派**（hierarchical: localize → repair → validate）目前更高 ~50%
   - SWE-agent 流派（ACI + tool）灵活但慢

2. **模型选择**
   - Claude 3.7 + scaffolding ~70% (Verified)
   - Qwen3-Coder / DeepSeek-V3 + agentless ~50-60%
   - 开源 best: SWE-Gym 训出的 32B model

3. **训练**（如要自训）
   - SFT：sample 成功 trajectory
   - RL：SWE-Gym（环境）+ unit test verify
   - 主要难点：long horizon credit、tool error recovery

4. **基础设施**
   - 容器化（每题独立 Docker 起 repo + run test）
   - 异步执行（每题 ~10 min）
   - log + 中间状态可回放

5. **推理控制**
   - max_iter 50 step；超时 kill
   - 多轮 retry + reflexion
   - cost：~$1-5 per task

**【追问】**
1. SWE-agent 和 OpenHands 区别？→ scaffolding 设计、ACI 不同；OpenHands 是社区驱动（前 OpenDevin）
2. agentless 真的不需要 agent 吗？→ 用 LLM 多轮 + 固定 pipeline，狭义不是 agent
3. 防 reward hack 怎么办？→ unit test 是 ground truth，但要防 LLM 改 test

- 第 2 周：§9-§11 (MoE + 训练 + 后训练) 公式推导
- 第 3 周：§12-§13 (推理优化 + 评测) + 写过 1-2 段手撕代码

### Q4.6 LLM 面试需要刷 LeetCode 吗？

- infra / 推理岗：会做基础 medium 即可，重点在 CUDA / 多卡通信概念
- 全栈岗：兼顾

### Q4.7 系统设计题打分点是什么？

- **正确性**：组件之间数据流没漏
- **完整性**：监控 + autoscale + 降级
- **取舍意识**：能讲清"为什么这样而不那样"
- **数字感**：能估算量级（不要 1000 GPU 跑 7B 这种错）
- **沟通**：边讲边画、主动澄清需求

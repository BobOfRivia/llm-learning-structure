## 〇、这一节想回答什么问题

"写代码时到底该调哪个 attention 函数？"

```python
# 1. 手写
output = (Q @ K.T / sqrt(d_k)).softmax(-1) @ V

# 2. PyTorch 官方
output = F.scaled_dot_product_attention(Q, K, V, is_causal=True)

# 3. xFormers
from xformers.ops import memory_efficient_attention
output = memory_efficient_attention(Q, K, V)

# 4. FlashAttention 直接调
from flash_attn import flash_attn_func
output = flash_attn_func(Q, K, V, causal=True)
```

四种写法，性能差几十倍。这节把 PyTorch SDPA、xFormers、FlashAttention、Triton 之间的关系理顺。

---

## 一、PyTorch SDPA（torch ≥ 2.0）

`torch.nn.functional.scaled_dot_product_attention`（简称 **SDPA**），是 PyTorch 官方的"门面"API。

特点：
- **不是**一个新算法，是一个**调度器**：根据 dtype、shape、硬件、mask 类型，自动选下面三种 backend 之一
- 是 PyTorch 2.0+ 推荐的写法

### 1.1 三个 backend

| Backend | 用什么 | 何时被选中 |
|---------|--------|-----------|
| **flash** | FlashAttention（v2 / v3） | BF16/FP16，连续，causal 或 full |
| **mem_efficient** | xFormers 风格的 memory-efficient kernel | flash 不可用但 dtype 支持 |
| **math** | naive 实现（PyTorch 原生 GEMM + softmax） | 上面都不行，fallback |

可以查询当前调度：
```python
from torch.nn.attention import sdpa_kernel, SDPBackend
with sdpa_kernel(SDPBackend.FLASH_ATTENTION):
    out = F.scaled_dot_product_attention(...)
```

### 1.2 落到 flash 的条件（常见踩坑）

- dtype 必须是 `torch.float16` 或 `torch.bfloat16`（FP32 不支持）
- head dim 必须是 8/16/32/64/96/128/160/192/224/256 之一
- attention mask：支持 `is_causal=True`、或不传 mask；自定义 attn_bias 时会掉到 mem_efficient 或 math
- `dropout_p > 0` 在 flash 上支持（但有版本要求）
- Q, K, V 必须 contiguous

调试技巧：把 `TORCH_LOGS="sdp"` 打开，PyTorch 会打出每次选了哪个 backend，以及没选 flash 的原因。

## 二、xFormers（Meta）

[xFormers](https://github.com/facebookresearch/xformers) 是 Meta 维护的"高效 transformer 算子库"。

### 2.1 三个常用 op

| Op | 用途 |
|----|------|
| `memory_efficient_attention` | 类 FA 的 fused kernel（早于 FA 出来） |
| `memory_efficient_attention_forward` | 只 forward |
| `BlockDiagonalMask` / `LowerTriangularMask` | 高效 mask 类型 |

### 2.2 xFormers vs FlashAttention

- xFormers 早于 FA（2022 年初）就有 memory-efficient attention
- 但**性能不如 FA2/FA3**，且不支持 H100 上的 TMA/WGMMA
- 现在 PyTorch 2.0+ 的 mem_efficient backend 实际是 xFormers 风格
- **建议**：除非有特殊 mask 形状需求，直接用 SDPA 就够

### 2.3 还在用 xFormers 的场景

- **特殊 mask**：BlockDiagonal（packed sequence）、文档级 mask
- **Diffusion 模型**：早期 stable-diffusion 生态深度依赖 xFormers
- **历史代码**：不少 2022-2023 的项目还在用

## 三、FlashAttention 官方包

[`flash-attn`](https://github.com/Dao-AILab/flash-attention) Python 包。

```python
from flash_attn import flash_attn_func, flash_attn_varlen_func
out = flash_attn_func(q, k, v, causal=True, dropout_p=0.0)
```

### 3.1 何时直接调（不走 SDPA）

- 需要 **varlen（packed）**：`flash_attn_varlen_func` 支持不等长 batch 拼接
- 需要 **window attention**：`window_size=(left, right)` 参数
- 需要 **ALiBi**：FA 内置支持
- 需要 **FP8（FA3）**：直接走 FA3 包
- 需要最新优化（H100 上 FA3 > SDPA 默认选的 FA2）

### 3.2 typical layout

FA 的 input layout 是 `(batch, seq, heads, head_dim)`，**和 PyTorch 默认的 `(batch, heads, seq, head_dim)` 不同**。容易踩坑。

```python
# PyTorch SDPA: (B, H, L, D)
# FlashAttention: (B, L, H, D)
q_fa = q_torch.transpose(1, 2).contiguous()
```

## 四、Triton 自定义 kernel

[Triton](https://github.com/triton-lang/triton)（OpenAI）：用 Python 写 GPU kernel，编译成 PTX。

### 4.1 用途

- **prototyping**：先用 Triton 验算法，再考虑要不要写 CUDA
- **小 niche kernel**：稀疏 attention、特殊 mask、custom RoPE
- **教学**：FlashAttention 的 [Triton 实现](https://github.com/Dao-AILab/flash-attention/blob/main/flash_attn/flash_attn_triton.py) 是经典教程

### 4.2 性能

- 比 CUDA 写的 FA2 通常慢 10-30%
- 但**开发速度快 10×**
- 当前 Triton 在 H100 上不如手写 CUDA（TMA/WGMMA 支持有限）

### 4.3 vs `torch.compile`

- `torch.compile` 在底层有时会生成 Triton kernel
- 自己写 Triton 是"主动"，`torch.compile` 是"被动"
- 复杂 attention 变体（NSA、DSA）几乎都用 Triton 写

## 五、PyTorch 编译路径

### 5.1 `torch.compile`

```python
model = torch.compile(model, mode="max-autotune")
```

底层做的事：
1. **TorchDynamo**：trace 出 graph
2. **AOTAutograd**：分离 forward / backward
3. **Inductor**：lowering 到 Triton / OpenAI Triton kernel / cuBLAS
4. **CUDA Graph**（可选）：减小 launch overhead

对 attention 的影响：
- 如果你用 `F.scaled_dot_product_attention`，`torch.compile` 会**保留**这个 op，不重写
- 如果你手写 `Q @ K.T / sqrt(d) ... softmax ... @ V`，`torch.compile` 会尝试 fuse，但**做不出 FA 的效果**
- → 写 SDPA 而不是手写，是 `torch.compile` 友好的最低成本写法

### 5.2 CUDA Graphs

- decode 阶段每步 kernel 数固定，CUDA Graph 可消除 launch overhead（每 token 省 ~1ms）
- 但要求 input shape 固定（动态 batch 不友好）
- vLLM、TensorRT-LLM 都集成了

## 六、Attention 算子的精度问题

### 6.1 softmax 在 FP16/BF16 下的数值稳定

- naive softmax: $\exp(s_i) / \sum \exp(s_j)$，分子分母都可能 overflow
- safe softmax: $\exp(s_i - \max(s)) / \sum \exp(s_j - \max(s))$
- 现代 attention kernel（FA、cuDNN attention）都用 safe softmax，**且 softmax 内部用 FP32 累加**
- 手写时容易忘 FP32 累加 → 数值溢出，loss NaN

### 6.2 BF16 vs FP16

- **BF16**（指数 8 位，mantissa 7 位）：动态范围大、精度低；训练标配
- **FP16**（指数 5 位，mantissa 10 位）：动态范围小、精度高；推理常用，训练需 loss scaling
- attention 内部用什么：FA2/FA3 中 attention matrix 在 FP32 累加

### 6.3 FP8 attention（前沿）

- FA3 支持 FP8 attention，但 K/V scale 要 per-head 选
- 实测在 short context 下接近 BF16 质量，long context 略掉点
- DeepSeek-V3、NVIDIA TensorRT-LLM 都已上 FP8 attention

---

## 七、实战选择矩阵

| 场景 | 推荐 |
|------|------|
| 一般训练（Llama 风格 + causal） | `F.scaled_dot_product_attention(..., is_causal=True)` |
| Packed 训练（多序列拼一条） | `flash_attn_varlen_func` |
| Window attention / ALiBi | `flash_attn_func`（直接调）|
| 自定义稀疏 mask | Triton 手写（参考 FA Triton 实现） |
| H100 上极致性能 | FA3 直接调（暂未默认走 SDPA） |
| Diffusion / 老代码 | xFormers `memory_efficient_attention` |
| 推理引擎（vLLM/SGLang） | 它们已经在内部用 FA + Paged + 优化好 |

## 八、cuDNN Attention（NVIDIA）

NVIDIA 自家 cuDNN（9.x+）也提供了 fused attention，名字 `cudnnFusedAttention`：
- 在 H100/B200 上性能与 FA3 接近
- 支持 multi-query、grouped-query、sliding window
- PyTorch SDPA 在新版本上也会调 cuDNN attention 作为 backend
- TensorRT-LLM 是首选用户

## 关键问答

**Q1**：写代码时直接 `F.scaled_dot_product_attention` 还是 `flash_attn_func`？
- 99% 场景：**SDPA**（前向兼容、自动选最优 backend）
- 需要特殊功能（varlen、window、ALiBi）：直接 FA
- 跨硬件移植性强：SDPA
- 极致性能 + H100 + 最新 FA3：直接 FA3 库

**Q2**：手写 attention 为什么不要 fuse 到 FA？
- `torch.compile` 的 Inductor 做不出 FA 的 tile 切分 + online softmax
- 它只能做 elementwise fusion 和简单的 matmul-bias 融合
- 想要 FA 速度必须用 FA kernel

**Q3**：为什么 FA 要求 head_dim 是特定值（64、128 等）？
- kernel 用 `constexpr` 模板按 head_dim 特化
- 编译期才能确定 SRAM tile 大小 → 必须是预编译过的尺寸
- head_dim=96 / 192 等是后期补的

**Q4**：训练 loss NaN 通常是不是 attention 数值问题？
- 70% 的概率是
- 排查清单：softmax 是否 FP32 累加 / mask 是否 `-inf` 而不是 `-1e9` / Q/K scale 是否漏除 `sqrt(d_k)`
- 用 SDPA 几乎不会遇到这些坑（kernel 已处理）

**Q5**：Triton 写 attention 比 CUDA 慢吗？
- 单 kernel：通常慢 10-30%
- 但能快速实验新算法（NSA、DSA、sliding window）
- 一旦算法稳定，团队再考虑用 CUDA 重写

**Q6**：CUDA Graph 为什么对 decode 友好？
- decode 每步 op 数固定（几十个 kernel launch）
- 每次 launch overhead 5-20μs，累计大
- CUDA Graph 把整个 step 录下来，replay 一次 ≈ 1 个 launch
- 实测 decode tokens/s 提升 10-25%

**Q7**：xFormers 现在还要不要用？
- 一般 transformer：不需要，SDPA 替代
- 稀疏 / block-diagonal mask：仍是好选项
- 不要为了新项目主动引入 xFormers 依赖

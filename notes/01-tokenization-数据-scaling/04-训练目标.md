# 1.4 训练目标

[← 返回框架](../../README.md) · [📎 materials.md → §1.4](../../materials.md)

## 一、Next-Token Prediction（Causal LM）

主流 decoder-only 模型的目标。

**数学形式**：
$$p_\theta(x_1, x_2, \dots, x_T) = \prod_{t=1}^{T} p_\theta(x_t \mid x_{<t})$$

**损失函数**（cross-entropy / NLL）：
$$\mathcal{L}(\theta) = -\frac{1}{T} \sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t})$$

**实现关键**：
- **Causal mask**：attention 中遮住未来位置
- **Teacher forcing**：训练时用真实 token 作为下一步输入（推理时用自己生成的）
- **Shifted target**：input = `[x_1, ..., x_{T-1}]`，target = `[x_2, ..., x_T]`

---

## 二、为什么是 Cross-Entropy

对分类问题（next token 在 V 维 one-hot 上），CE 等价于最大化训练数据似然 MLE。

**CE vs MSE**：
- CE 给低概率的正确类**强梯度**：$\frac{\partial \mathcal{L}}{\partial z_y} = p_y - 1$
- MSE 在 softmax 后梯度会消失（饱和）
- 信息论上 CE = KL(真实分布 || 模型分布) + H(真实分布)，等价于最小化 KL

---

## 三、Perplexity（PPL）

预训练阶段最常报告的指标。

$$\text{PPL} = \exp\left(-\frac{1}{T} \sum_t \log p(x_t \mid x_{<t})\right) = \exp(\mathcal{L})$$

**直觉**：每个位置上的"等效分支因子"
- PPL = 1：完美预测
- PPL = V：纯随机
- 现代 LLM 在 web 文本上 PPL 约 3–10

**变体**：
- **BPC**（bits per character）：用 log₂、按字符均分（去除 tokenizer 影响）
- **BPB**（bits per byte）：UTF-8 字节级，多语言公平

## 四、Loss Masking 工程细节

### 4.1 Padding 不计 loss
batch 内对齐用的 `<pad>` token，loss 设置为 0（`ignore_index=-100`）。

### 4.2 SFT 阶段只算 response loss
```
<system>...<user>...<assistant>...
              ↑ 这部分及之前的 token 不计 loss
```
原因：prompt 是输入条件，模型不需要"学着生成 prompt"。

### 4.3 多文档 packing
预训练时常把多个文档拼成 4k/8k 序列以提效，需要 **document mask** 切断跨文档 attention（FlashAttention v2 起原生支持 variable-length / packing）。

## 五、其他训练目标（理解差异）

### 5.1 MLM（Masked LM, BERT）

随机 mask 15% token，预测被 mask 的。
$$\mathcal{L} = -\mathbb{E}_{M} \sum_{i \in M} \log p(x_i \mid x_{\setminus M})$$

- **双向 attention**，表征强
- **训推不一致**：训练时见 `[MASK]`，推理时没有
- 80% mask + 10% random + 10% keep 的 trick 缓解
- **生成弱**：不能自回归

### 5.2 Span Corruption（T5）

mask 整段（连续 span），用 sentinel `<X>`、`<Y>` 占位，**解码器输出原段**。
```
input:  Thank you <X> me to your party <Y>
target: <X> for inviting <Y> last week <Z>
```
- 兼具 MLM 的双向上下文 + 生成能力
- T5 / Flan-T5 / mT5 使用

### 5.3 FIM（Fill-in-the-Middle）

用于 **code 模型**（GitHub Copilot、Codex、StarCoder、DeepSeek-Coder）。

训练时随机把序列重排：
```
原序列: [prefix][middle][suffix]
FIM 重排: <PRE>[prefix]<SUF>[suffix]<MID>[middle]
```
模型仍按 next-token 训练，但学会在给定前后文情况下"补中间"。

- 推理时切换 PSM / SPM 两种格式
- 与 CLM 兼容（损失同为 next-token CE）

### 5.4 UL2 / Mixture of Denoisers

Google 提出，混合多种 corruption 目标（R-denoiser / S-denoiser / X-denoiser），训出统一模型。

### 5.5 Prefix LM

输入分两段：prefix 用双向 attention，target 用 causal。**GLM、PaLM-1** 用过，现已少见。

## 六、为什么 CLM 赢了 MLM

历史问题：BERT 一度是 NLP 主流（2018-2020），但 2020 GPT-3 后 decoder-only 完全胜出。

| 维度 | CLM | MLM |
|------|-----|-----|
| 训推一致 | ✅ | ❌（训练 mask 推理无） |
| 直接生成 | ✅ | ❌（需要额外 head） |
| In-context learning | ✅ | ❌（结构上做不到） |
| 表征质量 | 中等（要做 sentence embedding 需另训） | 强 |
| 数据效率 | 学每个 token | 只学 15% mask |

**核心原因**：MLM 训练目标和"生成任务"本质不一致；in-context learning 这个**涌现能力**只在 CLM 上出现。

> 即使 MLM 在 representation benchmark 上更强，CLM 的通用性碾压了它。

## 七、与采样的关系

训练目标决定推理时怎么采样：

| 训练 | 推理 |
|------|------|
| CLM | 自回归（greedy / top-k / top-p / temperature） |
| MLM | 不能直接生成；需 Gibbs sampling 等近似 |
| T5 | encoder 一次性，decoder 自回归 |

采样参数（temperature / top-k / top-p）影响生成的多样性，与训练目标无关，但训练目标决定它们"有意义"。

## 关键问答

**Q1**：为什么用 cross-entropy 而非 MSE？
- 分类问题的 MLE 等价于最小化 CE
- CE 给错误预测强梯度，MSE 在 softmax 输出处会梯度消失
- 信息论解释：CE = KL(真实 || 模型) 上界

**Q2**：Perplexity 与 BPC 的关系？
- $\text{BPC} = \log_2(\text{PPL}) / \overline{\text{token长}}$
- PPL 依赖 tokenizer（同样文本，词表大 PPL 小）
- BPC / BPB 更公平，但学界仍习惯报 PPL

**Q3**：为什么 BERT 不能直接做生成？
- 双向 attention 不能 strict left-to-right
- 训练时见 `[MASK]`，推理时没有自然的 mask 位置
- 改造（如 BART、T5）已偏向 encoder-decoder

**Q4**：FIM 训练为什么有必要？
- 代码补全场景里光标前后都有 context
- CLM 只能用前文，FIM 让模型学会"双向条件下生成中间"
- 损失同样是 CE，只是输入序列被重排

**Q5**：SFT 的 loss 应不应该包含 prompt？
- 主流做法：**只算 response 上的 loss**（prompt 部分 ignore）
- 原因：模型已经能生成各种 prompt，关键是学 response 分布
- 少数做法：保留 prompt loss（轻微，有时帮助）

**Q6**：训练时怎么处理超长文档？
- **Chunked**：切成固定长度
- **Packing**：多文档拼接 + document mask
- **Long context curriculum**：分阶段提高 context 上限

## 一、核心论点

**2024 年起的共识**：模型架构 / 训练算法的 ROI 已经远低于数据质量的 ROI。
- 同样架构 + 同样算力，更好的数据可以让 1.5B 模型打平 7B
- **FineWeb-Edu**、**Phi 系列**、**Nemotron-CC** 是这条路线的代表

类比：
> "Compute is the fuel, data quality is the engine."

## 二、数据源

### 2.1 Web（占比最大）

基于 **CommonCrawl**（CC）的衍生数据集，规模逐代提升：

| 数据集 | 年份 | 规模 | 关键做法 |
|--------|------|------|----------|
| **C4** (T5) | 2019 | 750 GB | 启发式过滤 |
| **CCNet** | 2019 | — | 用 5-gram KenLM 算 PPL 过滤 |
| **The Pile** | 2020 | 825 GB | 22 个高质来源混合 |
| **RefinedWeb** (Falcon) | 2023 | 5 TB | 大规模启发式 + MinHash dedup |
| **RedPajama-v2** | 2023 | 30 T tokens | 暴露 40+ 质量信号 |
| **FineWeb** | 2024 | 15 T tokens | 大规模 + 严格 dedup |
| **FineWeb-Edu** | 2024 | 1.3 T tokens | **基于教育性的模型分类器** |
| **DCLM** | 2024 | 240 T tokens | 模型 classifier + benchmark 反馈 |
| **Nemotron-CC** | 2024 | 6.3 T tokens | NVIDIA，**重写低质量文档** |

### 2.2 高质量精选源

- **Wikipedia**：多语言、高质量，但量小
- **Books**：Books3（侵权下架后多家自建）、Project Gutenberg
- **Papers**：arXiv、PubMed、S2ORC
- **Code**：GitHub → **The Stack v1/v2**（BigCode）；**StarCoder data**
- **Math**：**OpenWebMath**、**ProofPile**、**AutoMathText**
- **Q&A**：StackExchange、Reddit

### 2.3 多语言

- mC4、CulturaX、HPLT、Common Pile

## 三、数据清洗 Pipeline

### 3.1 文本提取
- HTML → 纯文本：**trafilatura**、**resiliparse**
- PDF → 文本：**Nougat**、**Marker**、**MinerU**

### 3.2 语言识别
- **fastText**（Facebook，176 语言）
- **cld3** / **GlotLID**

### 3.3 质量过滤

三代演化：

**第一代 — 启发式规则**（C4、Gopher）：
- 行长度阈值、unique words 比例、bullet/省略号比例
- 字符 n-gram 重复率
- "stop words" 数量
- 简单但 recall 低，会误删

**第二代 — 困惑度过滤**（CCNet、CCMath）：
- 用 KenLM 或小 LM 在干净语料上训练
- 用 PPL 阈值过滤
- 比规则强但仍有偏差

**第三代 — 模型分类器**（FineWeb-Edu、DCLM、Nemotron-CC）：
- 用 LLM（Llama-3-70B）给样本打"教育性 / 信息量"分数
- 训练 BERT/embedding 小分类器
- 大规模回去筛 CC
- **效果显著**：FineWeb-Edu 1.3T tokens 训出的模型超过 FineWeb 全量 15T

### 3.4 去重（Deduplication）⭐ 重要

去重是预训练数据工程**最被低估的杠杆**：
- 不去重：模型在重复段落上过拟合 → 评测正常但泛化差
- 不去重：导致**记忆/隐私泄露**风险
- Lee et al. 2021 证明去重可以 2-3× 减少所需训练 token

**层级**：
1. **URL 去重**：同一 URL 只保留一次
2. **Exact dedup**：完全相同的文档
3. **Near-duplicate dedup**：
   - **MinHash + LSH**（最主流）
   - **SimHash**
   - **Suffix Array**（精确长 n-gram 匹配）
4. **跨数据集去重**：训练集 vs 评测集（防污染）

### 3.5 安全 / 隐私
- **PII 移除**：邮箱、电话、信用卡正则
- 有害内容（NSFW、仇恨言论）分类器过滤
- 版权敏感源（Books3）选择性处理

## 四、数据配比（Data Mixture）

不同来源混合时的权重决定模型能力分布。

**经验法则**：
- **Web**：40-80%（主体）
- **Code**：5-20%（影响推理能力，越来越高）
- **Math**：1-10%
- **Books / Papers**：5-15%（高质长文）
- **多语言**：按目标语言比例

**前沿做法**：
- **DoReMi** (2023)：用 proxy 小模型自动学权重
- **RegMix** (2024)：回归预测最优配比
- **课程学习**：训练后期切到更高质数据（**annealing data**）

**Llama-3 公开细节**（8B/70B/405B）：
- 15T tokens
- 大幅提高 code、math、多语言比例
- 训练末期 annealing 阶段单独用高质数据

## 五、合成数据（Synthetic Data）

### 5.1 思路

> Microsoft Phi 系列把这个思路推到极致：
> **"Textbooks Are All You Need"**

用 GPT-4 / Claude 等强模型生成"教科书风格"的训练数据，让小模型在质量极高的数据上训练。

**Phi-3-mini (3.8B)** 达到了 Mixtral 8×7B 级别。

### 5.2 应用场景
- **数学**：MetaMathQA、OpenMathInstruct
- **代码**：Magicoder、Evol-Instruct
- **指令**：Self-Instruct、Alpaca、UltraChat
- **推理蒸馏**：R1 → 蒸馏 7B/32B

### 5.3 风险
- **模型崩塌（model collapse）**：纯合成训练会丢失长尾分布
- 多样性下降
- 错误传播

**实践共识**：合成数据是**调味料**，不是主食；与真实数据混合使用。

## 六、数据污染（Contamination）

训练集与评测集（MMLU / GSM8K / HumanEval 等）重合 → 评分虚高。

**检测方法**：
- **n-gram overlap**（13-gram 是常用阈值）
- **min-K% Prob**：模型对成员数据的概率分布更"自信"
- **canary string**：插入唯一字符串，看模型是否记住

**应对**：
- 训练前主动 decontaminate
- 用**新评测**（如 LiveCodeBench、AIME 当年题、Arena 实时人评）

## 关键问答

**Q1**：为什么 FineWeb-Edu (1.3T) 能打过 FineWeb (15T)？
- 模型分类器筛出的"教育性"文档与下游 benchmark 高度相关
- 验证了"数据质量 > 数据数量"的 Chinchilla 后时代结论
- 注意这种过滤对特定 benchmark 有过拟合风险

**Q2**：为什么去重这么重要？
- 重复内容让模型在小部分高频文本上过拟合
- 增加隐私泄露风险（GDPR / 训练数据反推）
- Lee 2021 证明可以等效 2-3× token 效率

**Q3**：合成数据的本质是什么？
- 把强模型的能力"压缩"到训练数据里 → 用数据通道做"软蒸馏"
- 优点：可控、可标注、可针对短板生成
- 风险：多样性、模型崩塌

**Q4**：数据墙（data wall）问题？
- 高质量人类文本接近耗尽（约 100-300T tokens 量级）
- Llama-3 已用 15T，DeepSeek-V3 用 14.8T
- 解法：合成数据、多模态扩展、Test-time scaling

**Q5**：怎么验证数据污染？
- 13-gram overlap 是最常用的近似
- 评测集需要 hold-out + 持续刷新

# 8.2 位置外推（PI / NTK-aware / YaRN / LongRoPE）

[← 返回框架](../../README.md) · [📎 materials.md → §8.2](../../materials.md)

---

## 〇、这一节回答什么

> 模型在 4k 训练，但部署要 128k —— 怎么让 RoPE 在没见过的 position 上仍然正确？

主流四代方法：**Position Interpolation (PI) → NTK-aware → YaRN → LongRoPE / Dynamic NTK**。

---

## 一、回顾：RoPE 是什么

[RoPE (Su et al. 2021)](https://arxiv.org/abs/2104.09864)：把 position 信息**乘到 Q/K 上**而不是加到 embedding。

对位置 $m$、维度对 $(2i, 2i+1)$，旋转角度：
$$\theta_i = b^{-2i/d}, \quad \text{rotation angle at position } m = m \cdot \theta_i$$

其中 $b$ 通常 = 10000（"RoPE base"），$d$ 是 head dim。

```
低维（i 小）：θ 大 → 旋转快 → 编码"高频/局部"
高维（i 大）：θ 小 → 旋转慢 → 编码"低频/全局"
```

→ 注入到 attention 的内积：$\text{score}(m, n) = q_m^\top k_n$，只依赖 **相对位置** $m - n$。

→ RoPE 的优点：相对位置 + 公式简洁；但它**外推不友好**——超过训练 max position 后，attention score 分布显著漂移。

---

## 二、为什么 RoPE 外推不友好：max position 与 OOD 角度

### 2.1 什么是 max position

**max position = 模型在预训练阶段输入序列里出现过的最大位置索引**（记作 $L_{train}$）。它来自三处约束的叠加：

1. **配置层面**：HF config 中的 `max_position_embeddings`（Llama-2 = 4096、Llama-3 = 8192、Qwen2.5 = 32768）。
2. **数据层面**：训练样本被打包 / 截断到的长度——模型实际见过的最长 token 距离就是这个值。
3. **位置编码层面**：对 RoPE 来说，意味着每个维度 $i$ 实际"扫"过的旋转角度范围是 $m \cdot \theta_i,\ m \in [0, L_{train}]$。

> RoPE 不像 learned absolute embedding 那样有一张"位置表"——公式上可以代入任意大的 $m$，但**模型权重只在 $m \le L_{train}$ 这个角度分布上训练过**。所以 max position 不是硬上限，而是**分布意义上的训练上限**。

### 2.2 为什么"传统 RoPE 直接外推"会崩

可以拆成 3 个层面：

**(1) 中-低频维度的角度落到训练分布外（OOD）**

| 维度类型 | $\theta_i$ | 训练时累积角度 $L_{train}\cdot\theta_i$ | 推到 $L_{target}=32 L_{train}$ |
|---|---|---|---|
| 高频（i 小） | 大（≈1） | 已转几百~几千圈 | 转更多圈，但因 $\sin/\cos$ 周期性，**角度落点分布与训练时相同**，本质安全 |
| **中频**（i 中等） | 中等 | 转了 1~几十圈 | **从未在这个角度密度上训练过** → OOD |
| 低频（i 大） | 小 | 连一圈都没转完 | 绝对角度从未出现过 → OOD |

关键洞察：**周期性掩盖了高频的危险，但中-低频维度是真的"没见过"那么大的累积角度**。这就是 NTK / YaRN 要"分频段处理"的根本动因。

**(2) attention score 量级漂移，softmax 失稳**

RoPE 下 $\text{score}(m,n)=q_m^\top k_n$ 近似为一个带衰减的振荡求和：

$$\text{score}(m-n) \approx \sum_i (q_i k_i) \cos((m-n)\theta_i)$$

- 训练时 $|m-n| \le L_{train}$，求和在该范围内的"远近差异"是可区分的。
- 推到 $|m-n| \gg L_{train}$ 时，振荡项相位错乱，求和方差被放大或抵消 → **logit 量级飘** → softmax 忽然过 sharp 或过 flat。
- §5.2 YaRN 的 attention temperature 就是为了把这个 entropy 拉回训练时水平。

**(3) 相对位置的"局部辨识"被打破**

RoPE 的卖点是相对位置编码，但"相对"这件事只在训练见过的 $|m-n|$ 范围内才稳定：

- 高频维度负责区分"相邻 / 隔几个 token"（局部）。
- 低频维度负责区分"开头 / 中间 / 末尾"（全局）。

直接外推时，**低频维度从未旋转过完整周期**——它甚至还没"展开"它能表达的全部信息，模型对这种角度的 q/k 投影完全没训练过。这正是 PI 出现的动机（把 $m$ 缩回训练区间），也是 NTK / YaRN / LongRoPE 进一步精细化的原因——**不同频段的 OOD 风险不同，不能一刀切**。

### 2.3 一句话总结

> 超过 $L_{train}$ 后，中-低频维度的旋转角度落到训练分布外，而 attention score 又是各维度 $\cos((m-n)\theta_i)$ 的求和——**OOD 相位 → logit 量级漂移 → softmax entropy 失衡 → 远距离相对位置不可分**。后面 §3–§7 介绍的所有方法，本质都是"把 OOD 角度拉回 in-distribution"。

## 三、Position Interpolation (PI) — 最朴素

[Chen et al. 2023 — Extending Context Window via Position Interpolation](https://arxiv.org/abs/2306.15595)。

**思路**：把要外推的 position 直接 **线性缩放回训练范围**。

```
原训练 max position L_train = 4096
目标 L_target = 16384
scale factor s = L_target / L_train = 4

位置 m 在 RoPE 中改为 m' = m / s = m / 4
```

→ 所有维度的旋转角度都缩 1/s。
→ 优点：实现简单（一行代码改 freq）
→ 缺点：**所有频率都被压扁**，高频信息（区分相邻 token）严重损失 → 短任务掉点

实测：PI + 少量 finetune（~1B token）能扩到 16-32k，但精度有损。

## 四、NTK-aware Scaling — 频域不均匀拉伸

[NTK-aware Scaling (bloc97, 2023-06, Reddit/blog)](https://www.reddit.com/r/LocalLLaMA/comments/14lz7j5/ntkaware_scaled_rope_allows_llama_models_to_have/)。

**问题**：PI 对所有 dim 用同 scale → 高频被压垮。
**核心洞察**：高频 dim 本来旋转就快（数千圈），不需要拉伸；低频 dim（旋转慢）才需要拉伸。

```
PI:    所有 dim 都 freq → freq / s
NTK:   高频 dim 几乎不动，低频 dim 拉伸更猛
```

数学：把 RoPE base $b$ 改成 $b'$：
$$b' = b \cdot s^{d/(d-2)}$$

→ 在低频维度上等价于 PI，在高频维度上几乎不变。

→ **无需 finetune** 就能扩到 2-4× 训练长度（"training-free"），是早期 Llama 长 context 部署常用方案。

```
Llama-2 4k + NTK base 10000 → 1000000 → 实测能撑到 16k 大致可用（精度有损）
```

## 五、YaRN — Yet another RoPE extensioN

[Peng et al. 2023 — YaRN: Efficient Context Window Extension of LLMs](https://arxiv.org/abs/2309.00071)。

把"频域分段处理"做到极致：

### 5.1 三段策略（按 wavelength 分）

定义维度 $i$ 的波长 $\lambda_i = 2\pi / \theta_i$（旋转一圈所需 position 数）。

```
高频段 (λ_i < L_train):           旋转过多圈，外推安全 → 保持原样（不缩放）
低频段 (λ_i > L_target):          从未旋转完整一圈 → 用 PI 缩放
中间段 (L_train < λ_i < L_target): smooth ramp 在两者间插值
```

→ 同时保留高频"局部辨识"和低频"全局位置"，避免 PI/NTK 的极端。

### 5.2 attention temperature 调整

YaRN 还观察到：扩 context 后 attention 分布会变"陡"（softmax 内积尺度变大）。
→ 给 attention 内积乘一个温度因子 $\sqrt{1 / t}$（$t \approx 0.1 \ln(s) + 1$）。

→ 让 attention 分布在长 context 上保持原有 entropy。

### 5.3 实测

[YaRN 论文](https://arxiv.org/abs/2309.00071) 在 Llama-2 7B 上：
- 4k → 128k，需要 finetune 400 step（约 0.1% 训练 token）
- perplexity、retrieval 均接近 dense fine-tune
- → 成为当前最主流的"短训长用"方案

DeepSeek-V3、Qwen2.5、Mistral 等多家都用 YaRN 风格。

## 六、Dynamic NTK / Adaptive 方案

**动态调整 scale**：推理时根据实际 input 长度动态算 scale。

```
def dynamic_ntk(input_len, L_train):
    s = max(1, input_len / L_train)
    b' = base * s ** (d / (d - 2))
    return b'
```

→ 短输入用原 base，长输入按需扩展。
→ HuggingFace transformers 内置（`rope_scaling={"type": "dynamic", ...}`）

优势：单模型支持任意长度
弱点：分布上仍有微变化，长输入精度低于 finetune 过的 YaRN

---

## 七、LongRoPE — 非均匀 + 渐进

[Ding et al. 2024 — LongRoPE](https://arxiv.org/abs/2402.13753)（Microsoft）。

YaRN/NTK 都是**手工设计**频域分段。LongRoPE：

1. **用进化搜索**，给每个 dim 独立的 rescale factor（不再"三段")
2. **渐进 finetune**：4k → 32k → 128k → 256k → 2M
3. 把每一档作为"中转站"再扩

效果：能稳定扩到 **2M token**，是当前公开非合成方案的上限之一。

代表应用：Phi-3-mini-128k、Phi-3.5。

## 八、其他变体（不深入）

| 方案 | 关键 idea | 应用 |
|------|----------|------|
| **ABF** (Adjusted Base Frequency) | 直接增大 RoPE base 到 1M-10M | Llama-3 系 |
| **CLEX** | 把 RoPE rescale 写成连续函数学习 | 学术 |
| **PoSE** | 训练时 randomly skip position | 训练 trick |
| **Self-Extend** | 推理时用 floor 分组 position（无训练） | training-free 应急 |

工业上 2024-2025 主流仍是 **YaRN + 长 context CT** 组合。

## 九、不只是 RoPE：其他位置编码的扩展

| 位置编码 | 扩展方式 |
|---------|---------|
| RoPE | PI / NTK / YaRN / LongRoPE（本节） |
| ALiBi | 天生支持外推（线性 bias 无 max position） |
| 学习式 absolute | 几乎不可外推（必须重学） |
| T5 relative bias | 可外推但效果一般 |
| **No position encoding（NoPE）** | decoder-only 中 causal mask 隐式编码顺序，长 context 表现意外好 |

→ 选择 RoPE 的代价是"必须设计外推方案"；选择 ALiBi/NoPE 则训练成本可能更高（质量略低）。

→ 当前主流模型几乎都是 RoPE（Llama / DeepSeek / Qwen / Mistral / Gemma），所以外推方案研究最多。

## 十、关键问答

**Q1**：RoPE 为什么不能直接外推？
- 训练时模型只见过 $m \in [0, L_{train}]$ 范围内的旋转角度
- 超出后高频维度旋转角度落到"分布外"
- attention score 在 OOD position 上变得 chaotic

**Q2**：PI / NTK / YaRN 谁能完全无 finetune 工作？
- PI：理论上需要 finetune 才能不掉点
- NTK：training-free 能用，但限于 2-4× 扩展，精度有损
- YaRN：training-free 能用，但官方 paper 推荐 ~400 step finetune
- 工业实操：都会 finetune，差别在 finetune cost

**Q3**：YaRN 的 temperature 调整为什么必要？
- 长 context 中 attention 平均要"分散"更多 token
- 若 softmax 温度不调，logit 范围会变（attention 变 sharp 或 flat）
- temperature ↑ 让分布回到原训练 entropy 水平
- 在数学上是补偿 RoPE 旋转分布的尾部行为

**Q4**：LongRoPE 比 YaRN 强在哪？
- YaRN 用"3 段固定函数"做 dim-wise rescale
- LongRoPE 用搜索得到 dim 级最优 rescale → 更精细
- 渐进 finetune 让超长 context (1M+) 也稳
- 代价：实现复杂、搜索成本高

**Q5**：为什么 Llama-3 直接把 RoPE base 改到 500000（ABF）就 work 了？
- 8B-70B 大模型容量大，承受得起频域稍微偏移
- 配合 long-context CT，分布会被"训正"
- 简单 + 工程友好，是大模型的偏好

**Q6**：训练时位置编码已经搞好了，推理时还要做啥？
- 部署引擎（vLLM / SGLang）要正确实现对应 scale 参数
- 注意 `rope_scaling` 字段（HF config）：type、factor 必须一致
- 用错 scale 会引入显著精度下降，且不容易发现（perplexity 还行但 NIAH 崩）

**Q7**：动态 NTK 和 YaRN 怎么选？
- 单模型多长度部署：dynamic NTK 方便
- 锁定目标长度（如 128k）：YaRN + finetune 质量更优
- 1M+ 极长：LongRoPE 渐进路线

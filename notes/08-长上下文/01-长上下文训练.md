# 8.1 长上下文训练（recipe / data / staged training）

[← 返回框架](../../README.md) · [📎 materials.md → §8.1](../../materials.md)

---

## 〇、本节回答什么

§5-§7 解决了"长 context 怎么算得动"（attention 算量、KV 体积、架构选择）。
本节解决：**模型怎么"学会"在长 context 上工作？**

> "把一个 4k 模型直接拉到 128k 推理"几乎一定掉点。要正确扩展，必须：
> 1. 训练数据分布要含长样本
> 2. 位置编码要外推（见 §8.2）
> 3. 训练超参（lr、batch、context length）要 staged
> 4. 评测要选对（见 §8.3 / §13）

---

## 一、为什么"短训长用"会掉点

```
4k 训练的模型 → 直接拿到 128k 推理：
  ├─ 位置编码：RoPE 在未见过的 position 上失真（频率 OOD）
  ├─ Attention 分布：sink token、attention sink 现象在长序列上失衡
  ├─ KV 数值：layer norm / RMSNorm 累加误差变大
  └─ 模型从未见过"跨万 token 的长依赖"，retrieval / reasoning 都崩
```

→ 经验：超过训练长度 ~2× 就开始明显掉点，超过 4× 通常崩溃。

## 二、主流长 context 训练 recipe

### 2.1 两阶段（最常见）

```
Stage 1: 短 context 预训练
  L = 4k 或 8k，约消耗 90-95% 训练 token
  数据：标准网页/代码/数学 mix

Stage 2: 长 context continued pretraining
  L = 32k → 128k → 1M，逐步扩
  数据：长文档（书、代码仓、长论文、长对话）占比拉高
  Token 量：5-50B（远少于 Stage 1）
  位置编码：同步调整（RoPE base 扩大 / YaRN scaling，见 §8.2）
```

代表：[Llama-3](https://arxiv.org/abs/2407.21783)（8k → 128k）、[Qwen2.5-1M](https://arxiv.org/abs/2501.15383)（32k → 1M）、Yi（4k → 200k）。

### 2.2 多阶段渐进（更稳）

```
4k → 16k → 32k → 64k → 128k → 256k → 1M
```

每一档训若干 step，让 RoPE/attention 分布平滑迁移。
代表：Qwen2.5-1M、DeepSeek-V3（推理时 8k → 128k via YaRN）。

### 2.3 直接 long-context from scratch（少见）

少数模型直接用长 context 从头训（如部分 Mamba / hybrid）。
- 优点：分布一致，不需要切换
- 缺点：吞吐显著降低、训练 token 成本上升
- 工业上一般不选

## 三、长 context 数据从哪来

长 context 训练**最大瓶颈是数据**，不是算力：

| 来源 | 典型长度 | 注意点 |
|------|---------|--------|
| 书（Books3 / Project Gutenberg） | 50k-500k token | 版权问题，质量参差 |
| 代码仓（整 repo） | 10k-1M | 用 file-concat 或 repo-as-doc |
| arxiv 论文（全文 + ref） | 10k-50k | tex / pdf parse 质量重要 |
| 长对话 / 多轮 QA | 8k-64k | 合成数据为主 |
| Web crawl（CommonCrawl 长文档） | 5k-30k | filtering 严格 |
| 合成长 context | 任意 | 用短文档拼接 + needle 任务 |

工业实操：
1. **天然长文档不够** → 用"短文档拼接 + 任务化"补足
2. **拼接策略**：相关文档拼一起（同主题 / 同 repo）比随机拼接好
3. **加合成 needle 任务**：在长 doc 中插入"问题-答案"对，强迫模型学跨万 token retrieval

## 四、关键训练超参

### 4.1 Batch size 折算

长 context 训练时 **per-GPU 能放下的 batch 急剧减少**：

```
4k context, batch=4M token: 每 GPU bsz=128
128k context, batch=4M token: 每 GPU bsz=4    ← 32× 缩小
```

→ 必须用**全局 batch token 数恒定**而不是"sample 数恒定"来 schedule。
→ 通常配合 **gradient accumulation + sequence parallel**（见 §10）。

### 4.2 Learning rate

延续短训练的 lr schedule 即可（continued pretraining 时一般 lr 是 stage1 末端的 5-10%）。
经验：不要在长 context 阶段冷启动 lr，会扰动已学到的能力。

### 4.3 训练长度（token budget）

长 context 阶段消耗的 token 远比想象少：
- Llama-3：long context 阶段约 800B token（占总 15T 的 5%）
- Qwen2.5-1M：long context 阶段约 50B token
- 经验：5-50B token 通常足够"激活"长 context 能力（不需要重训）

### 4.4 上下文长度本身的 schedule

```
linear schedule:      4k → 128k 直线扩
step schedule:        4k 训 N step → 32k 训 N → 128k 训 N
mixed-length batch:   一个 batch 里同时含短样本和长样本，按长度 bucket
```

实测 step schedule 最稳；mixed-length batch 训练吞吐更高（短样本不浪费 padding）。

## 五、Long-context 训练的常见工程问题

### 5.1 内存炸（activation memory）

长 context 主要内存压力来自 **attention activation**（即使有 FA）：
- 4k → 128k：activation 32× 增长，即使常数小
- 解法：
  - **Sequence Parallel**（SP）：把 sequence 维度拆 GPU
  - **Context Parallel**（CP，Ring-Attention）：跨 GPU 流水 KV
  - **Selective activation checkpointing**：attention 层重算
  - 见 [§10 并行化](../10-预训练-并行化-peft/02-并行化.md)

### 5.2 训练 throughput 暴跌

- 4k → 128k 训练吞吐通常掉 5-10×
- 这是为什么"先短后长"：短训练扛 95% token，长训练只用 5%

### 5.3 长样本质量 filter

长样本里"垃圾内容"占比往往更高（自动爬取拼接易混入低质）：
- 用 perplexity-based filter
- 用 doc-level dedup（MinHash）
- 严控 repetition

### 5.4 数据 packing 时的边界

长 doc 内部不要随意切碎（影响 long-range 依赖）：
- 用 **document-aware packing**（同 doc 内 attention，跨 doc mask）
- 见 [FlashAttention varlen](https://github.com/Dao-AILab/flash-attention) 的 cu_seqlens 模式

## 六、Needle in a Haystack（NIAH）评测

长 context 训练后**必须用 NIAH 类评测验证**，不能只看 perplexity：

```
长 doc (e.g., 128k token) 中插入一段事实："The magic number is 42."
模型在 doc 末尾被问："What is the magic number?"
正确答案：42

测试时把 needle 插入到 doc 的不同位置 (0%, 10%, ..., 100%)
绘制热力图：(context 长度) × (needle 位置) → 正确率
```

观察：
- 训练长度内正确率应接近 100%
- 训练长度外通常出现热力图缺角（"middle problem"、"forgotten depth"）
- 见 §13 评测：[RULER](https://arxiv.org/abs/2404.06654)、[NIAH](https://github.com/gkamradt/LLMTest_NeedleInAHaystack) 是事实标准

## 七、与位置编码、KV 节省的关系

长 context 训练**三件事必须一起做**：

```
       数据 / recipe (本节 §8.1)
              ↑
              │
   位置编码外推 ──────── 长 context 训练 ──────── KV 节省
   (§8.2)                                       (§8.3 推理)
```

- 只调数据 不调位置编码：训练长度外仍崩
- 只调位置编码 不补数据：见过 position 但没见过"长 retrieval pattern"，质量低
- 训练 OK 但 KV 推理省不下来：部署仍困难

## 八、关键问答

**Q1**：为什么不直接从头训 128k？
- 训练吞吐降 5-10×，token cost 拉爆
- 长依赖学得慢（warmup 不充分）
- 工业实操：短训扛主力 → 长训"激活"长 context 能力，最经济

**Q2**：为什么长 context continued training 只用 5-50B token 就够？
- 短训阶段模型已经学会"语言模型本质"
- 长训只是教它"在更长 window 里把这件事做下去"
- 不是从零学新能力，是 calibration

**Q3**：合成 needle 任务可以代替真长文档吗？
- 部分能（教会"跨长距离 retrieval"）
- 但不能完整代替（真长文档的语言分布更丰富）
- 工业：真长 + 合成 needle 同时用，比例 3:1 ~ 1:1

**Q4**：训练 8k 部署 128k，模型能用吗？
- 直接：通常崩
- 加 YaRN 等位置编码外推（§8.2）：能 work 但精度下降明显
- 正经做法：训练时就扩到目标长度
- 评测：用 NIAH，不要只看 perplexity

**Q5**：长 context 训练时，attention 还用 dense softmax 吗？
- 通常**先 dense 训，再蒸 sparse**（Kimi K2 路线）
- 或者**全程 sparse / hybrid**（Jamba 路线）
- 见 §6 / §7 架构选型

**Q6**：long context 训练 lr 要不要重新 warmup？
- 不需要重 warmup（这是 continued pretraining 不是 from scratch）
- 一般 lr = stage1 末端 5-10%，cosine decay
- 重 warmup 反而扰动已学能力

**Q7**：怎么判断 long context 训练训够了？
- 训练 loss 在长样本上稳定下降
- NIAH 评测在目标长度上 ≥ 95% 正确率
- RULER（多种 task 类型）评分稳定
- 不能只看 perplexity（PPL 在长 context 上不敏感）

## 九、家族图谱（2024-2025 主要长 context 模型）

| 模型 | 训练 context | 推理 context | 关键技术 |
|------|-------------|-------------|---------|
| Llama-3 | 8k → 128k | 128k | RoPE base ↑ + long CT |
| Llama-3.1 | 8k → 128k | 128k | + 合成 long-doc |
| Qwen2.5-1M | 32k → 256k | 1M | 多阶段 + YaRN-style |
| Yi-34B-200K | 4k → 200k | 200k | RoPE + long CT |
| DeepSeek-V3 | 4k → 32k | 128k | MLA + YaRN |
| Kimi K2 | 长 context from staged | 1M+ | MoBA + MLA |

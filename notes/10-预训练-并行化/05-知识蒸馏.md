## 〇、本节回答什么

> 已经训出 / 拿到一个强 teacher 模型，如何把它的能力压缩到更小的 student（推理友好）？

蒸馏在 LLM 时代的核心场景：
1. **预训练蒸馏**（pretrain-time distill）：DistilBERT、MiniLLM、Gemma-2
2. **数据蒸馏 / 合成数据**：Phi-4、Nemotron 用大模型生成 SFT 数据
3. **对齐蒸馏**：RLHF 后蒸馏（详见 §11）
4. **推理蒸馏**：CoT 蒸馏，把链推理能力压到小模型（DeepSeek-R1-Distill）

本节聚焦 1, 2, 4；3 留到 §11。

本节核心要回答：

1. **Hinton 的 T² 缩放是怎么推出来的？** —— 梯度尺度对齐
2. **forward KL vs reverse KL 几何上差别在哪？** —— mode-seeking vs mean-seeking
3. **GKD 的 on-policy 怎么解决 exposure bias？** —— 伪代码 + 直觉
4. **f-divergence 统一框架**：所有蒸馏 loss 都是它的特例
5. **不同 tokenizer 怎么蒸？** —— ULD 等跨词表方法
6. **R1-Distill 为什么效果这么好？** —— 推理蒸馏的范式革命
7. **模型崩塌的数学根因** —— 反复用合成数据训练为什么会塌

## 一、Hinton 经典蒸馏

[Hinton et al. 2015 — Distilling Knowledge](https://arxiv.org/abs/1503.02531)

### 1.1 公式

teacher 输出 logit $z^T$，student 输出 $z^S$，loss 由两部分组成：

$$
\mathcal{L} = (1-\lambda) \cdot \mathcal{L}_{CE}(y_\text{true}, p^S) + \lambda \cdot T^2 \cdot \text{KL}(p^T_T \,\|\, p^S_T)
$$

其中：

$$
p_T = \mathrm{softmax}(z / T)
$$

- $T$ 是 temperature，**软化分布**让 student 学到更多 dark knowledge（次优类别的相对关系）
- $T \in [2, 8]$ 经验
- $\lambda \in [0.5, 0.9]$

### 1.2 直觉

- 真实 one-hot label 只告诉 student "对的是 A"
- teacher 软化 logits 告诉 student "A=0.7, B=0.2, C=0.1" → **类间相似关系**也学了
- 等价于一种更丰富的监督信号

### 1.3 为什么 KL 项要乘 T²？★

考虑 KL loss 对 student logit $z^S_i$ 的梯度：

$$
\frac{\partial \text{KL}(p^T_T \| p^S_T)}{\partial z^S_i} = \frac{1}{T} (p^S_{T,i} - p^T_{T,i})
$$

注意里面有个 $1/T$ → 大 $T$ 时梯度被压扁。

这意味着 distillation loss 的梯度尺度与 CE loss 的梯度尺度**差了 1/T**。

为了让两个 loss 项的梯度 contribution 相当，distill loss 要乘 $T^2$：

$$
T^2 \cdot \frac{\partial \text{KL}}{\partial z^S} \sim T \cdot \text{(原 CE 梯度尺度)}
$$

这样：
- 调 $T$ 时不需要重新调 $\lambda$（梯度尺度自动平衡）
- 否则改 $T=4 \to T=8$ 等于把 distill loss 权重隐式砍半

→ Hinton 论文里这个 $T^2$ 看似小细节，实际是工程上"调参不打架"的关键。

### 1.4 在 LLM 上的形式

每个 token 位置都有一个 vocab 分布，loss：

$$
\mathcal{L}_\text{KD} = \frac{1}{T_\text{seq}} \sum_t \text{KL}(p^T_t \,\|\, p^S_t)
$$

teacher 给 student 提供 **soft token-level distributions**（远比 hard label 信息丰富）。

### 1.5 信息论视角

teacher 的 $p^T$ 是 student "想要逼近的分布"。最小化 $\text{KL}(p^T \| p^S)$ 等价于：

$$
\arg\min_S \text{KL}(p^T \| p^S) = \arg\max_S \mathbb{E}_{p^T}[\log p^S]
$$

即"按 teacher 的分布采样，最大化 student 的对数似然"。

→ 蒸馏 = 在 teacher 的"软标签分布"上做最大似然估计。

## 二、蒸馏的三种 loss 类型

### 2.1 Logit / Soft-target KL（最经典）

如上 §1.4。要求 student 和 teacher **vocab 相同**（一般强制 student 用 teacher 的 tokenizer）。

### 2.2 Hidden / Feature 蒸馏

[**DistilBERT** (Sanh 2019)](https://arxiv.org/abs/1910.01108) / [**TinyBERT** (Jiao 2020)](https://arxiv.org/abs/1909.10351)：

匹配中间层 hidden states：

$$
\mathcal{L}_\text{hid} = \sum_l \| h^S_l - W_l h^T_{l'} \|^2
$$

需要 student 层数与 teacher 对齐（或学一个 projection）。

适合 student 与 teacher 维度不同的情况（projection $W_l$ 学一个映射）。

### 2.3 Attention 蒸馏

匹配 attention pattern：

$$
\mathcal{L}_\text{attn} = \sum_l \mathrm{KL}(A^T_l \,\|\, A^S_l)
$$

让 student 学 teacher "看哪里"。MobileBERT、TinyBERT 都用了。

实战：**多种 loss 组合**最强（hard label + soft KL + hidden + attention）。

## 三、Forward vs Reverse KL 的几何差异 ★

### 3.1 两种方向的 KL

$$
\text{Forward KL}: \text{KL}(p^T \,\|\, p^S) = \sum_v p^T_v \log \frac{p^T_v}{p^S_v}
$$

$$
\text{Reverse KL}: \text{KL}(p^S \,\|\, p^T) = \sum_v p^S_v \log \frac{p^S_v}{p^T_v}
$$

### 3.2 几何直觉：mean-seeking vs mode-seeking

设 teacher 是双峰分布（如两种合理答案），student 容量有限只能学单峰：

```
Teacher p^T:    ╱╲   ╱╲     (双峰)
                ╲╱   ╲╱

Forward KL:   p^T 不为 0 处, p^S 必须不为 0（否则 log 0）
                   → student 被迫覆盖所有 mode → 学成"平均" → 单峰横跨两峰中间
                ╱─────╲      (mean-seeking, "平均化")

Reverse KL:   p^S 不为 0 处, p^T 必须不为 0（否则 log 0）
                   → student 只敢分布在 teacher 高密度区 → 锁定单峰
                ╱╲              (mode-seeking, "锁定")
                ╲╱
```

### 3.3 LLM 蒸馏的选型

| 场景 | 推荐 | 原因 |
|------|------|------|
| Student 容量充足 (≥ teacher 一半) | Forward KL | 学全部能力 |
| **Student 远小于 teacher** | **Reverse KL** | 锁定高质量 mode，不学"低质量但概率非零"的回答 |
| 生成任务 | Reverse 或混合 | 避免学到"虚假平均化" |
| 分类任务 (短输出) | Forward 即可 | mode 单一 |

### 3.4 [MiniLLM (Gu 2023)](https://arxiv.org/abs/2306.08543)

> 用 **反向 KL** + on-policy 采样训 LLM student。

forward KL 在 LLM 生成上有个具体问题：teacher 概率分布的尾部有大量"低质量但概率非零"的回答，student 强行学这些尾部会拉低质量。

reverse KL 让 student 只覆盖 teacher 的高概率 mode → 实际输出质量更高。

实验：MiniLLM 在 5 类指令任务上比标准 KL 蒸馏 ROUGE 提 3-5 点。

## 四、f-divergence 统一框架

[Wen 2023 — f-divergence for KD](https://arxiv.org/abs/2307.15190)：所有蒸馏 loss 都可以用 f-divergence 统一：

$$
D_f(p \| q) = \sum_v q_v \cdot f\!\left(\frac{p_v}{q_v}\right)
$$

通过选不同的 $f$ 函数得到不同 divergence：

| Divergence | $f(t)$ | 性质 |
|-----------|--------|------|
| **Forward KL** | $t \log t$ | mean-seeking |
| **Reverse KL** | $-\log t$ | mode-seeking |
| **JS divergence** | $\frac{1}{2}[t \log t - (1+t) \log \frac{1+t}{2}]$ | 对称、平衡 |
| **α-divergence** | $\frac{t^\alpha - 1}{\alpha(\alpha-1)}$ | $\alpha$ 调控 mean/mode |
| **TVD (Total Variation)** | $\frac{1}{2} |t - 1|$ | L1，稳定 |
| **Hellinger** | $(\sqrt{t} - 1)^2$ | 对称、平方根 |

**实战发现**：α=0.5 附近（介于 forward KL 和 reverse KL 之间）通常最稳。这是 GKD 默认配置。

## 五、On-Policy / GKD（解决 exposure bias）

### 5.1 Exposure Bias 问题

经典 KD 用 teacher 的训练分布 $p_\text{data}$ 上的 token 算 KL：

```
for (prompt, response) in dataset:
    student forward 到 token i, 算 KL(p^T_i, p^S_i)
```

但推理时 student 是 **自回归生成**：用自己上一步的输出作为下一步输入。

→ 训练分布（teacher / data）和推理分布（student 自己生成）**不一致**。

student 生成时一旦犯错，就会进入训练时没见过的状态，雪崩。

### 5.2 GKD: Generalized KD

[GKD (Agarwal 2023)](https://arxiv.org/abs/2306.13649)：

> 用 student 自己生成的样本（on-policy）求 KL，对抗 exposure bias。

伪代码：

```python
for step in range(num_steps):
    prompt = sample_batch()
    
    # On-policy: 用 STUDENT 自己生成 response
    with no_grad:
        response = student.generate(prompt)
    
    # 在 student 生成的轨迹上算 KL(p^T || p^S)
    p_T = teacher(prompt, response).softmax()
    p_S = student(prompt, response).softmax()
    
    # 混合 forward KL 和 reverse KL（α-divergence）
    loss = α * KL(p_T, p_S) + (1-α) * KL(p_S, p_T)
    
    loss.backward()
    optimizer.step()
```

关键：
- **student 自己生成** → 覆盖 student 实际推理时会遇到的 state
- **teacher 给指导** → 在这些 state 上"如果是我会怎么走"
- 类似 RL 里的 on-policy 思想（DAgger 算法的蒸馏化）

### 5.3 GKD 与 SFT 的关系

朴素 SFT = teacher-forcing（teacher 提供 ground truth response）
SFT 的问题就是 exposure bias

GKD = "on-policy SFT with soft teacher"
- 训练分布 = student 实际生成的分布
- 监督信号 = teacher 在该轨迹上的 token 分布

工业大厂（DeepMind / Google）训 Gemma-2 / Gemini Nano 时用了这套。

### 5.4 实现成本

- on-policy 采样意味着每个训练 step 都要 generate → 速度比 SFT 慢 3-5×
- 通常 batch 中混合 on-policy 和 off-policy 样本（50/50）
- DeepMind 用了 sequence-level KL（整段 KL 而不是 token-level）

## 六、预训练阶段蒸馏

### 6.1 [DistilBERT (2019)](https://arxiv.org/abs/1910.01108)

- teacher = BERT-base (110M)
- student = 6 层 BERT (66M)
- 蒸馏 + MLM + cos-similarity 三 loss 联合
- 速度 ↑ 60%，质量保留 97%

经典案例，奠定 "encoder 模型预训练蒸馏" 范式。

### 6.2 [MiniLM (Wang 2020)](https://arxiv.org/abs/2002.10957)

只蒸 last layer 的 self-attention dot product，简化但等效。被广泛用做 sentence-encoder。

### 6.3 [Gemma-2 (Google 2024)](https://arxiv.org/abs/2408.00118) — 业界最规模化的蒸馏案例

> 用 27B teacher 训 9B / 2B 的 student，**蒸馏 token-level distribution 而不是 hard label**。

技术细节：
- teacher 输出全 vocab (256K) 的 softmax 分布
- student 学这个分布（forward KL）
- 同 batch 同时算 hard CE loss + soft KD loss
- KD 系数 $\lambda \approx 0.8$

结果：
- Gemma-2 9B 同等数据下 PPL 优于 from-scratch baseline
- 训练算力被"老师"省下不少（蒸馏比 from-scratch 收敛快 2-3×）
- 关键：teacher 的 soft distribution 提供了"密集 / 多 bit 的信息"

→ "**用大模型当 pretrain 监督信号**"成为 2024 工业的隐含范式。

### 6.4 LLM 时代蒸馏的范式变化

decoder-only LLM 蒸馏关键差异：
- **生成式 → 必须考虑 teacher-student 训练分布偏移**
- 单纯学 teacher 静态输出会有 **exposure bias**
- on-policy / reverse KL 解决方案见 §5

## 七、数据蒸馏（Synthetic Data Distillation）

### 7.1 思路

> 直接 sample teacher 输出当数据，存储下来训 student。简单粗暴但极其有效。

```
GPT-4 / Claude / DeepSeek-V3 ──产生大量 (prompt, response) 对──→ 训 student SFT
```

经典：
- [Alpaca (2023)](https://github.com/tatsu-lab/stanford_alpaca)：用 text-davinci-003 生成 52k 指令 → 训 LLaMA-7B
- WizardLM、Vicuna、Orca、Phi-1/2/3/4 系列
- [Nemotron-4 340B (NVIDIA 2024)](https://arxiv.org/abs/2406.11704)：专门设计成"生成合成数据用"的 teacher

### 7.2 黑盒 vs 白盒蒸馏

| 类型 | 是否需要 teacher logits | 数据形式 | 代表 |
|------|--------------------|---------|------|
| **白盒蒸馏** | ✅ 全 vocab softmax | (prompt, token-level p^T) | Gemma-2, MiniLLM |
| **黑盒蒸馏** | ❌ 只有 teacher response 文本 | (prompt, response) | Alpaca, Phi 系列 |

黑盒蒸馏 = 退化的"数据蒸馏" = 把 teacher 当 API 调用。
- 优点：可以用任何闭源 teacher（GPT-4、Claude）
- 缺点：丢失 dark knowledge（只有 hard label 不知道次优类别的概率）

### 7.3 Phi 系列：合成数据的极端版本

[Phi-3 / Phi-4 (Microsoft 2024)](https://arxiv.org/abs/2412.08905)：

- "textbook-quality" 合成数据占 50%+
- 14B 模型在 reasoning 上对标 70B
- 但 **窄分布风险**：超出"textbook"模式的任务表现弱
- Phi-4 还特意做 "data calibration" 避免过度依赖合成

### 7.4 合成数据的两个坑

#### 7.4.1 模型崩塌 (Model Collapse)

[Shumailov 2024 (Nature)](https://www.nature.com/articles/s41586-024-07566-y)：

> 全用合成数据训会逐代质量下降。

数学根因：

假设原始数据真实分布 $P$，第 $n$ 代模型估计为 $\hat{P}_n$。每一代用上一代生成数据训练。

```
P → 训 → model_1 → 生成数据 → 训 → model_2 → ... → model_n
```

两类误差不断累积：
- **采样误差**：有限样本导致 $\hat{P}_n$ 偏离 $P$
- **近似误差**：模型容量有限，无法完美拟合
- **学习误差**：optimizer 找不到全局最优

每一代误差 compound → 经过 5-10 代，模型分布的"尾部"完全消失，最终只输出极少数 mode → **崩塌**。

#### 7.4.2 能力上限被 teacher 卡住

student 永远不会超越 teacher，除非引入新信号（self-play、RLHF、真实数据）。

工业混合策略：**真实数据 + 合成数据 7:3 ~ 5:5**。

## 八、推理蒸馏（CoT Distillation）

### 8.1 思路

> 把大模型的 Chain-of-Thought 推理链当训练目标，让小模型学会"显式思考"。

[Distilling Step-by-Step (Hsieh 2023)](https://arxiv.org/abs/2305.02301)、[Orca (2023)](https://arxiv.org/abs/2306.02707)：

```
prompt:     "What is 23 × 47?"
teacher:    "First compute 20×47=940, then 3×47=141, sum=1081"  ← 学这个！
student:    train to generate same CoT + answer
```

vs 没有 CoT 的蒸馏：

```
prompt:     "What is 23 × 47?"
teacher:    "1081"   ← 只有答案
student:    学到"短答模式"，遇到难题就不会推理
```

### 8.2 [DeepSeek-R1 蒸馏 (2024)](https://arxiv.org/abs/2501.12948) — 现象级案例 ★

> R1（reasoning 模型）蒸馏 → R1-Distill-Qwen-7B / 14B / 32B 等开源小模型
> 7B 模型 GSM8K / MATH 分数对标早期 GPT-4

做法：
1. R1 生成 800k 推理轨迹（带 `<think>` 内部独白）
2. 蒸到 Qwen2.5 base 上做 SFT
3. **仅 SFT，没用 RL** → 仍能学到推理能力

这是 **2025 推理小模型** 的事实标准 pipeline。

### 8.3 R1-Distill 为什么效果这么好

三个关键因素：

#### (a) Teacher 输出本身已是高质量推理链

R1 通过 RL 训成 reasoning model，输出格式：

```
<think>
首先，我需要分析问题...
让我先试 X = ...
不对，X 应该是...
所以最终 X = ...
</think>

答案：X
```

这种 trace 本身就携带"思考过程"。student SFT 这种数据 = 学到 "**思考链格式 + 正确推理**"。

#### (b) Reasoning 能力是"格式可习得"的

R1 的发现：reasoning 能力很大程度是 **学到了 "thinking format"** —— 学会生成 `<think>` 内的多步推理 + 自我修正模式。

→ 这种格式 / 模式比"知识"更容易蒸馏（不需要 RL 信号也能 SFT 学到）。

#### (c) 小模型容量足够承载推理格式

7B / 14B base 已经"理解" reasoning step 的语义，缺的是"什么时候触发 thinking"和"思考的具体步骤"。SFT 解决了这两点。

### 8.4 推理蒸馏 vs RL

- **蒸馏 R1 → 7B**：SFT 即可，~3 天训完
- **RL train 7B → reasoning 模型**：~30 天，效果可能不如蒸馏
- 工业现状：所有 14B 以下推理模型几乎全是 R1 / o1 蒸馏

→ 2025 推理小模型范式：**RL 在 teacher 端做一次，所有 student 共享蒸馏。**

## 九、跨 tokenizer 蒸馏（白盒难，但需要）

### 9.1 问题

不同模型用不同 tokenizer，token 一一不对应：
- Llama: "ChatGPT" → ["Chat", "G", "PT"]
- GPT-4: "ChatGPT" → ["ChatGPT"]

soft KL 需要相同 vocab，跨 tokenizer 不能直接用。

### 9.2 解决方案

#### 9.2.1 [ULD (Universal Logit Distillation, Boizard 2024)](https://arxiv.org/abs/2402.12030)

- 在每个文本位置上对齐：teacher 的 token-level prob 通过 **vocab projection** 映射到 student 词表
- 用 optimal transport 解 vocab 之间的最优匹配
- 训练时只用对齐区域的 KL

#### 9.2.2 Token Re-mapping

简单粗暴：把 teacher 的 token sequence 用 student tokenizer 重新分词。
- 优点：实现简单
- 缺点：损失 token-level prob 对齐精度

#### 9.2.3 退化为黑盒蒸馏（数据蒸馏）

最实用：直接 sample teacher 输出当数据，student SFT。
- 优点：无 tokenizer 约束
- 缺点：丢失 dark knowledge

→ 工业上大多数跨 tokenizer 蒸馏都是 §9.2.3（数据蒸馏）。

## 十、蒸馏 vs 量化 vs 剪枝（小模型三剑客）

| 方法 | 改变什么 | 质量损失 | 加速 | 用例 |
|------|---------|---------|------|------|
| 蒸馏 | 重训 student | 中（5-15%） | 大（参数减半） | 部署小模型 |
| 量化 | weight 比特 | 小（< 5%） | 大（FP16→INT4 4×） | 推理端 |
| 剪枝 | 删 weight | 中（10-20%） | 中（结构化才有效） | 不主流 |

工业典型组合：**先蒸馏 + 再量化**（如 7B → INT4 部署，推理体验 ≈ 全精度 1/10）。

## 十一、自适应蒸馏调度

### 11.1 温度调度

固定 $T$ 不一定最优。一些工作探索：

- **逐 layer 温度**：高层（接近输出）用低 $T$，低层用高 $T$
- **训练动态温度**：开始 $T$ 大（学全部 mode），后期 $T$ 小（锁定高质量）

实证收益 ~ +1% PPL，工业未普及。

### 11.2 自适应 λ（KD 权重）

- 训练初期：$\lambda$ 大（多学 teacher）
- 训练后期：$\lambda$ 小（多学 hard label，避免 teacher 偏差）

实现简单（线性 / cosine schedule），DistilBERT 和 Gemma-2 都用了。

## 十二、关键问答

**Q1**：蒸馏一定比 from-scratch 好吗？
- 相同 token 数：蒸馏收敛快 2-3×，质量略好
- 同质量目标：蒸馏所需 token 少 ~30-50%
- 但 student 的"质量天花板"被 teacher 决定

**Q2**：蒸馏只能用相同 tokenizer 吗？
- soft KL → 必须相同 vocab
- 不同 vocab 时：
  - 用 hidden 蒸馏（projection layer）
  - 或 ULD 跨 vocab 匹配
  - 或 token re-mapping（损失精度）
  - 或直接退化为"数据蒸馏"（最实用）

**Q3**：reverse KL vs forward KL，怎么选？
- forward KL：student 大、容量足 → 学全部 modes（mean-seeking）
- reverse KL：student 小（容量受限）→ 锁定高质量 mode（mode-seeking）
- LLM 蒸馏一般用 **reverse 或混合 KL**

**Q4**：蒸馏能不能让 student 超越 teacher？
- 单纯蒸馏：不能。student 是 teacher 的函数
- 加上 RLHF / RLAIF / self-play / 真实数据后：可能（如 R1-Distill 在某些任务比原 7B SFT 强）
- 整体仍是 teacher upper-bounded

**Q5**：数据蒸馏的版权风险？
- OpenAI / Anthropic ToS 禁止用其 API 输出训竞品
- 工业 "白手套"做法：用 open-weight 模型（DeepSeek-V3、Llama-3、Qwen）生成
- 学术界默认接受 GPT-4 蒸馏（已成事实标准）

**Q6**：Phi-4 / Gemma-2 这种"合成 + 蒸馏"路线会成主流吗？
- 小模型（< 14B）：**已是主流**
- 中模型（30-70B）：混合数据 + 蒸馏 / RL
- 大模型（70B+）：必须真实数据 + 蒸馏只作为辅助监督

**Q7**：R1-Distill 为何效果这么好？
- 关键：teacher 是"reasoning 模型"，输出本身已是高质量推理链
- student SFT 这种数据 → 直接学会"思考链格式 + 正确推理"
- 验证了 "**reasoning 是可以蒸馏的**"（这是 2024-2025 最有意义的发现之一）

**Q8**：Hinton 的 T² 缩放可以省掉吗？
- 理论上调 $\lambda$ 可以补偿
- 实际工程上保留 $T^2$ 让"调 T 不影响 λ"，调参更友好
- 工业默认保留

**Q9**：GKD 的 on-policy 采样开销大吗？
- 每 step 需要 student.generate → 慢 3-5×
- 工程上常 50% on-policy + 50% off-policy 混合，平衡速度
- 收益：student 实际推理时 robust 度大幅提升

**Q10**：模型崩塌一定会发生吗？怎么避免？
- 全用合成数据训会必然崩
- 混合真实数据可避免（真实数据占比 ≥ 50% 即可）
- 工业做法：每一代合成数据都"diversity check"（去重、覆盖度评估）
- 注意：现实中互联网内容越来越多 AI 生成的，未来 web crawl 数据本身就是"被污染"的

**Q11**：f-divergence 框架中 α=0.5 为什么最稳？
- α=1 是 forward KL，α=0 是 reverse KL
- α=0.5 在两者之间，既不过度 mean-seeking 也不过度 mode-seeking
- 工程上对超参不敏感，调参容错率高

**Q12**：白盒 vs 黑盒蒸馏质量差多少？
- 白盒（有 teacher logits）：理论上限更高，~3-5% 优势
- 黑盒（只有 teacher text）：实际差距 1-3%
- 黑盒优势：可以用任何 teacher（包括闭源 GPT-4 / Claude）
- 工业主流：开源 teacher 用白盒，闭源用黑盒

# 10.3 显存四块（参数 / 梯度 / 优化器 / 激活）

[← 返回框架](../../README.md) · [📎 materials.md → §10.3](../../materials.md)

> 本节是预训练**显存预算**的基础语言。理解 16N 之后,再去看 §10.4 怎么把它在 5D 并行下切到每张卡。

---

## 一、显存被谁吃了

LLM 训练显存可拆为四大块:

```
┌──────────────────────────────────────────────────┐
│ 参数 (Weights)         ~ 2N  bytes (BF16)        │
├──────────────────────────────────────────────────┤
│ 梯度 (Gradients)       ~ 2N  bytes (BF16)        │
├──────────────────────────────────────────────────┤
│ 优化器状态 (Optimizer) ~ 12N bytes (Adam, FP32)  │
│   m: 4N (FP32)                                   │
│   v: 4N (FP32)                                   │
│   master weight: 4N (FP32, 混合精度)             │
├──────────────────────────────────────────────────┤
│ 激活 (Activations)     ~ O(B L d × layers)       │
│   随 batch / seq / 模型层数线性增                │
└──────────────────────────────────────────────────┘
```

**经典口径**:混合精度(BF16 计算 + FP32 主权重) Adam 训练的"模型态"占用 = $(2 + 2 + 12)N = 16N$ 字节。

| N | 模型态显存 |
|---|------------|
| 7B | 112 GB |
| 13B | 208 GB |
| 70B | **1.12 TB** ⚠️ |
| 405B | 6.48 TB |
| 671B (DeepSeek-V3) | 10.7 TB |

→ 大模型训练显存中模型态本身就远超单卡,必须分布式(§10.4)。

## 二、每块详解

### 2.1 参数 (Weights)
$$\text{size} = N \times \text{bytes}_{compute}$$
- BF16: 2N
- FP8 计算: 1N(但仍保留 BF16 主权重做累加)

### 2.2 梯度 (Gradients)
$$\text{size} = N \times \text{bytes}_{grad}$$
- 与参数同精度,BF16: 2N
- 反向时实时生成,需要在 optimizer.step() 前保留

### 2.3 优化器状态 (Optimizer States)

**Adam / AdamW**:每参数需要 2 个动量(m, v)+ FP32 主权重:

| 项 | 精度 | 大小 |
|---|------|------|
| m (一阶动量) | FP32 | 4N |
| v (二阶动量) | FP32 | 4N |
| master weight | FP32 | 4N |
| **小计** | | **12N** ⚠️ |

> Optimizer state 是显存第一大头。

替代方案:
- **SGD-momentum**:4N(仅 m)
- **8-bit Adam**(bitsandbytes):~3N
- **Lion**:4N(仅 m)
- **CAME / Adafactor**:~2N

### 2.4 激活 (Activations)

forward 时为 backward 保留的中间结果。

单层激活粗估(无 recompute):
$$\text{Activation per layer} \approx s \cdot B \cdot L \cdot d \cdot \text{bytes}$$

其中 $s$ ≈ 10-30(取决于 attention/FFN/Norm 缓存了多少)。

经典近似([Korthikanti et al. 2022](https://arxiv.org/abs/2205.05198)):
$$\text{Total activation} \approx 34 \cdot B L d \cdot \text{layers} \cdot \text{bytes}$$

→ Llama-3 70B(layers=80, d=8192, BF16)训练 B=1, L=8k:
$$34 \times 1 \times 8192 \times 8192 \times 80 \times 2 \approx 365 \text{ GB}$$

**激活才是真正的"会爆炸"那块**:与 B、L 都成正比,而模型态不会。

## 三、激活的优化武器

| 技术 | 显存节省 | 算力代价 |
|------|---------|---------|
| **Gradient checkpointing** | 大段 recompute → ~√N | forward 2× |
| **Sequence Parallel** | 在 SP 维度切 LN/Dropout | 通信 ↑ |
| **Tensor Parallel** | 切到多卡 | 通信 ↑ |
| **Activation offload (CPU/NVMe)** | 几乎全省 | I/O 慢 |
| **FlashAttention** | 不存 $L^2$ attention 矩阵 | 几乎无 |
| **Selective recomputation** | 只对 attn 重算 | 平衡型 |

> 千亿模型训练几乎必开 gradient checkpointing + FlashAttention + TP/SP。

## 四、模型态切分:ZeRO / FSDP

把"全部冗余存在每卡"的 DP 模式按 optimizer state / gradient / parameter 三个层级切片,每卡显存可以降到 16N / N_DP。

> **完整 ZeRO-1/2/3 的分片公式、通信原语(AllGather/ReduceScatter)、与 TP/PP 的组合,见 §10.4 并行化**。本节只需记住:**16N 是单卡上限,ZeRO-3 + 32 卡 ⇒ 70B 模型态 1.1 TB → ~35 GB/卡**。

---

## 五、训练 vs 推理对比

推理只需 **参数 + KV-cache + 少量激活**(无梯度、无优化器):

```
inference VRAM ≈ N × bytes_compute  +  KV-cache  +  small activations
```

| 模型 | 训练模型态 (16N, BF16) | 推理参数 (BF16) | KV-cache (L=8k, GQA, B=8) |
|------|-------------|-------------|---------------------------|
| Llama-3 8B | 128 GB | 16 GB | 1 GB |
| Llama-3 70B | 1.12 TB | 140 GB | 10 GB |
| DeepSeek-V3 671B (FP8, MoE) | ~6 TB (FP8) | ~700 GB (FP8) | 极小 (MLA) |

→ **训练瓶颈在 16N 模型态;推理瓶颈在参数 + 长上下文 KV-cache**(后者详见 §4.1、§8.3)。这一不对称是为什么训练并行(TP/PP/ZeRO)和推理并行(TP only / EP)选型完全不同。

## 六、显存计算"checklist"

训练规划时按这个 checklist 估算单卡:

```
单卡显存预算 ≈ 模型态/TP/PP/DP   ← 通过并行切
            + 激活/SP/recompute  ← 通过 SP+checkpoint 切
            + workspace(cuDNN, NCCL buffer)
            + framework 自身(~2-3 GB PyTorch/CUDA context)
            + 安全余量(10-20%)
```

实战中"显存不够"几乎只有三种情况:
1. **模型态超了**:上 ZeRO-3 / TP / PP
2. **激活超了**:上 gradient checkpointing / SP / 减 batch / 减 seq
3. **碎片化**:用 `torch.cuda.empty_cache()`、PYTORCH_CUDA_ALLOC_CONF 控制

## 关键问答

**Q1**:为什么 Adam 是 12N?SGD 只有 4N?
- Adam: m + v + master weight = 4+4+4 = 12N
- SGD-m: m + master = 4+4 = 8N(如果用 master)
- SGD 不带 master:4N(m)
- Adam 内存大但收敛快,是 LLM 训练标配

**Q2**:为什么混合精度训练还要 FP32 master weight?
- 累加大量 BF16 小更新会 underflow(BF16 精度只 7 bit mantissa)
- master weight FP32 累积,每 step 把 FP32 copy 转 BF16 用
- 这是 Pascal 时代 Mixed Precision 论文(Micikevicius 2017)确立的标准

**Q3**:激活和 KV-cache 是同一个东西吗?
- 概念上是不同的:
  - 训练激活:所有层的中间结果(attn 输出、FFN 输入、Norm 输入...)
  - 推理 KV-cache:只 cache K、V,且**复用**
- 推理时其它"激活"用完即丢

**Q4**:FlashAttention 怎么省显存?
- 标准 attention:softmax 矩阵 $L^2$ 必须存 → $O(L^2)$ 激活
- FA:分块算 softmax,online normalize,永不实例化全矩阵 → $O(L)$
- 长序列下省显存极显著

**Q5**:为什么训练 70B 一定要多卡?
- 模型态 1.12 TB > 80GB 单卡 → 一定要切
- 切法:TP / PP / FSDP(ZeRO-3)
- 单卡 80GB 极限:完全 offload 的 ~13B 训练

**Q6**:DeepSeek-V3 FP8 训练显存为什么省?
- 参数 FP8: N(而非 2N)
- 梯度可 FP8 计算后再聚合
- master weight 仍 FP32(4N)
- 总计 ~9-10N vs 16N,省 ~40%
- 但要小心数值稳定性(loss scaling, FP8 quant)

## 〇、本文回答什么

> **LM 的前向只给出一个概率分布 $p(\cdot \mid x_{<t})$，它本身不"生成"任何东西。** "生成"是一个额外的**决策规则**：从这个分布里挑一个 token。挑法（decoding / sampling strategy）决定了输出的确定性、多样性和质量。

一句话分类：

```
解码策略
├── 确定性（deterministic）：每次输出一样
│   ├── Greedy（贪心，argmax）
│   └── Beam Search（束搜索，近似最大似然序列）
└── 随机性（stochastic sampling）：每次可能不同
    ├── 温度 temperature（调分布尖锐度，是"前置旋钮"）
    └── 截断类（在采样前先裁掉长尾）
        ├── Top-k（固定个数）
        ├── Top-p / Nucleus（固定累积概率质量）
        ├── Min-p（相对最高概率的阈值）
        └── Typical / η-sampling（按熵/信息量裁）
    + 惩罚类（repetition / frequency / presence penalty）
```

关键认知：**这些操作绝大多数在 logits 上做，最后才 softmax**（数值稳定，见 [§补充 3](./03-logits-与归一化函数.md) §5）。它们不是互斥的，实际管线是**串联**的：

```
logits ──温度──→ ──repetition penalty──→ ──top-k 截断──→ ──top-p 截断──→ ──min-p 截断──→ softmax ──→ multinomial 抽样
```

---

## 一、确定性解码

### 1.1 Greedy（贪心）

每一步取当前分布 argmax：

$$x_t = \arg\max_i \; p(i \mid x_{<t})$$

- 等价于**温度 $T \to 0$**。
- 优点：可复现、快、无随机性。
- 缺点：**局部最优 ≠ 全局最优序列**。每步只看当下最大，会错过"这一步稍次、但整句更优"的路径；容易陷入**重复退化**（"the the the…"、复读机）。
- 用途：需要确定性的场景——大多数 benchmark 的 pass@1、结构化抽取、需要可复现的 pipeline。

### 1.2 Beam Search（束搜索）

维护 $B$ 条（beam width）候选序列，每步对每条展开所有词表、按**累计对数概率**排序保留 top-$B$：

$$\text{score}(y_{1:t}) = \sum_{\tau=1}^{t} \log p(y_\tau \mid y_{<\tau})$$

- 目标是近似 $\arg\max_y p(y \mid x)$，即**最大似然整句**，比 greedy 更接近全局最优。
- 长度惩罚（length penalty / normalization）：不除长度会偏爱短句（对数概率是负的、越长越小）。
- **为什么现代开放式生成基本不用 beam**：最大似然序列在开放生成里往往**乏味、重复、"安全但无聊"**（likelihood trap）。beam 在**低熵、有唯一正解**的任务（机器翻译、语音识别、约束解码）仍是主力；在**聊天/写作/推理**里几乎被采样类取代。
- 成本：一次前向要跑 $B$ 条，KV-Cache 也要存 $B$ 份，开销约 $B\times$。

> 记忆点：**Greedy 是 beam width = 1 的 beam search。**

## 二、温度 temperature —— 采样的"总旋钮"

$$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

温度 $T$ 直接除在 logits 上，改变分布**尖锐度**（entropy），但**不改变排序**：

| $T$ | 效果 | 直觉 |
|---|---|---|
| $\to 0$ | 分布塌缩到 argmax | = greedy，最确定、最保守 |
| $< 1$（如 0.7） | 分布更尖 | 更保守、更"抓大概率"，常用于代码/事实 |
| $= 1$ | 原始分布 | 模型"本来"的置信度 |
| $> 1$（如 1.3） | 分布更平 | 更发散、更有创意，也更容易胡说 |
| $\to \infty$ | 趋近均匀分布 | 纯随机 |

要点：

- 温度是**乘性缩放**，在 logits 上是线性操作，干净；在 probs 上没有等价简单形式（见 [§补充 3](./03-logits-与归一化函数.md) §5.2）。
- **温度决定"敢不敢选长尾"，截断决定"允不允许长尾进入候选"**。两者正交，常配合用（先温度、再截断）。
- 工程细节：`T=0` 在实现里通常被特判为 greedy（否则除零）。

## 三、截断类采样（在抽样前裁掉长尾）

softmax 后词表里总有几万个概率很小但非零的 token；纯 multinomial 会以极小概率抽到"垃圾 token"，一旦抽中就可能带偏整句。截断类方法**先把长尾裁掉**再抽样。

### 3.1 Top-k

只保留概率最高的 **$k$ 个** token，其余 logits 设 $-\infty$（softmax 后为 0），在剩下的 $k$ 个里重新归一化后抽样。

- 优点：简单、稳。
- 缺点：**$k$ 固定，不自适应分布形状**。
  - 分布很尖（模型很确定）时，$k=50$ 会强行纳入 49 个几乎不可能的 token → 引入噪声；
  - 分布很平（模型很不确定）时，$k=50$ 又可能砍掉本该保留的合理选项。

### 3.2 Top-p（Nucleus Sampling，Holtzman et al. 2019）

按概率从大到小累加，取**累计概率刚好 ≥ $p$** 的最小 token 集合（"核 nucleus"），在核内归一化抽样。

- 关键优点：**候选集大小随模型置信度自适应**。
  - 模型确定时核很小（可能只有 1-2 个）；
  - 模型不确定时核自动变大。
- 典型值 $p = 0.9 \sim 0.95$。是目前**最常用**的默认采样。
- 缺点：**对温度敏感**——高温把分布压平后，核会迅速膨胀，容易把垃圾 token 纳进核（见 §3.3 动机）。

> Top-k 是"固定**个数**"，Top-p 是"固定**质量**"。

### 3.3 Min-p（Nguyen et al. 2024）

设一个**相对阈值**：保留满足 $p_i \ge p_{\min} \cdot p_{\max}$ 的 token，其中 $p_{\max}$ 是当前最高概率、$p_{\min}$ 是超参（如 0.05~0.1）。

- 动机：直接盯住"相对于最可能 token，这个候选有多可信"，而不是绝对累积质量。
- **对温度更鲁棒**：即使高温把分布压平，阈值随 $p_{\max}$ 一起下移，候选集不会像 top-p 那样爆炸。因此 min-p 支持**高温 + 保质量**的组合（既发散又不胡说）。
- 2024 年后在开源社区（尤其创意写作、reasoning）流行度上升，常与较高温度搭配。

### 3.4 Typical / η-sampling（局部典型采样）

不按概率大小裁，而是按**信息量偏离**裁：保留那些 $-\log p_i$ **接近该步分布熵 $H$** 的 token（"典型"的 token），砍掉过于确定（无聊）和过于意外（离谱）的两端。

- 出发点：人类语言的每个词大致携带"接近平均"的信息量（typicality / 均匀信息密度假说）。
- 更小众，某些开放式生成上更连贯，但收益不稳定、超参难调，工业默认里少见。

### 3.5 一张对比表

| 方法 | 裁剪依据 | 候选集自适应？ | 对温度鲁棒 | 常用默认 |
|---|---|---|---|---|
| Top-k | 固定前 $k$ 个 | 否 | 一般 | $k=40\sim50$ |
| Top-p | 累积质量 $\ge p$ | **是**（按置信度） | 差（高温膨胀） | $p=0.9\sim0.95$ |
| Min-p | 相对最高概率阈值 | 是 | **好** | $p_{\min}=0.05\sim0.1$ |
| Typical | 偏离熵的程度 | 是 | 中 | 小众 |

## 四、惩罚类（抑制重复）

在采样前对 logits 做**硬调整**，压制已出现的 token，缓解复读：

| 名称 | 机制 | 说明 |
|---|---|---|
| **Repetition penalty**（Keskar 2019） | 已出现 token 的 logit **除以** $\rho>1$（正 logit 变小、负 logit 更负） | 乘性惩罚，最常用 |
| **Frequency penalty**（OpenAI） | 按出现**次数**线性减 logit | 出现越多罚越狠 |
| **Presence penalty**（OpenAI） | 只要出现过就减一个固定量 | 鼓励引入新话题 |
| **No-repeat n-gram** | 禁止重复出现过的 n-gram（logit 设 $-\infty$） | 硬约束，翻译/摘要常用 |

这些都依赖 logits 在 $\mathbb{R}$ 上的自由度（见 [§补充 3](./03-logits-与归一化函数.md) §5.4）。惩罚过重会伤流畅度和事实性，需权衡。

## 五、约束解码 / 结构化输出（附）

当需要**合法 JSON / 正则 / 语法**时，在每步用一个状态机/语法（grammar）算出"当前合法的 token 集合"，把非法 token 的 logit 设 $-\infty$ 再采样。

- 工具：Outlines、llguidance、XGrammar、vLLM 的 guided decoding。
- 本质仍是"在 logits 上加 mask"，只是 mask 来自语法约束而非概率大小。
- 与上面所有采样策略**正交**，可叠加。

## 六、怎么选：任务 → 策略

| 任务 | 推荐 | 理由 |
|---|---|---|
| 代码 / 事实问答 / 抽取 | greedy 或低温（$T\le0.3$）+ top-p 0.9 | 要准、要可复现 |
| 聊天 / 通用 | $T\approx0.7$ + top-p 0.9~0.95 | 质量与多样性平衡 |
| 创意写作 | 高温（$T\ge1.0$）+ min-p 0.05~0.1 | 要发散又不崩 |
| 机器翻译 / ASR / 约束生成 | beam search（+ length penalty） | 有唯一正解、低熵 |
| Self-Consistency / Best-of-N（§12.6） | 中高温采样，**必须 $T>0$** | 要采出**多条不同**路径才能投票 |
| RLHF / GRPO rollout（§11） | 带温度采样 | 温度 = 探索；$T=0$ 无梯度信号多样性 |
| Benchmark pass@1（§13） | 通常 greedy | 可复现、公平对比 |

## 七、关键问答

**Q1：temperature 和 top-p 有什么区别？能同时用吗？**
A：温度改**整个分布的尖锐度**（所有 token 概率一起重算），top-p 只在采样前**裁掉长尾候选集**。两者正交，工程默认**同时用**：先温度再 top-p。记忆：温度调"敢选多冷门"，top-p 调"允许多少候选进场"。

**Q2：为什么开放式生成不用 beam search？**
A：beam 找的是**最大似然序列**，而高似然文本在开放生成里往往重复、乏味（likelihood trap）。beam 只在低熵、有唯一正解的任务（翻译/ASR/约束解码）有优势。

**Q3：min-p 比 top-p 好在哪？**
A：top-p 的核大小对温度敏感——高温把分布压平后核迅速膨胀、纳入垃圾 token。min-p 用"相对最高概率的阈值"，阈值随最高概率一起浮动，高温下候选集不爆炸，所以能"高温发散 + 仍保质量"。

**Q4：greedy 一定比采样质量高吗？**
A：不一定。greedy 每步局部最优，容易重复退化；且**很多任务（尤其 reasoning）需要多样性**——Self-Consistency 正是靠采样出多条路径再投票，单条 greedy 反而弱。但要**可复现/公平对比**时 greedy 更合适。

**Q5：采样为什么在 logits 上而不是 probs 上做？**
A：数值稳定 + 操作干净。温度是 logits 上的线性缩放；截断/惩罚/mask 是"把 logit 设 $-\infty$ 或加偏移"，softmax 后自动归一化，不破坏其他项相对关系。probs 上做这些会破坏"和为 1"。详见 [§补充 3](./03-logits-与归一化函数.md) §5。

**Q6：推测解码（§12.3）对采样有什么要求？**
A：要保证与 target 模型**分布等价**。所以 speculative decoding 用**修正采样**（对 draft 提议按 $p_\text{target}/p_\text{draft}$ 接受/拒绝），使最终样本分布严格等于 target 在同温度/同截断设置下的分布。因此评测/上线时 draft 与 target 的采样参数必须对齐。
